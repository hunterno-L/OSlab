# OSLab 学习闭环演示脚本（3～5 分钟）

对应《OSLab第三阶段执行计划-学习流程与UI重构.md》§13.2 演示主线。全程使用真实数据与真实状态变化：掌握度颜色、教师看板指标、时间轴事件均来自现场产生的学习证据，无硬编码演示数字。

## 0. 演示前准备（约 3 分钟，一次性）

1. 启动基础服务（Windows 服务，一般已常驻）：MySQL、Redis、Neo4j（密码 `11111111`）。

2. 启动后端（端口 8121）：

   ```powershell
   cd 后端代码/osLab-backend
   $env:SPRING_NEO4J_AUTHENTICATION_PASSWORD='11111111'
   ./mvnw.cmd spring-boot:run
   # 健康检查： http://localhost:8121/api/health/liveness
   ```

3. 启动前端（端口 8081，`/api` 代理到 8121）：

   ```powershell
   cd 前端代码/oslab-frontend
   npm run serve
   ```

4. **联调验收**（RunKey 标记本轮数据，不复位环境；末行 `RESULT = PASSED` 即环境可用）：

   ```powershell
   # 先启动回显沙箱（判题链路用，127.0.0.1:8090）
   python scripts/dev/sandbox_stub.py
   # 后端需以 CODESANDBOX_TYPE=remote 指向 http://127.0.0.1:8090/executeCode 启动
   powershell -ExecutionPolicy Bypass -File scripts/dev/verify-learning.ps1
   # 期望：PASS=80 FAIL=0 SKIP=7（SKIP 为 Real 判题等如实标注项），exit 0
   # 失败时 exit 1，报告写入 artifacts/final-check/
   ```

   演示账号未准备时先执行 `scripts/dev/prepare-demo-accounts.ps1 -DemoPassword <口令>`（幂等）。审核演示题 910010 保持 SUBMITTED 供审核链演示。

5. 演示账号（密码统一 `oslab123456`）：

   | 账号 | 角色 | 班级 |
   | --- | --- | --- |
   | `teacher_demo` | 教师/管理员 | 未绑定班级（管理视角） |
   | `student_demo1` | 学生 A | os2026 |
   | `student_demo2` | 学生 B | os2026 |

6. AI 配置（可选）：本机用户环境变量已配置 `AI_ARK_API_KEY / AI_ARK_BASE_URL / AI_ARK_MODEL` 时，节点导师为 AI 模式；未配置或调用失败时自动进入降级模式（界面明示），两种模式均已验收。

7. 内容就绪：两条知识链（内存管理→虚拟内存→页表→缺页中断→页面置换→FIFO/LRU；进程→进程状态→CPU 调度→时间片轮转/进程切换）的节点素材与 24 道已发布测评题由 `数据库文件/oslab_demo_seed_v3.sql` + `oslab_seed_v4_content.sql` 预置（幂等，可重复执行）。

## 1. 演示主线（九步）

### ① 知识图谱选节点（学生 A）

学生 A 登录后默认进入知识图谱（/graph）——按章节着色的课程结构叠加个人掌握状态；
选中「页面置换」节点，右侧详情显示掌握证据与关联分组，点唯一主按钮「进入学习」。

### ② 节点工作台答错一题（证据生成）

节点工作台四页签（知识内容 / 知识详解 / 题目练习 / 实践）：先看「知识内容」与「知识详解」，
切到「题目练习」**故意答错 1 题**（建议选 LRU 判断题，答"对"——正确答案是"错"）。
提交后立即看到：判分结果、解析与常见误区、掌握度变化（对照 BKT 公式，答错后约 0.1123 且为薄弱态）。

### ③ 图谱补救路径

回到知识图谱点「只看学习路径」——画布收窄到后端生成的补救路径（前置关系 + 行动入口），
沿路径进入缺页中断、LRU 关键节点。

### ④ 交互模拟预测

顶栏「实验中心」→「交互模拟」（/experiments/simulation）：页面置换步进回放，
先做「预测下一步」（服务端判分并写入学习事件，页面以 prediction.eventId 标注"已计入学习证据"），
再用对比模式查看 FIFO / LRU / OPT 三算法同序列缺页数（10 / 9 / 7）。改输入后旧结果标记"需重新运行"。

### ⑤ 编程实验：提交错误代码

从工作台「实践」页签或实验中心进入 LRU 编程实验（/experiments/code/:id），
提交一份**错误实现**（如命中不更新访问顺序），留页轮询到终态（Wrong Answer）。

### ⑥ 向导师提问后修正通过

失败后切「向导师提问」页签（自动预填题目/代码/判题上下文，用户点击发送），
按提示修改代码再提交 → Accepted；JUDGE PASS 事件落在 LRU 节点，掌握度回升。

### ⑦ 回看证据与记录回放

头像菜单 →「学习记录」（/records）：时间线查看刚产生的作答/预测/判题事件（含 before → after 与事件组），
打开图谱回放拖动滑块/播放，回顾学习前后状态。

### ⑧ 账号隔离（学生 B）

换学生 B 登录同一节点：颜色/证据/记录与学生 A 不同（B 无证据则为灰色）；
学生访问教师端接口返回无权限（40101）。

### ⑨ 教学管理与内容维护（管理员）

teacher_demo 登录 → 教学管理（/teaching/overview）：班级下拉选择真实班级，
「列表 / 图谱」切换查看班级薄弱热力；点击节点下钻（人数、薄弱占比、首次正确率、实验通过率、误区）；
时间线按班级过滤；章节资源完整度表；
到「测评管理」用 JSON 导入一道新题（预览 → 导入草稿），
或在「知识维护」（/teaching/knowledge）选中节点「编辑学习素材」发布，切回学生侧即可见。

## 2. 状态与预期说明

- 不追求"一次答对就变绿"：状态服从现有证据与 BKT 阈值（GREEN 需足量独立观测）。
- 无样本指标一律显示「暂无样本」，不显示 0%。
- 学生端任何接口不预发答案与解析；作答后才返回。

## 故障预案

| 场景 | 处理 |
| --- | --- |
| AI 模型不可用 | 直接演示降级模式：检索证据 + 确定性建议，界面已明示模式 |
| 代码沙箱判题慢 | 打开数据库中已有的真实提交记录展示终态，说明异步链路 |
| 页面刷新丢状态 | 属故障：掌握度/事件持久化在 MySQL，刷新即恢复，可现场验证 |
| 演示数据被弄乱 | 重跑 `scripts/dev/verify-learning.ps1` 检查环境（RunKey 标记、不复位数据）；素材/题目种子可重复执行恢复 |
