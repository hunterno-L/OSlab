System Call 系统调用
Chapter 01
系统调用

操作系统通过系统调用向用户程序提供服务，它是跨越权限边界的唯一合法通道。

系统调用（System Call）是操作系统内核提供给用户程序的 编程接口。 用户程序运行在受限的用户态， 当需要执行文件读写、进程创建、内存分配等特权操作时， 必须通过系统调用陷入内核态，由操作系统代为执行。

内核态
完全硬件访问 · Ring 0
↑ syscall 陷入 · eret / sysret 返回 ↓
用户态
受限执行环境 · Ring 3
🔒

为什么需要系统调用？

如果允许用户程序直接访问硬件，恶意程序可以破坏其他进程乃至整个系统。操作系统充当“守门人”——所有特权操作必须经过内核审查后代为执行，实现安全隔离。

⚙️

触发机制

通常由一条特殊指令触发，如 syscall（x86-64 / MIPS）或软件中断 int 0x80（x86）。执行后 CPU 将控制权转交给内核异常处理程序，同时切换至内核态。

📦

参数传递约定

系统调用号通过专用寄存器传递（如 $v0 / rax）。参数依次存入参数寄存器（最多4个），多余参数通过用户栈传递，返回值写回同一寄存器。

🔄

完整执行流程

1
用户程序设置系统调用号和参数寄存器
2
执行 syscall，CPU 切换至内核态，PC 跳转异常向量
3
内核保存寄存器现场（TrapFrame）
4
根据调用号分发到对应内核服务函数
5
执行服务，将返回值写回寄存器
6
eret 恢复现场，返回用户态继续执行

Chapter 03
代码实践

从汇编指令到 C 封装层再到内核处理，了解系统调用在各个层次的实际代码形态。

汇编层：直接使用 syscall 指令发起系统调用。约定调用号存入 $v0，参数依次存入 $a0~$a3，执行后返回值在 $v0。
# ────────────────────────────────────────────
# 示例：通过系统调用打印字符串，再退出进程
# ────────────────────────────────────────────

.data
  msg:  .asciiz  "Hello, OS!\n"

.text
.globl main

main:
    # ── 调用 sys_write ──────────────────────────
    li   $v0, 4004       # 系统调用号：write
    li   $a0, 1          # 参数1: 文件描述符 (stdout)
    la   $a1, msg        # 参数2: 字符串起始地址
    li   $a2, 11         # 参数3: 字节数
    syscall              # 陷入内核 → 触发异常
    # 返回后 $v0 = 实际写入字节数（11）

    # ── 调用 sys_exit ───────────────────────────
    li   $v0, 4001       # 系统调用号：exit
    li   $a0, 0          # 退出码 0 = 正常
    syscall
C 封装层：标准库通过内联汇编将 C 函数调用转换为系统调用。用户程序调用 write()，最终执行到下面这段封装代码。
/* ────────────────────────────────────────────
 * C 语言系统调用通用封装（内联汇编）
 * ──────────────────────────────────────────── */

/* 通用系统调用包装，最多4个参数 */
static inline int msyscall(int sysno,
                             int a1, int a2,
                             int a3, int a4) {
    int ret;
    __asm__ __volatile__(
        "move $v0, %1\n\t"  /* 加载系统调用号 */
        "move $a0, %2\n\t"  /* 参数1 */
        "move $a1, %3\n\t"  /* 参数2 */
        "move $a2, %4\n\t"  /* 参数3 */
        "move $a3, %5\n\t"  /* 参数4 */
        "syscall\n\t"        /* 触发系统调用 */
        "move %0, $v0\n\t"  /* 获取返回值 */
        : "=r"(ret)
        : "r"(sysno), "r"(a1), "r"(a2),
          "r"(a3), "r"(a4)
        : "$v0", "$a0", "$a1", "$a2", "$a3"
    );
    return ret;
}

/* 具体系统调用封装 */
int syscall_write(int fd, const void *buf, int n) {
    return msyscall(SYS_write, fd, (int)buf, n, 0);
}

void syscall_exit(int status) {
    msyscall(SYS_exit, status, 0, 0, 0);
}

int syscall_mem_alloc(uint envid, uint va, uint perm) {
    return msyscall(SYS_mem_alloc, envid, va, perm, 0);
}
内核处理层：汇编部分保存寄存器现场（TrapFrame），C 层根据系统调用号查表分发到具体的内核函数。
/* ────────────────────────────────────────────
 * 内核异常处理（简化示意）
 * ──────────────────────────────────────────── */

/* ── 汇编层：保存完整寄存器现场 ── */
NESTED(handle_sys, TF_SIZE, sp)
    subu  $sp, $sp, TF_SIZE     # 在内核栈开辟 TrapFrame
    SAVE_ALL                       # 保存所有通用寄存器

    mfc0  $k0, CP0_STATUS
    sw    $k0, TF_STATUS($sp)   # 保存 Status（含特权级）
    mfc0  $k0, CP0_EPC
    sw    $k0, TF_EPC($sp)      # 保存 EPC（返回地址）

    move  $a0, $sp               # 传入 TrapFrame 指针
    jal   do_syscall             # 调用 C 层分发函数
END(handle_sys)

/* ── C 层：系统调用号分发 ── */
void do_syscall(struct Trapframe *tf) {
    int sysno = tf->regs[2];    /* $v0：系统调用号 */
    int a0    = tf->regs[4];    /* $a0 */
    int a1    = tf->regs[5];    /* $a1 */
    int a2    = tf->regs[6];    /* $a2 */
    int a3    = tf->regs[7];    /* $a3 */

    /* 关键：EPC+4，跳过 syscall 指令，避免无限循环 */
    tf->cp0_epc += 4;

    if (sysno < 0 || sysno >= MAX_SYSNO) {
        tf->regs[2] = -E_INVAL;
        return;
    }
    tf->regs[2] = sys_call_table[sysno](a0, a1, a2, a3);
}
系统调用表：内核维护一张函数指针数组，以系统调用号为下标，映射到对应的内核服务函数。
/* ────────────────────────────────────────────
 * 系统调用号定义（调用号基于 POSIX 约定）
 * ──────────────────────────────────────────── */

/* 标准 POSIX 系统调用 */
#define SYS_exit          4001   /* 进程退出 */
#define SYS_fork          4002   /* 创建子进程 */
#define SYS_read          4003   /* 读文件 */
#define SYS_write         4004   /* 写文件 */
#define SYS_open          4005   /* 打开文件 */
#define SYS_close         4006   /* 关闭文件 */
#define SYS_getpid        4020   /* 获取进程 PID */
#define SYS_brk           4045   /* 调整堆边界 */

/* 自定义系统调用（进程/内存管理实验） */
#define SYS_mem_alloc     1      /* 分配物理页 */
#define SYS_mem_map       2      /* 建立虚拟映射 */
#define SYS_mem_unmap     3      /* 解除映射 */
#define SYS_env_alloc     4      /* 创建进程控制块 */
#define SYS_yield         5      /* 主动让出 CPU */
#define SYS_ipc_recv      6      /* IPC 阻塞接收 */
#define SYS_ipc_send      7      /* IPC 发送 */

/* 函数指针表 */
typedef int (*syscall_fn_t)(int, int, int, int);

syscall_fn_t sys_call_table[MAX_SYSNO] = {
    [SYS_mem_alloc] = (syscall_fn_t)sys_mem_alloc,
    [SYS_mem_map]   = (syscall_fn_t)sys_mem_map,
    [SYS_env_alloc] = (syscall_fn_t)sys_env_alloc,
    [SYS_yield]     = (syscall_fn_t)sys_yield,
    [SYS_ipc_recv]  = (syscall_fn_t)sys_ipc_recv,
    /* ... */
};
Chapter 04
生活中的类比

系统调用是抽象概念，用三个贴近日常的场景帮助你建立直觉。

🏦
类比场景 01
银行柜台
你（用户程序）不能直接走进金库（内核），必须到柜台（系统调用接口）填写申请，由银行职员（内核）代为操作金库中的资产（硬件资源）。每种业务有固定的业务号（系统调用号），柜台核验后才执行。
业务号 ≡ 系统调用号
填写申请单 ≡ 设置参数寄存器
柜台受理 ≡ syscall 陷入内核
返回回执 ≡ 写回返回值
🍽️
类比场景 02
餐厅点菜
食客（用户程序）无法直接进入厨房（内核）操作，只能通过菜单号（调用号）告知服务员（内核接口），厨房按需备餐，做好后端上桌（写回结果）。客人不需要知道厨房如何运作，只需要看菜单。
菜单号 ≡ 系统调用号
点菜参数 ≡ 参数寄存器
上菜 ≡ 系统调用返回值
厨房 ≡ 内核服务函数
🛂
类比场景 03
海关边检
普通旅客（用户态）不能随意进入边控区（内核态），每次需要跨越特权边界都必须经过检查口（异常向量入口），系统核验身份后执行操作，再护送回出发地（eret 返回用户态）。
过关申请 ≡ syscall 指令
验护照 ≡ 参数合法性校验
记录来时地址 ≡ EPC 寄存器
盖章放行 ≡ eret 返回

随堂小测

6 道选择题，检验对系统调用机制的理解，每题即时反馈解析。

0 / 6 已作答
QUESTION 01 / 06
在 MIPS 架构中，系统调用号应存放在哪个寄存器中？
系统调用号存放在 $v0 中（即 regs[2]）。执行 syscall 后，内核从 TrapFrame 的 regs[2] 读取该值来确定服务类型。
QUESTION 02 / 06
执行 syscall 指令后，CPU 会跳转到哪个地址执行异常处理程序？
通用异常（含 syscall）跳转地址为 0x80000080。TLB Miss 入口是 0x80000000，复位向量是 0xBFC00000，三者容易混淆，需记牢。
QUESTION 03 / 06
关于 EPC 寄存器在系统调用中的处理，以下描述正确的是？
EPC 保存的是触发异常的指令地址（即 syscall 本身）。若内核不做 EPC += 4 就直接 eret，程序会原地再执行一次 syscall，形成死循环。这是初学者常见的 Bug！
QUESTION 04 / 06
下列哪项操作必须通过系统调用才能完成？
向标准输出写文本涉及与 I/O 设备交互，属于特权操作，必须通过 sys_write 系统调用由内核代为执行。整数计算、栈变量分配、循环控制都是纯用户态操作，无需陷入内核。
QUESTION 05 / 06
系统调用比普通函数调用开销大的主要原因是？
主要开销来源：① 保存/恢复全部寄存器到 TrapFrame；② 特权级切换刷新流水线；③ 地址空间变化导致 TLB 和 Cache 部分失效。这解释了为何要尽量减少系统调用次数（如用 writev 合并多次写操作）。
QUESTION 06 / 06
系统调用完成后，内核通过什么指令从内核态返回用户态？
eret（Exception Return）是专用异常返回指令，它会：① 将 PC 设为 EPC；② 恢复 Status 寄存器中的特权级位；③ 从用户态继续执行。jr $ra 只是普通跳转，不会切换特权级。
