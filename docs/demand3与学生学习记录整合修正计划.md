## 5. 阶段二：知识图谱节点、关系和布局

### 5.1 节点视觉规则

1. 图谱节点只承担“识别概念”和“显示掌握状态”，不在卡片内堆叠说明段落。详情、描述、章节路径和学习操作放在既有右侧节点详情区域。
2. 节点改为紧凑、稳定尺寸：建议常规节点宽 104–152px、高 32–42px；标题最多两行或单行省略，长名称通过 hover/focus 展示全名。节点尺寸分档最多三档，不能每次渲染抖动变化。
3. 类别和个人掌握状态分开表达：类别使用浅色表面/边框；掌握状态使用短色条或小圆点；选中态使用清晰的蓝色描边/外环。弱状态不得把标题文字整体变淡至不可读。
4. 默认缩放层只保留名称与必要状态标识；章节、类别、掌握状态的详尽说明由画布图例和详情栏承接。缩小时按缩放层级隐藏附属信息，节点 hit-area 保持可点击。
5. 单击只选择节点并更新详情栏；双击沿用现有行为进入节点学习工作台。换选节点时旧高亮立即清除；筛选后被隐藏的选中节点不继续残留高亮。

### 5.2 层级布局与连线

1. 默认课程图按课程结构组织成稳定区域：章节/子目录或学习单元形成空间分组，知识节点在所属区域内按目录顺序或前置关系层级布置。目录层级和学习顺序一眼可辨；不要把 150 个节点全部投入随机力导向后任其散开。
2. 对没有目录坐标的独立节点，按章节/类别放入可辨认的邻近区域，不覆盖成一堆。少量跨章节依赖保留为跨区边。
3. 关系方向和语义使用更清晰的描边比例：关系线建议 1.5–2px，选中邻接关系 2–2.5px；箭头尺寸与节点尺寸匹配；弱化非关联边但保留可见下限。
4. 默认不在所有边上绘制关系文字。开启“关系标签”时，以水平短标签显示；优先显示当前选中/悬停节点邻边和当前缩放下不冲突的标签。过密时执行避让或按需显示，不旋转放大标签填满画布。
5. 不同关系继续保留方向、线型和颜色语义，图例能解释依赖/前置、包含、相关、实现等已有类型。标签关闭时不残留文字。
6. 过滤、切换个人掌握、历史回放时复用同一套布局输入和节点身份，不因状态颜色更新而随机改变坐标。新筛选结果重新适配画布，重置视野不裁掉边缘节点。
7. 检查 `KnowledgeGraph.vue` 中对 ECharts 内部字段的缩放/控制器访问；新实现优先采用组件公开的事件和变换接口，避免继续扩散对 `_controllerHost` 等内部结构的依赖。若短期保留，必须将其封装在单一适配点并以实际版本回归测试。

### 5.3 图谱验收

- 桌面全图：150+ 节点可完整适配；标签不会超出容器或压在关系文字上。
- 单元/路径局部：主要路径顺序明确、节点互不遮挡、边不被节点大面积覆盖。

### 6.2 恢复和保留交互

所有适用算法保留当前已有能力，并按资源矩阵补齐：

- 输入编辑、默认示例恢复、行/项增加删除和即时校验。

### 6.3 18 项输入和行为补齐

按算法组实现并测试以下行为：

- **CPU 调度：**进程行可增删；输入到达时间、运行时间及所需优先级；RR 可设置时间片。MLFQ 支持 2–6 层队列，每层独立配置时间片，并呈现进入/降级/抢占/完成队列事件；仍保留有明确默认示例的快捷恢复。
- **分区分配：**允许输入多个初始空闲分区大小和多个进程需求，展示各次分配、剩余空间和释放/合并规则；保留当前 `ALLOC/FREE` 演示作为扩展操作。不可把多分区资源简化为一个总内存块后宣称等价。
- **页面置换：**FIFO/LRU/OPT 均支持 1–60 个物理块和访问序列；每步展示命中/缺页、被换出页和帧状态，序列长度按画布可读性分页/横向滚动。
- **磁盘调度：**支持初始磁头、请求序列和方向，按授权资源范围 1–200 验证端点；显示移动顺序和磁头移动总量，SCAN/C-SCAN 的端点与回扫计费按算法定义实现并说明。
- **速度和日志：**步骤动画、动态提示、队列日志使用同一播放器状态。暂停后不得继续追加事件；恢复后从当前步骤继续；调整输入后必须重跑才能使用旧运行结果。
- **解析内容：**将资源中已有的算法思想/特点整理到可访问的解析面板；不把当前每步 detail 误当成旧解析的完整替代。

- 活动名称、类型、时间和结果；以资源实际名称为主，不把所有模拟显示成同一个泛化标题。
- 来源上下文：课程、学习单元、学习活动、任务名称/任务轮次（有对应来源时显示）。
- 关联知识节点及本次掌握变化；多个节点受同一操作影响时，默认折叠为一条活动，展开查看各节点证据。
- 独立/非独立证据与系统错误的准确标记。活动时间线记录“发生过什么”；数字孪生掌握度只呈现被模型接受的证据和前后变化。
- 直接回到资源、任务或提交详情的操作。

顶部筛选包括活动类型、节点、日期和课程/单元；分页统计按学习活动数，不按因同一作答影响多个知识节点产生的事件行数。保留待巩固列表和只读图谱历史回放入口，不把复习建议、任务提交或纯演示伪装成掌握状态。

### 7.2 记录类型和字段映射

| 学生活动 | 主要来源 | 时间线显示 | 主要回跳 |
|---|---|---|---|
| 题目练习作答 | `learning_event` 的 ATTEMPT / `LearningAttempt` | 题目标题、对错、首次/重复、相关知识点 | 打开同一题或其所属单元练习 |
| 编程实验判题 | `learning_event` 的 JUDGE / `QuestionSubmit` | 实验标题、判题结果、语言/错误摘要 | 打开对应提交详情或实验 |
| 算法模拟 | 判分型预测使用 `learning_event`；纯演示运行写入独立的学习活动记录 | 算法名称、输入快照、运行结果摘要和时间；判分结果单独显示 | 打开相同 algorithm key 的模拟；可恢复的输入来自记录快照 |
| 学习任务 | `LearningTaskRecipient`、`LearningTaskItemWork`、`LearningTaskSubmission` | 接受任务、任务内容状态、每轮正式提交/批阅状态与分数 | 打开 `/tasks/:taskCode` 对应任务及轮次/内容块 |
| 单元进度 | `learning_activity_progress`、课程活动来源字段 | 已完成的课程活动及完成规则 | 打开对应单元和 activityCode |

正式的题目作答、判题与任务轮次提交必须可追溯。草稿自动保存不逐次生成噪音时间线；在任务详情展示当前草稿状态即可。任务文件显示原文件名和对应任务项，不在记录卡片直接暴露存储地址。

### 7.3 API 与分组实现

1. 当前 `/api/learning/mastery/timeline` 返回按知识节点展开的学习事件分页；现有 `LearningEvent.eventGroupKey` 已能标识同一次作答/判题影响的多个节点，事件也包含 `sourceUnitCode`、`sourceActivityCode`、`sourceTaskCode`、`sourceTaskItemCode`、`sourceTaskRound`。
2. 给学生记录增加一个“活动记录”查询契约，例如 `GET /api/learning/records/activities`，支持 `type/courseCode/unitCode/nodeCode/startTime/endTime/current/pageSize`，服务端先按活动归并，再分页并返回活动总数。
3. 后端活动 VO 至少包含：`activityId/activityType/title/status/result/occurredAt/courseCode/unitCode/activityCode/taskCode/taskItemCode/roundNo/resourceType/resourceId/nodeRefs/evidenceRefs/returnRoute`。可用字段为空时保持 nullable；不要以姓名、节点中文名或前端猜测来构造算法身份。
4. ATTEMPT/JUDGE/判分型 SIMULATION 按 `eventGroupKey` 合为一条活动卡片；其节点数组保留各自 before/after、结果、是否独立证据。无 `eventGroupKey` 的历史事件以现有事件自身作为一条记录。
5. 普通算法演示没有判分或知识节点掌握变化时，也要作为“运行记录”进入学生记录：用户点击运行并产生完整演示结果后，服务端保存一条独立活动记录，至少包括当前用户、algorithm key、展示标题、输入参数快照、结果摘要、运行时间，以及可获得的课程/单元/activity 上下文。无需保存每一帧或每次暂停/拖动；重置但未运行、输入尚未执行、运行报错不生成成功运行记录。若演示过程另有可判分提交，则仍按判分型证据记录，不把同一运行重复显示为两条主活动。
6. 纯演示运行记录与 `LearningEvent` 掌握证据分开存储/标注，不触发掌握度更新；不得伪装成正确率、通过记录或节点掌握证据。可在活动详情显示输入快照和运行结果，并用 algorithm key 返回相同模拟；参数快照采用 JSON 结构化字段，大小有上限，不保存源代码或敏感数据。
7. 任务记录从当前学生自己的 recipient、item work、submission 和 task snapshot 组装。每轮正式提交是一条稳定历史记录；接受状态显示任务接受时间；工作草稿反映为任务状态，不把每次保存重复追加为新活动。
8. 单元进度显示已完成活动，不重复复制事件证据。点击进入对应 `/courses/:courseCode/units/:unitCode` 并选中 activityCode。
9. 新活动查询只读取当前登录用户记录，不接收任意 userId。图谱 snapshot 仍经现有 `/learning/mastery/snapshot?atEventId=...` 只读回放；活动卡片展开后仍以 eventGroupKey 关联其节点证据。
10. 先复用当前表和稳定快照；仅当普通模拟运行记录无法从现有事件/任务/进度记录中重建时，增加一张最小活动记录表或等价持久化模型。该模型不与 `LearningEvent` 混用掌握证据。任何新增契约须在前后端 API 类型、查询服务和测试中同时落地。

### 7.4 记录验收

- 用一条关联多个知识点的题目作答验证：时间线只显示一条活动；展开后显示全部受影响节点；节点回放仍能正确重建该事件前后状态。
- 用一次编程实验通过、一次答案错误、一次 SYSTEM_ERROR 验证标题、回跳与掌握证据标签；SYSTEM_ERROR 不被计作失败掌握证据。
- 对带 algorithm key 的模拟记录验证正确回到同一个算法；旧记录没有 key 时显示兼容标题，回到算法目录而不是错误猜算法。
- 验证普通模拟完成一次运行后有一条活动记录，能恢复算法与输入快照；逐步播放不重复造记录，运行错误不记作成功，且纯演示不增加掌握度。
- 完整验证任务接受、内容草稿、题目/实验任务项、文件材料、正式提交、重新提交轮次、教师批阅/退回状态。学生只看到自己的任务和提交。
- 验证单元活动完成状态与学习记录互相定位，分页、日期过滤、节点过滤和空态均按活动数工作。
- 验证记录页的“活动事实”和个人图谱的“掌握证据”不同步造假：单纯播放、保存草稿、系统错误不增加掌握度。
