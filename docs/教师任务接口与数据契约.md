# 教师任务接口与数据契约

更新：2026-10-21
实现依据：`docs/教师端内容管理与学习任务执行计划.md` 与当前源码。

所有路径相对于后端上下文 `/api`，响应沿用 `BaseResponse { code, data, message }`。  
教师端继续使用 `ADMIN` 承载教师能力；任务写操作再校验 `creatorId`。学生接口只按当前登录用户查询接收记录。

## 1. 通用约定

- 新任务域的所有 BIGINT 身份（taskCode 之外的 userId、itemId、submissionId、fileId）在 JSON 中按字符串返回。
- 时间使用本地时间 ISO-8601：`yyyy-MM-dd'T'HH:mm:ss`；请求也兼容 `yyyy-MM-dd HH:mm:ss`。
- 任务状态：`DRAFT / PUBLISHED / CLOSED`，`isArchived` 独立。
- 接收人状态：`PENDING / IN_PROGRESS / SUBMITTED / RETURNED / REVIEWED`；逾期由 `dueAt + allowLate` 推导。
- 乐观锁：草稿保存、发布、设置携带 `rowVersion`；不匹配返回 `50001 任务已被其他编辑保存，请刷新`。
- 幂等：发布仅从 DRAFT 发生一次，重复调用返回已发布结果；正式提交按 `(recipientId, submissionKey)` 返回同一提交。
- 内容块类型：`TEXT / MATERIAL / QUESTION / EXPERIMENT`；题目/实验来源：`REFERENCE / AUTHORED`。
- 资源作用域：共享资源 `resourceScope=SHARED`；任务执行副本 `resourceScope=TASK`，只能通过任务上下文访问。

## 2. 教师任务接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/teaching/tasks` | 分页；参数 `title,status,className,archived,current,pageSize`；默认仅当前创建者、未归档 |
| POST | `/teaching/tasks` | 创建草稿；返回完整任务（含 `taskCode,rowVersion`） |
| GET | `/teaching/tasks/{taskCode}` | 创建者读取草稿或发布快照（含参考答案/隐藏用例） |
| PUT | `/teaching/tasks/{taskCode}` | 仅 DRAFT 完整保存；请求见 §3 |
| POST | `/teaching/tasks/{taskCode}/audience-preview` | 解析班级/学生选择；返回有效人数与排除项 |
| POST | `/teaching/tasks/{taskCode}/preview` | 学生视角预览；不返回答案、解析、隐藏用例 |
| POST | `/teaching/tasks/{taskCode}/publish` | 请求 `{rowVersion}`；生成执行副本、快照、接收名单 |
| PATCH | `/teaching/tasks/{taskCode}/settings` | 发布后延长截止/逾期开关/追加说明 |
| POST | `/teaching/tasks/{taskCode}/recipients` | 发布后显式追加接收学生；返回 `added/already/excluded` |
| POST | `/teaching/tasks/{taskCode}/close` | 关闭任务；保留查阅、下载、批阅 |
| POST | `/teaching/tasks/{taskCode}/duplicate` | 复制为新草稿，不复制学生答案 |
| POST | `/teaching/tasks/{taskCode}/archive` | 列表归档 |
| DELETE | `/teaching/tasks/{taskCode}` | 仅删除草稿 |
| GET | `/teaching/tasks/{taskCode}/recipients` | 接收人进度、轮次、分数、待批阅状态 |
| GET | `/teaching/tasks/{taskCode}/submissions/{submissionId}` | 提交详情：文字、文件、作答、代码与判题结果 |
| POST | `/teaching/tasks/{taskCode}/submissions/{submissionId}/review` | 按项分数/评语；服务端重算总分 |
| POST | `/teaching/tasks/{taskCode}/submissions/{submissionId}/return` | 退回并开启下一轮；必要时必须提供新 `dueAt` |
| GET | `/teaching/tasks/resources/questions` | 共享已发布题目选择器 |
| GET | `/teaching/tasks/resources/questions/{id}` | 题目完整编辑内容（答案/解析/节点） |
| GET | `/teaching/tasks/resources/experiments` | 共享已发布实验选择器 |
| GET | `/teaching/tasks/resources/experiments/{id}` | 实验完整编辑内容（用例/配置/初始代码） |

### 2.1 保存请求

```json
{
  "title": "第三章混合任务",
  "description": "说明文字",
  "courseCode": "course.operating-systems",
  "unitCode": "unit.memory.paging",
  "dueAt": "2026-11-01T23:59:59",
  "allowLate": true,
  "rowVersion": 3,
  "audience": { "classNames": ["操作系统 2024-1 班"], "userIds": ["1925422357237989377"] },
  "items": [
    {
      "itemCode": "item.intro",
      "itemType": "TEXT",
      "sourceMode": null,
      "required": true,
      "maxScore": null,
      "content": {
        "title": "任务说明",
        "contentMd": "# 阅读要求\n请先阅读资料。",
        "requireText": false,
        "requireFile": false,
        "requireConfirm": false
      }
    }
  ]
}
```

### 2.2 内容块 `content` 结构

**TEXT**

```json
{"title":"标题","contentMd":"Markdown 正文","requireText":false,"requireFile":false,"requireConfirm":false,"textPrompt":"答复提示"}
```

任一 `require*` 为 true 时，该块进入人工批阅；全部为 false 时正式提交即视为确认完成。

**MATERIAL**

```json
{"title":"资料","description":"阅读说明","files":[{"fileId":"...","originalName":"a.docx","size":1024,"ext":"docx"}],"requireConfirm":true,"requireFile":false}
```

教师资料需先通过 `/task-files` 以 `purpose=TEACHER_MATERIAL` 上传，再在保存草稿时引用。每块最多 5 个文件。

**QUESTION**

```json
{
  "sourceMode":"AUTHORED",
  "title":"单选题",
  "content":"题干 Markdown",
  "type":"SINGLE",
  "options":[{"key":"A","value":"选项 A"},{"key":"B","value":"选项 B"}],
  "answer":"A",
  "analysis":"解析",
  "misconception":"常见误区",
  "difficulty":2,
  "sectionCode":"sec.memory.paging",
  "nodeCodes":["os.memory.paging"]
}
```

`type`：`JUDGE`（answer `"true"/"false"`）、`SINGLE`（answer 选项 key）、`MULTIPLE`（answer key 数组）、`FILL_BLANK`（answer 字符串或可接受答案数组）。
`REFERENCE` 时至少提供 `sourceQuestionId`；服务端载入来源完整内容，可再覆盖字段。发布时若来源修订已变化，返回需重新预览的明确错误。

**EXPERIMENT**

```json
{
  "sourceMode":"AUTHORED",
  "title":"求和",
  "content":"实验说明 Markdown",
  "originalCode":"import java.util.*; ...",
  "answer":"参考解（可选）",
  "manualReview":false,
  "requirePass":true,
  "judgeCase":[{"input":"1 2","output":"3"}],
  "judgeConfig":{"timeLimit":1000,"memoryLimit":256,"stackLimit":128},
  "languages":["java"],
  "samples":[{"input":"1 2","output":"3"}],
  "tags":["实验"],
  "nodeCodes":["os.overview.concurrency"]
}
```

自动判题要求至少一个用例、正数限制与至少一种语言（`java/cpp/c/go`）。`manualReview=true` 时可不提供用例，改由 `requireText/requireFile` 指定报告要求，不执行代码判题。

## 3. 学生任务接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/learning/tasks` | 本人接收的任务分页；`status` 支持 PENDING/IN_PROGRESS/SUBMITTED/REVIEWED/RETURNED |
| GET | `/learning/tasks/summary` | 待接收/进行中/待批阅/已批阅数量 |
| GET | `/learning/tasks/{taskCode}` | 学生快照、当前轮次、工作草稿、允许操作、历史摘要 |
| POST | `/learning/tasks/{taskCode}/accept` | 幂等接收；PENDING → IN_PROGRESS |
| PUT | `/learning/tasks/{taskCode}/items/{itemCode}/work` | 保存文字/答案草稿/文件 ID/代码草稿 |
| POST | `/learning/tasks/{taskCode}/items/{itemCode}/answer` | 客观题作答；请求 `{roundNo,submissionKey,answer}` |
| POST | `/learning/tasks/{taskCode}/items/{itemCode}/code-submissions` | 代码提交；请求 `{roundNo,submissionKey,language,code}` |
| GET | `/learning/tasks/{taskCode}/items/{itemCode}/code-submissions/{id}` | 本人判题状态与脱敏详情 |
| POST | `/learning/tasks/{taskCode}/submit` | 请求 `{roundNo,submissionKey}`；校验必做项与判题终态 |
| GET | `/learning/tasks/{taskCode}/submissions` | 本人历史正式提交摘要 |
| GET | `/learning/tasks/{taskCode}/submissions/{submissionId}` | 本人单轮答案、文件、代码、得分与批阅 |

`saveWork` 请求：

```json
{"roundNo":2,"answer":{"confirm":true},"textResponse":"实验说明","fileIds":[2112846968558112771]}
```

- 题目作答必须调用 `/answer` 才会产生正式判分；只保存 `answer` 草稿不进入提交依据。
- 代码提交必须等待终态；系统故障（status=3）不满足提交条件，也不写知识错误证据。
- 纯文字/纯资料任务若无答复要求，正式提交即视为完成。

## 4. 任务附件接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/task-files` | multipart：`file` + `taskCode` + `itemCode` + `purpose` |
| GET | `/task-files/{fileId}` | 校验任务身份后下载，保留原文件名 |
| DELETE | `/task-files/{fileId}` | 草稿资料或未被正式提交引用的本人文件可删除 |

`purpose`：`TEACHER_MATERIAL`（仅创建者、仅草稿可传）、`STUDENT_WORK`（仅已接收学生、任务发布中）。

- 单文件 ≤ 10 MiB；允许 `.doc .docx .pdf .txt .md .png .jpg .jpeg .webp`；每块最多 5 个。
- 下载响应：`Content-Disposition: attachment; filename*=UTF-8''...`、`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`。
- 已正式提交引用的文件禁止删除/覆盖。

## 5. 教师内容维护接口（本轮补齐）

### 5.1 共享实验

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/teaching/experiments` | 新建共享实验草稿；保留真实 ID，`publicationStatus=DRAFT` |
| GET | `/teaching/experiments/{id}` | 编辑内容、节点映射、待应用修订 |
| PUT | `/teaching/experiments/{id}` | 草稿直接更新；已发布则保存为待应用修订 |
| POST | `/teaching/experiments/{id}/apply` | 将待应用修订写回原实验并设为 PUBLISHED |
| POST | `/teaching/experiments/{id}/publish` | 发布草稿实验 |
| POST | `/teaching/experiments/{id}/offline` | 下线实验 |

请求字段：`title,content,originalCode,answer,tags,judgeCase,judgeConfig,nodeCodes,apply`。  
已发布实验改稿不会改变学生当前看到的内容，直到显式应用。

### 5.2 知识节点关系

`PUT /teaching/content/nodes/{nodeCode}/relations`

```json
{"relations":[{"toNodeCode":"os.memory.paging","relationType":"REQUIRES","reason":"先修 paging"}]}
```

- 只替换本节点出向关系，入向关系保留；关系类型：`REQUIRES/CONTAINS/BASED_ON/IMPLEMENTS/RELATED_TO/CONTRASTS_WITH`。
- `REQUIRES` 检查环；其他关系不做全图无环限制。
- MySQL 写入后插入 `course_graph_sync` 待同步记录；响应 `syncStatus=PENDING`，可在 `GET /teaching/content/graph-sync` 查看/重试。

### 5.3 学习单元

沿用 `GET/PUT /teaching/units/{unitCode}`、`POST /teaching/units/{unitCode}/publish`。  
前端已提供表单（基础信息、目标、节点映射、活动、完成规则），JSON 仅保留为高级工具。新单元先用稳定 `unitCode` 保存草稿。

### 5.4 共享题目

沿用 `POST /learning/questions/add|update`、`/manage/get`、`/manage/list/page`、`/review`。  
本轮补充 `sectionCode` 字段；编辑已发布题继续进入 `TeachingAssessmentService` 修订/发布流程，不直接覆盖已发布内容。

## 6. 资源隔离与证据

- 发布任务时，每个 QUESTION/EXPERIMENT 生成 `learning_question/question` 的 `TASK` 副本；题面、答案、判题用例、限制和节点映射全部复制。
- 通用题目/实验列表、目录计数、测评候选池、资源选择器只读取 `SHARED`；通用详情/提交接口遇到 TASK 副本返回不存在/无权限。
- 任务副本不可通过旧编辑、批量维护或下线按钮修改；任务关闭/归档后副本与历史保留。
- 旧 `/question/question_submit/*` 列表排除 `resourceScope=TASK` 的提交；直接提交详情仅允许提交本人或任务创建者读取，其他管理员不能凭提交 ID 绕过任务授权。
- `learning_attempt/question_submit/learning_event` 写入 `sourceTaskCode/sourceTaskItemCode/sourceTaskRound`。
- `evaluationIdentity`：引用题按来源稳定代码 + 规范化判分内容指纹；自编题按规范化题干/选项/答案/节点生成。重复身份只记行为事件，不重复增加 BKT 独立观测。
- 接收、下载、批阅、任务总分不写掌握度。

## 7. 错误示例

```json
{"code":50001,"data":null,"message":"还有未完成的必做项：实践报告（需要填写说明）"}
{"code":50001,"data":null,"message":"「Sum two integers」判题系统故障，请重新提交代码"}
{"code":40101,"data":null,"message":"仅任务创建者可操作该任务"}
{"code":40101,"data":null,"message":"无权下载该文件"}
{"code":50001,"data":null,"message":"已超过截止时间且不允许逾期提交"}
```

## 8. 配置

```yaml
spring.servlet.multipart.max-file-size: 10MB
spring.servlet.multipart.max-request-size: 12MB
oslab.tasks.storage-dir: ${OSLAB_TASK_STORAGE_DIR:./data/task-files}
oslab.tasks.max-file-bytes: 10485760
oslab.tasks.max-files-per-item: 5
```

附件目录必须位于服务器私有持久卷，不能放在 Nginx 静态目录。容器部署请挂载持久卷并设置 `OSLAB_TASK_STORAGE_DIR`。
