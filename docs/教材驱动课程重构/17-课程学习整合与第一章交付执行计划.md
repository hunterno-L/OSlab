## 1. 完成定义

学生从唯一“课程学习”导航进入课程主工作区；左侧按教材展示章节、小节和学习单元，目录选择驱动中央图谱范围，右侧显示节点或单元信息。原“章节学习覆盖”区域由目录树取代。保留数字孪生、节点工作台、关系标签及题目练习、算法模拟、编程实验三个独立入口。

题目练习以章节/小节/学习单元组织，可按图谱节点和个人作答状态筛选；题卡从上至下连续排列，每题就地作答和反馈。实验中心的旧模拟工作台退场，由授权资源的新目录和播放器承载 18 项演示；判分只对已实现并通过服务端验证的算法开放。

第一章以已接收的 35 个节点、57 个教学块、已导入的 103 道题和十个单元草稿为基础，处理 A 题目尚存的争议，再编排活动和执行系统发布流程。J 的知识内容直接沿用此前导入数据，不重复审核或导入。确认无用的旧节点或题目按稳定代码清理，但不删除作答、学习事件、掌握历史或仍有实际引用的资源。

## 3. 目标交互与信息架构

### 3.1 一个“课程学习”入口

- 顶栏只保留一个面向学生的“课程学习”项，目标 `/graph`；删除独立 `/courses` 导航项。学生默认入口指向 `/graph`，首页不再重复放“课程学习”和“知识图谱”两张卡片。
- `/courses`、`/courses/:courseCode` 保留兼容跳转并传递 courseCode/sectionCode/unitCode；`/courses/:courseCode/units/:unitCode` 继续打开真实单元工作页。
- `/courses/.../units/...` 的 navKey 同样归到 `graph`，不因进入单元又选中另一个导航项。图谱页与单元页复用一个 `CourseCatalogSidebar` 和课程工作区壳；单元页也保留章/节/单元目录，原活动导航改成内容区内的步骤条/锚点，不再叠加第二条左侧大导航。
- 节点工作台以 `/knowledge/concept/:nodeCode` 和稳定代码为主键；旧名称路径仅作兼容。返回时保留目录、图谱和单元上下文。
- 题目练习、算法模拟、编程实验仍各自独立可达；算法模拟继续显示在实验中心独立入口中。

### 3.2 左侧目录驱动中央图谱

左侧以课程章节→小节→学习单元树替换“章节学习覆盖”。章节、小节、单元都有选中态；单元只显示发布状态与真实进度。未作答/未评估不显示为掌握度 0 或薄弱。

- 点章节：范围包含该章所有后代小节和已发布单元的教学节点。
- 点小节：图谱聚焦该小节及其单元的教学节点。
- 点单元：突出 `nodeMappings` 中 `TEACHES` 节点；可将真实关系相邻节点弱化显示为上下文。点选只改变视图，不自动写学习进度。
- 点图谱节点：右侧显示定义、小节、个人概念/实践状态和真实证据；可进入节点工作台、查看关联题目或打开所在单元。
- “开始/继续学习”进入已有单元页面；返回后恢复目录选中、图谱范围和滚动/节点上下文。
- 删去冗余“课程结构”“课程知识结构”文案、旧章节筛选、知识层筛选和实体类型筛选及对应的 ref、watch、clearFilters 分支；不是只隐藏控件。
- 数字孪生继续保留：同一稳定节点叠加当前学生的掌握状态与证据；关系标签、学习路径、重置视野等有效操作继续工作。
- 学生目录不改写教师图谱维护能力；`/teaching/knowledge` 仍可创建节点、改关系和查看管理信息。

首次进入 `/graph` 时读取课程 resume：已有记录就定位当前单元；新学生定位第一个已发布单元并展开其父目录。右侧先显示该单元目标、已学位置和“开始/继续学习”，不是无提示地抛出全量图谱。只有学生主动选择全课程或章节时才放大探索范围。保留一个主操作，不新增欢迎大屏、课程首页或并列的两套目录。

目录标题的点击与展开按钮分开：箭头只展开/折叠，章/节标题选择范围，单元标题预览单元并联动图谱，右侧主按钮进入学习。图谱节点点击可以切换右侧到节点信息，但不清掉左侧单元上下文；右侧须能返回当前单元概览。

沿用已确认的白/浅灰背景、克制蓝色、细边框和现有 `learning-theme.css` 变量。桌面课程页采用约 250–280px 目录、弹性主区、约 300–340px 详情区；窄屏先收起右侧详情，再将目录变为可唤起抽屉，不压成不可读的图谱。单元正文限制阅读行宽，目录和主内容各自正确滚动。无需重新设计品牌或引入新组件框架。

### 3.3 题目练习与瀑布卡片流

分类导航只保留**章节目录→小节→学习单元、图谱节点、个人作答状态**。移除题型、难度等分类控件及它们的查询/状态逻辑。题目标题搜索是检索，不属于分类，可独立保留在题卡流上方。

- 目录依赖稳定 sectionCode/unitCode，不以中文章名、题号前缀或旧图谱 chapter 推导归属。
- 同屏纵向展示多张题卡；移除“当前一题+上一题/下一题”作为练习列表主界面。
- 每题显示题干、选项、关联节点、所属单元/小节和个人最近作答状态；作答后在本卡内显示服务端判分、解析和误区，不跳页也不重置其余卡片。
- 复用 `QuestionAnswerCard.vue` 和现有四种客观题判分。页面分批加载每次 10–20 道，不一次请求全库；切换目录回第一页，最后发起的筛选请求优先。
- 连续测评可以保留为独立次级模式，继续使用固定测评会话页；它不是题目练习默认视图，并继承相同目录/节点/状态范围。
- 单元配套题继续使用 PRIMARY/SECONDARY nodeCode 关联；题目流中 unitCode 范围来自已发布单元的配套题映射与 QUESTION 活动，二者的差别见 4.4。
- 学习状态沿用最新有效作答的服务端定义：`ALL`、`UNANSWERED`、`NEEDS_REVIEW`、`CORRECT`。必须在分页前完成状态过滤，目录计数和实际题目使用同一查询谓词。

## 4. 数据和接口契约

### 4.1 可复用接口与拟扩展字段

继续使用当前学生接口：

```text
GET  /api/courses/{courseCode}/outline
GET  /api/courses/units/{unitCode}
GET  /api/courses/nodes/{nodeCode}/units
POST /api/courses/units/{unitCode}/position
POST /api/courses/activities/{activityCode}/complete
POST /api/learning/questions/list/page
POST /api/learning/questions/catalog
POST /api/learning/questions/answer
POST /api/learning/assessment/start
```

在 `CourseService.outline()` 已发布单元摘要中补充 `nodeMappings: [{nodeCode, role, name?}]`，仅从该单元 `publishedJson` 读取；前端据此快速计算图谱直接节点。章节/小节范围由 `course_section.parentSectionCode` 递归后代得到。

扩展 `LearningQuestionQueryRequest`、catalog 请求和测评 start 请求，增加可选 `courseCode`、`sectionCode`、`unitCode`、`nodeCode`。旧 `chapter`、`nodeName` 供兼容路由/管理页使用；新版学生界面不依赖旧字段。catalog 与列表共用过滤器。

过滤语义：

1. `sectionCode` 包含该小节及后代目录中的发布题目；单元和小节同时存在时取交集。
2. 单元到题目的正式映射来自已发布单元 JSON 的 `questionMappings`（本轮新增，见 4.4）与 `activityType=PRACTICE|ASSESSMENT`、`reference.kind=QUESTION`、`reference.code=questionCode` 活动的并集，按 questionCode 去重。
3. `usageSuggestions` 只是导入建议，必须由 L 选定并写入单元的正式 `questionMappings` 或活动后才能对学生显示为该单元题目。
4. **不可从 `learning_unit_activity` 草稿表行单独判定学生可见关系**：保存单元草稿会更新这些关系行，可能早于发布快照。
5. 节点筛选以 `learning_question_node.nodeCode` 匹配，PRIMARY/SECONDARY 均可；与 unitCode 同时选中时仍需满足正式单元活动映射。
6. 学生列表要求题目 `isDelete=0 && reviewStatus=PUBLISHED`；状态过滤在分页前执行。管理员审核列表继续走原权限和数据口径。
7. 作答沿用 `POST /api/learning/questions/answer`。前端 `QuestionAnswerCard` 与课程模块已使用 `sourceUnitCode`、`sourceActivityCode`；复用现有 DTO 和结果校验。只有显式来源活动一致的作答，才能经课程 complete 接口推进该活动；仅带 unitCode 筛题不等于正在完成该单元的某个活动，不能自动填造 activityCode。

题目范围、节点和状态取交集；目录先前所属的节点不在新目录范围时清除该节点筛选并保留其他适用条件。catalog 返回该课程真实目录树、已发布单元题量、范围内节点列表及个人状态统计；章/节题数按 distinct questionCode 计，不能把多个单元引用同一道题重复累加。未归入教材的保留旧题只出现在“全部题目”与节点/状态范围，不新建“历史/来源/难度”等分类。

建议将共享解析器命名为 `LearningQuestionScopeService`，这是本轮待新增内部服务，不是已有 API。列表、catalog 与 `listEligibleQuestionIds()` 一起接入它；`LearningAssessmentRunController.StartRequest` 是现有控制器内嵌类型，不要寻找或新造同名外部 DTO 再遗漏实际入口。

`CourseContentService.validateUnit()` 已接受 PRACTICE/ASSESSMENT + QUESTION + SUBMIT/PASS。`LearningQuestionQueryRequest`、`LearningQuestionServiceImpl`、`LearningAssessmentRunController` 是后端修改落点。新增模拟算法 API 时，明确 request/VO 与适配器约定，不把未识别 JSON 参数当成已有功能。

### 4.4 题目映射与必做活动分开

**不能为让题库筛选找到题目，就把全部 103 题都塞成课程必做步骤。** 当前包对十个单元给出 113 条用途建议（题目唯一数仍为 103）：基本概念 7、服务 8、发展 26、运行方式 22、中断 11、系统调用 11、结构 12、引导 7、虚拟机 3、章末复习 6。
