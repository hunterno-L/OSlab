两份文件作为同章一个题目包交付。按教材选择题组和综合题组分别查漏，适当补判断、填空和多选，自编题标来源，不为题型比例机械凑题。自审按 16／20 文档。

## 6. 成员侧先完成文件检查

仅需 Node.js，无依赖安装。在各自开工包根目录：

```powershell
# J
node tools/check-member-package.mjs . --work-dir work/ch02

# A，引用 J 发来的本章交付目录
node tools/check-member-package.mjs . --work-dir work/ch02 --with-j "../J-第二章-知识-001"

# A，本章实验修订
node tools/check-member-package.mjs . --work-dir experiment-work/ch02 --with-j "../J-第二章-知识-001"
```

后续替换 ch03／ch04／ch05。--with-j 只读候选目录、单元及节点，不导入数据；检查通过不表示 L 已批准候选代码。正式自审不加 --allow-empty，后者只供开工模板校验。

跨章引用新代码时可重复 --with-j：J 检查第三章可加 --with-j work/ch02；A 可同时引用 J 第二章和第三章交付目录。不需为候选前置单元等待 L 入库。

先修实际 JSON、题目、图片和代码再交包，附简短自审记录。无相应环境时注明未运行并给出明确缺项，不把准备好的命令写成已通过。

## 7. L 如何接收

L 查看每章覆盖表、自审和具体争议，确认目录／节点／单元，运行最终预览，先接知识再接题目与实验修订，再联调和发布。J/A 负责基础内容、完整答案、图片、编排建议与映射；L 不从头重录教材或逐题补答案。

chapter-plan 和综合应用题属于此次新增的离线资源规范，当前服务尚无对应直接导入／主观自动判分。L 后续接入单元和自评／教师评阅；现有客观题与实验修订沿用真实接口，不修改协议冒充已实现能力。

交付只压缩本章工作文件，不带空白的其他章、shared/、整本教材或未修改的全量实验快照。每章知识、题目和实验三类包分别审核，无适用实验就注明，不交空维护包。
