# OSLab `log2.txt` 视觉与交互设计

> 版本：2026-10-03
>
> 目标：把 OSLab 从“功能已经堆在页面上”整理成一套克制、清晰、有操作系统课程气质的学习工作区。本文是设计基线，不是实现记录；实现时以当前接口和数据契约为准。

## 1. 设计判断

当前页面的问题不是缺少颜色或卡片，而是三个层级没有被区分：

1. 图谱是课程结构、个人掌握状态和学习入口的混合视图。节点都像白色标签，关系线几乎同质，用户无法快速判断“这是依赖、包含、相关，还是实现”。
2. 节点工作台同时出现知识内容、关联题目、关联实验、交互模拟、关联资源和导师入口，入口名称重复，主线不清楚。
3. 题目练习仍然像一个带筛选表格的后台页面，不能让用户明确知道“我正在练哪个章节的哪个知识点、做了几道、错在哪里、下一步是什么”。

本轮设计的产品主线固定为：

```text
章节 → 知识点 → 学习内容 → 题目练习 / 编程实验 / 算法演示 → 学习证据 → 掌握状态
```

所有页面都服务于这条主线。任何不能帮助用户定位知识点、完成动作或理解反馈的元素都应删除。

## 2. OpenDesign 参考路线

### 2.1 参考选择

本设计使用 OpenDesign 的“诊断 → 参考路由 → 真实 token 分解”流程，不从记忆中拼接所谓“科技感”样式。

| 角色 | OpenDesign 参考 | 采用原因 | 不照搬的部分 |
|---|---|---|---|
| 主参考 | [Notion](https://opendesign.cc/packs/notion/DESIGN_SPEC.en.md) | 中性、克制、以工作区和信息组织为中心；适合知识图谱、学习记录和管理页面 | 不采用其品牌叙事、深色宣传背景或营销型大标题 |
| 阅读参考 | [Readwise Reader](https://opendesign.cc/packs/readwise/DESIGN_SPEC.en.md) | 内容阅读、复习和高亮反馈的层级清楚；适合节点内容和答题反馈 | 不采用衬线展示字体作为全站标题，中文界面保持统一无衬线 |
| 技术参考 | [Expo](https://opendesign.cc/packs/expo/DESIGN_SPEC.en.md) | 开发者工具的紧凑密度、代码标签和单一功能蓝 | 不采用过大的启动页留白，不把学习平台做成开发工具官网 |

OpenDesign 的真实 token 已读取：Notion 使用 `#FFFFFF`、`#F9F9F8`、`#F7F7F5`、`#1B1B1B`、`#37352F`、`#A39E98`、`#4B7BF5` 和低透明度黑色细线；Readwise 使用 `#478CD0` 作为唯一功能蓝；Expo 使用 `#FFFFFF`、`#F9F9FB`、`#1C2024`、`#60646C` 和 `#0090FF`。本项目保留 OSLab 已有的深蓝品牌线索，但把它限制在主操作、选中状态和关系路径上。

### 2.2 视觉定位

**OSLab = 操作系统课程的精密学习工作区。**

三个关键词：

- **理性**：白色和暖灰色画布、细边线、稳定的 4px 网格。
- **有证据**：蓝色只标识行动和选中；绿色、琥珀、红色只表达学习状态或结果。
- **有密度但不拥挤**：桌面端同时展示结构、内容和状态，移动端按顺序折叠，不使用装饰性渐变和悬浮光晕。

### 2.3 OpenDesign 反模式

以下内容禁止进入本轮页面：

- 紫色或蓝色渐变背景、渐变按钮、发光球体和玻璃拟态。
- 每个区块都套一层圆角卡片和阴影。
- 将所有图谱连线画成相同灰色箭头。
- 用“AI 导师”作为大标题或装饰性机器人插画；导师必须是有上下文的功能面板。
- 为同一个动作同时提供“关联实验”“编程实验”“进入实验”三个入口。
- 过多的彩色标签；彩色必须能解释状态、类型或关系。
- 用示例数字、示例学生姓名或固定图谱节点替代真实 API 数据。

### 3.2 字体与尺寸

```css
:root {
  --oslab-font-ui: -apple-system, BlinkMacSystemFont, "Segoe UI",
    "PingFang SC", "Microsoft YaHei", sans-serif;
  --oslab-font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
  --oslab-text-display: 32px;
  --oslab-text-page: 26px;
  --oslab-text-section: 18px;
  --oslab-text-body: 14px;
  --oslab-text-small: 12px;
  --oslab-leading-body: 1.55;
}
```

- 页面标题只在页面头部使用 26px，节点标题最多 28px；紧凑卡片不使用英雄级文字。
- 正文 14px，说明文字 12px；代码、ID、算法序列使用等宽字体。
- 中文不使用负字距；标题通过字重和上下间距建立层级。

### 3.3 间距、表面和动效

- 基础单位 4px；常用间距 `4/8/12/16/24/32/48`。
- 容器圆角 8px，输入和按钮圆角 6px，状态标签可用 999px；禁止超过 12px 的大圆角。
- 面板使用 1px `--oslab-line`，只有浮层使用极浅阴影；页面主体不依赖阴影分区。
- hover 只改变背景或边线；选中使用蓝色边线和浅蓝背景。
- 过渡 150–200ms，`cubic-bezier(0.645, 0.045, 0.355, 1)`；不使用弹跳动画。

## 4. 全局布局

### 4.1 顶栏

桌面顶栏固定高度 64px，白底、底部细线。左侧为 OSLab 标识和课程名，中间为一级导航，右侧为通知、头像和角色信息。

学生一级导航：

```text
首页 · 知识图谱 · 题目练习 · 实验中心 · 学习资源
```

学习记录不占一级导航，放入头像菜单；管理员使用教学管理工作区，不把学生侧的学习入口与管理入口混在同一组。

### 4.2 内容网格

- 画布最大宽度 1440px，左右内边距 24–32px。
- 12 列网格，列间距 24px。
- 1024px 以上使用多栏；768–1023px 将侧栏变成顶部横向条；小于 768px 单栏堆叠。
- 页面顶部先给出面包屑、页面标题和当前上下文，再出现筛选或操作；不能让筛选控件漂在标题上方。

### 4.3 操作层级

- 每个页面只允许一个主操作色按钮。
- 次要动作使用 outline 或 text button。
- 破坏性操作使用红色状态，不使用红色主按钮作为普通入口。
- 所有图标按钮必须有 tooltip 或 aria-label；熟悉的动作优先使用图标，不把“刷新/重置/返回”写成大号文字按钮。

## 5. 知识图谱页设计

参考图：`C:\Users\one\Downloads\参考布局\图谱界面.png`，但节点和关系按真实图谱数据重做。

### 5.1 页面结构

```text
┌ 顶栏 ─────────────────────────────────────────────────────┐
│ 面包屑 / 知识图谱                         当前章节         │
│ 页面标题 + 说明                                          │
│ [课程结构] [我的掌握]  搜索  章节  类型  状态              │
├───────────────┬──────────────────────────────┬────────────┤
│ 章节摘要        │ 图谱画布                     │ 知识点详情   │
│ 学习覆盖        │ 节点、关系、图例、缩放         │ 选中节点     │
│ 状态统计        │                              │ 关联节点     │
└───────────────┴──────────────────────────────┴────────────┘
```

图谱左侧可以保留章节摘要，但它不是“图谱探索”入口，不再重复导航。题目练习页不使用这条侧栏。

### 5.2 节点视觉

节点类别和个人掌握状态是两个正交维度：

| 课程类别 | 节点底色 | 说明 |
|---|---|---|
| 概念 | `#EAF0FD` | 课程结构中的概念节点 |
| 算法 | `#F6EDDF` | 算法、策略和方法节点 |
| 功能 | `#E9F1ED` | 系统功能、机制和模块节点 |
| 未标注 | `#F0F2F0` | 数据未提供类别时的兜底 |

个人状态使用节点左侧 6px 状态条和右上角小圆点表达，不覆盖整个节点底色：

- 已掌握：绿色；待巩固：琥珀；薄弱：红褐；未学习：灰。
- 选中节点：2px OSLab 蓝描边，背景不变。
- 诊断脉冲：只在 1.2 秒内显示蓝色或琥珀描边，不改变布局。
- 节点高度 40–48px，最长名称两行截断，hover tooltip 展示全名和章节。

ECharts 仍可使用 `layout: "force"`，但必须保留稳定初始位置和当前视野；如果引入按章节聚类，聚类只影响布局，不改变后端节点关系。不得用固定示例坐标或硬编码节点名。

### 5.3 连线视觉和语义

真实关系值为 `related`、`contain`、`dependent`、`implements`；历史数据还可能出现 `implemente`，前端显示映射必须兼容二者。

| 关系 | 视觉 | 文案 | 是否表示学习先后 |
|---|---|---|---|
| `dependent` | OSLab 蓝实线 + 实心箭头 | 依赖 / 前置知识 | 是；`A dependent→ B` 表示先学 B，再学 A |
| `contain` | 灰蓝细虚线 + 空心箭头 | 包含 / 所属 | 否 |
| `related` | 灰色点线 + 小圆端点 | 相关 | 否 |
| `implements` / `implemente` | 琥珀短划线 + 细箭头 | 实现 | 否，除非业务另有证据 |

规则：

1. 默认只显示线型和箭头，关系文字只在选中节点相邻边、hover 或“显示关系标签”开关打开时显示，避免 150 个节点的画布被文字淹没。
2. 选中节点时只强调相邻边；其他边降低透明度，不删除上下文。
3. 多条同向边使用 `autoCurveness` 或稳定的轻微曲率，避免重叠。
4. 不把所有有向边叫作“前置知识”；只有 `dependent` 可以进入学习路径算法。
5. 空类型、未知关系和历史拼写必须可见但不能导致渲染失败。

### 5.4 详情面板

详情面板必须包含：

- 节点名、章节、课程类别、个人掌握状态。
- 一段真实描述；无描述时显示明确空态。
- 概念理解、实践应用、可信度三项进度。
- “关联节点”分组：前置知识、后续知识、包含关系、相关关系、实现关系。
- 最近学习证据：题目作答、编程提交或模拟预测；显示结果和掌握度前后变化。
- 唯一主操作：`进入学习`。

删除详情中的“开始评测”和“进入实验”并列按钮。题目、实验和资源的深入入口在节点工作台中统一出现。

关联节点优先使用当前完整图谱 `nodes/links` 在前端按 `source/target` 过滤，保证关系类型和方向不丢失；如果工作台需要完整关联列表，再扩展 `NodeWorkbenchVO`，不新增重复的图谱查询接口。

## 6. 节点学习工作台设计

参考图：`C:\Users\one\Downloads\参考布局\工作台界面.png`。

### 6.1 页面结构

```text
┌ 节点标题 / 章节 / 状态 / 掌握度 ──────────────── [刷新] ┐
│ 一句话定义 + 当前推荐行动                              │
├───────────────────────────────────────┬───────────────┤
│ 主内容                                  │ 图谱导师        │
│ [知识内容] [题目练习] [实践]             │ 当前焦点        │
│                                         │ 对话与引用       │
└───────────────────────────────────────┴───────────────┘
```

右侧导师常驻，但宽度控制在 320–360px；小屏变成内容底部的折叠面板。

### 6.2 页签和命名

最终只保留三类职责：

1. **知识内容**：核心概念、常见误区、前置/后继/相关节点和阅读材料。这里不再出现“关联资源”这个二次命名；资源以“阅读材料”作为内容的一部分。
2. **题目练习**：本节点题目列表、按题型和状态分组、进入连续练习。这里不展示实验卡片。
3. **实践**：编程实验和适用的算法演示放在同一个实践区域，分别标记“编程实验”和“算法演示”。不再有名为“关联实验”的总入口，也不把全站的实验中心复制到节点页。

顶部只保留 `继续学习` 一个主操作；题目、实践和阅读材料从对应页签进入。学习记录通过时间线链接查看，不再作为节点工作台的第四种资源类型。

### 6.3 导师

导师面板必须显示当前节点名、当前学习焦点、回答来源和来源跳转。默认问题来自当前节点的薄弱状态，例如“解释核心概念”“根据最近学习记录给出下一步”。

导师回答必须区分：

- 有结构化来源的 GraphRAG 回答：显示节点、题目、实验或事件来源。
- 规则回退：明确标记为规则回答，不伪装成外部模型结论。

工作台已有 `tutorAsk({ nodeName, question })`，当前不接收 `questionId`、代码或提交 ID。第一版只把节点上下文作为正式能力；若实验导师要理解代码和判题结果，使用实验页专用上下文包装，不能把节点导师按钮改名为实验导师。

## 7. 题目练习设计

参考图：`C:\Users\one\Downloads\参考布局\题目练习.png`。

### 7.1 移除左侧导航

题目练习页不渲染 `CourseSidebar`。章节和知识点目录放入页面顶部的内容区，避免 200px 侧栏挤压题干和选项。

### 7.2 信息架构

```text
面包屑：操作系统 / 题目练习
页面头部：题目练习 + 当前题数 + 当前筛选上下文
章节条：全部章节 | 内存管理 | 进程管理 | ...
知识点条：当前章节下的知识点及题量/进度
筛选条：题型、难度、学习状态、题目搜索
练习区：单题大卡片 + 本组进度 + 上一题/下一题
```

没有固定左侧目录。桌面端可以在练习区右侧放一个 240px 的“本组题目”索引，移动端改为顶部抽屉；它是当前题队列，不是全站导航。

### 7.3 题目卡片

- 题干、题型、难度、章节和知识点标签在同一标题区。
- 选项使用整行点击区域，选中态有蓝色边框和浅蓝底色；填空输入高度不小于 44px。
- 提交后反馈紧跟在题目下方，按“结果 → 正确答案/解析 → 常见误区 → 掌握度变化 → 下一步”排序。
- `下一题`是主操作，`上一题`和`返回知识点`是次操作；反馈展开后不跳到抽屉。
- 不预发送答案、解析或标准答案；继续复习时从真实题目接口恢复状态。

### 7.4 目录数据原则

题目可以关联多个知识点，目录统计必须按 `questionId` 去重。图谱节点数不能作为题目数。章节或知识点为空的题目进入“未归类”分组，不能被静默隐藏。

当前列表接口可复用：`POST /api/learning/questions/list/page`，支持 `chapter/nodeName/type/difficulty/studyState/title/current/pageSize`；当前没有三级目录聚合接口，因此设计要求增加专用 catalog 查询，不能用当前页记录伪造计数。

## 8. 实验中心与编程实验页设计

参考图：`C:\Users\one\Downloads\参考布局\交互模拟界面.png`。

### 8.1 实验中心

实验中心只呈现章节目录、编程实验列表、节点筛选和实验进度。删除 `QuestionsView.vue` 中“学习资料”整块，不删除全站 `学习资源` 数据或资源页面。

左侧章节目录可保留，因为它是实验中心内部的章节筛选，不是顶层重复导航；页面内不再放第二个“交互模拟”卡片。交互模拟仍由顶栏/统一侧栏进入。

### 8.2 编程实验工作台

三列布局：

- 左：实验目标、题面、输入输出格式、样例和关联图谱。
- 中：代码编辑器、语言选择、草稿状态。
- 右：提交、判题状态、运行时间/内存、补救建议。

恢复“实验导师”页签或右侧折叠面板；删除“节点导师”和“学习资源”动作。失败后导师默认收到题名、题面摘要、当前语言、代码片段和最近一次判题状态，但第一版可以将这些内容拼成 `/api/chat/ask` 所需的文本请求，不能宣称后端已结构化校验实验上下文。

导师面板需要 pending、业务错误、重试、切题守卫和用户隔离。旧 `ChatWindow.vue` 是无上下文的通用聊天，不能原样嵌入。

### 8.3 交互模拟

参考图的层级可以保留：输入控制区 → 执行步骤矩阵 → 结果摘要 → 算法比较 → 预测练习。页面必须：

- 显示当前算法、页面引用序列/进程输入和物理块/时间片。
- 用真实 `steps/gantt/processStats/prediction` 渲染，不搬参考图数字。
- 运行后保存不可变 `runConfig`；输入改变后把旧结果标记为“需重新运行”，禁止用新参数提交旧结果的预测。
- `step.frames` 是 FIFO/LRU 队列顺序，不直接宣称是固定物理帧编号；若要显示物理帧行，前端先重建槽位或后端增加明确 `frameSlots` 字段。
- 只有 `prediction.eventId` 存在时才显示“已计入学习证据”。

## 10. 响应式与可访问性

- 1440px：图谱三栏、工作台主区加导师栏、题目主区加题号索引。
- 1024px：图谱详情下移，导师栏缩为 300px；实验工作台仍保持编辑器最小宽度。
- 768px：所有侧栏变成横向滚动条或抽屉；题目选项整行排列；图谱详情接在画布后。
- 480px：主按钮全宽，节点标题和题干允许换行，禁止横向溢出；表格改为卡片列表。
- 键盘可到达所有筛选、节点、题目选项和提交按钮；焦点使用 2px 蓝色轮廓。
- 图谱提供关系图例和节点文本替代说明；颜色不是唯一状态信号，必须同时有文字/形状/状态条。
