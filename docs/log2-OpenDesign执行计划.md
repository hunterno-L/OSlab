## 1. 总目标和范围

### 1.1 产品主线

全站围绕一条可完成的学习路径收敛：

```text
章节 -> 知识点 -> 知识内容 -> 题目练习 / 编程实验 / 算法演示 -> 学习证据 -> 掌握状态
```

完成本计划后，用户应能从图谱选中一个知识点，看到相关节点和掌握原因，进入学习工作台，完成题目或实验，获得反馈，再返回图谱看到状态更新。教师账号应能在教师看板中看到班级薄弱点，但不应看到学生端的伪造数据或不存在的筛选能力。

### 1.2 本轮必须解决的问题

- 图谱节点、关系线和掌握状态要一眼可区分，选中节点后能够看到相关节点分组。
- 节点工作台删除重复入口，统一“知识内容、题目练习、实践”三个主区域。
- 题目练习去掉左侧课程侧栏，改为章节 -> 知识点 -> 题目列表和连续答题流。
- 实验中心删除学习资料区，保留编程实验和交互模拟两个清晰入口。
- 编程实验页恢复“实验导师”，移除“节点导师”和下方重复的学习资源入口。
- 交互模拟必须显示真实运行配置和真实运行结果，不能让修改后的输入与旧结果混在一起。
- 教师看板只使用当前已存在的只读接口，不虚构日期、排名、任务或备注功能。
- 全站沿用 OpenDesign 参考得到的中性工作区、细线、克制蓝色和明确状态色，不再增加渐变、发光、装饰性大卡片。

### 1.3 明确不做

- 不为每个知识点制作独立静态讲义页面。知识内容使用现有节点工作台和可复用内容区。
- 不新增没有后端契约支撑的“智能推荐”“自动生成讲义”或班级统计。
- 不把图谱节点数当成题目数，也不把演示用数字写死在界面。
- 不复制布局图中的示例题目、百分比、日期和实验结果。
- 不把 `dependent`、`contain`、`related`、`implements` 混成同一种关系。
- 不把 `implemente` 旧数据直接删除或静默迁移；显示层要兼容它。

## 2. 给所有 agent 的执行规则

1. 直接在当前工作区执行，保留已有未提交改动。不要 reset、checkout、清空工作区或重建项目。
2. 只修改当前阶段涉及的文件；需要扩大范围时先在交付说明中列出原因。
3. 前端手工编辑使用 `apply_patch`。不生成临时假接口、不在组件内写演示数据、不把未知参数发送给后端。
4. 所有 ID 按字符串处理，尤其是 `questionId`、`runId`、`submissionKey` 和图谱节点 ID。
5. `log2.txt` 要求的旧入口名称必须通过 `rg` 检查清理，但不要用全局替换破坏后端字段或历史兼容逻辑。
6. 新增 API 前先检查 `learning.ts` 和后端 controller/service。已有接口能满足时，优先复用已有接口。
7. 不使用浏览器自动化作为验收手段。功能验证使用接口、构建、单元测试和人工截图检查。
8. 每个阶段结束时都要留下：修改文件、接口变化、验证命令和仍存在的限制。

## 4. 阶段 1：OpenDesign 视觉基础和全局壳层

### 目标

先统一视觉基础，再做页面重排。所有页面都应像同一套教学工作区，而不是各自拼装的卡片。

### 修改范围

- `前端代码/osLab-frontend/src/styles/learning-theme.css`
- `前端代码/osLab-frontend/src/components/GlobalHeader.vue`
- `前端代码/osLab-frontend/src/components/LearningLayout.vue`
- `前端代码/osLab-frontend/src/components/CourseSidebar.vue`
- 必要时新增 `src/components/learning/` 下的共享按钮、状态标签、分区标题和空状态组件
- `src/config/appNavigation.ts` 仅在现有导航层级确实与页面路由不一致时修改

### 设计要求

以 `log2-OpenDesign视觉与交互设计.md` 的 token 为唯一基线：

- 页面背景使用接近 `#F7F7F5` 的暖白灰，内容面板使用 `#FFFFFF`。
- 正文使用近黑色，次要信息使用灰色，边界使用低对比度细线。
- 主蓝只用于当前导航、主按钮、选中节点、学习路径和链接，不用蓝色填满每张卡片。
- 掌握、待巩固、薄弱、未学习分别使用稳定的绿、琥珀、红、灰；状态色不能同时承担关系类型含义。
- 圆角控制在 4px/8px/12px，去除浮夸阴影、渐变背景和大面积装饰。
- 桌面端使用左侧课程导航 + 内容区；题目练习页面按阶段 5 的规则关闭左侧课程导航。
- 顶部导航只保留实际存在的路由，当前路由必须有清晰的下划线或侧边指示。

### 实现要点

1. 把颜色、间距、边框、圆角、层级和状态色收敛成 CSS 变量，页面组件只引用变量。
2. 统一按钮层级：一个主操作、一个次操作、一个危险操作，避免同一行出现多个视觉上同等重要的蓝色按钮。
3. 统一标题层级：页面标题、区块标题、字段标题和辅助说明各只有一种表现。
4. 统一加载、空数据、错误和无权限状态，不使用空白区域掩盖请求失败。
5. 让 `CourseSidebar` 支持显式隐藏，而不是通过 CSS 偶然压缩。题目练习路由必须使用显式配置。

### 验收

- 知识图谱、节点工作台、题目练习、实验中心、教师看板在同一浏览器窗口中视觉一致。
- 侧栏隐藏后主内容能自动占满空间，不能留下空白列。
- 所有按钮有明确的成功、失败或跳转行为，没有只改变颜色的假按钮。
- 前端 lint/build 通过；无新增 TypeScript 类型错误。

### 反模式

- 不在每个页面单独定义一套蓝色、灰色和卡片阴影。
- 不用大号渐变标题、发光节点、毛玻璃或营销型 hero。
- 不为了“高级感”降低正文对比度或把操作文字改成只有图标。

### 交给 agent 的提示词

```text
请先阅读 docs/log2-OpenDesign视觉与交互设计.md 和 docs/log2-OpenDesign执行计划.md 的阶段 1。基于现有 Vue 组件统一 OpenDesign 风格 token、全局导航、内容面板、按钮、状态标签、加载/空态/错误态，并让 LearningLayout/CourseSidebar 支持题目练习显式隐藏侧栏。保持现有路由和接口，不写演示数据；完成后运行前端 lint/build，报告修改文件、截图检查结果和未解决问题。
```

## 5. 阶段 2：知识图谱重做

### 目标

让图谱成为“课程结构 + 个人掌握状态 + 下一步入口”，而不是一张拥挤的节点关系图。

### 修改范围

- `前端代码/osLab-frontend/src/components/KnowledgeGraph.vue`
- `前端代码/osLab-frontend/src/views/knowledgeGraph/KnowledgeGraphView.vue`
- `前端代码/osLab-frontend/src/api/learning.ts` 仅在现有类型缺字段时补充类型
- 后端只有在真实 VO 无法提供图谱状态时才扩展接口

### 数据和关系规则

1. 全量图谱以 `GET /api/knowledge_graph/getAll` 为结构来源；个人掌握状态使用当前个人图谱接口或已有 `NodeWorkbenchVO` 数据。
2. 章节过滤在客户端基于真实 `chapter` 字段执行，不能按显示名称猜测。
3. `dependent` 表示学习先后：A 依赖 B，应从 B 指向 A，B 是 A 的前置知识。
4. `contain` 只表示结构包含，不等同于学习前置关系。
5. `related` 只表示相关，不产生学习顺序。
6. `implements` 和历史 `implemente` 都显示为“实现”，不能删除旧值。
7. 节点颜色由“节点类别”和“个人掌握状态”两层表达：类别使用稳定色相，掌握状态使用边框、角标或外环，不能用同一颜色同时表达两种语义。

### 图谱画布

1. 默认布局使用稳定的章节分组或层级布局；力导向只作为节点很多时的退化方案。
2. 节点采用轻量矩形或胶囊形，显示短名称和状态点，避免当前白色标签全部同质化。
3. 边默认低对比度；选中节点时仅高亮相邻边，边标签在 hover/选中时显示。
4. 前置路径使用主蓝，包含关系使用中性线，相关关系使用点线，实现关系使用琥珀虚线或小标签。
5. 处理孤立节点、缺失目标节点、重复边和旧关系值，不能让 ECharts 抛异常或绘制悬空文字。
6. 保留缩放、拖拽、定位和重置，但所有控件都要有可见反馈。

### 右侧知识点详情

选中节点后按以下顺序展示：

1. 节点名称、章节、类别和掌握状态。
2. 一句话概念说明；没有内容时显示明确空态。
3. 掌握状态的证据：近期题目、实验、最近一次失败或暂无证据。
4. 相关节点分为“前置知识”“后续知识”“相关节点”和“实践入口”，实践入口下再按真实数据标记“编程实验”或“算法演示”。
5. 只保留一个主按钮“进入学习”，次按钮按数据存在性显示“做题”或“进入实验”。
6. 管理员维护操作放在折叠的管理区，不与学生学习 CTA 混排。

### 验收

- 图谱能显示当前真实节点和关系，不能出现全白矩形和无法区分的灰线。
- 选中节点时只突出相邻节点和关系，取消选择后恢复全局层级。
- 至少验证四种关系显示和方向；历史 `implemente` 数据仍可读。
- 右侧详情能列出相关节点，点击相关节点会更新详情而不是跳到错误页面。
- 章节过滤、搜索、重置和刷新都能触发真实状态变化。
- 图谱空数据、接口失败和无权限状态有明确提示。

### 反模式

- 不用固定节点坐标把布局锁死成一张静态海报。
- 不把所有边都画成相同灰色实线。
- 不把掌握比例写死；不得把图谱节点数量当成题目数量。
- 不新增“查看讲义”这类要求每个节点维护静态页面的入口。

### 交给 agent 的提示词

```text
请按阶段 2 重做 KnowledgeGraph.vue 和 KnowledgeGraphView.vue。结构必须来自 GET /api/knowledge_graph/getAll，掌握状态复用现有个人图谱/NodeWorkbenchVO 数据；正确区分 dependent、contain、related、implements，并兼容历史 implemente。实现类别色 + 掌握状态边框/角标、相邻关系高亮、右侧相关节点分组和唯一主 CTA“进入学习”。不要写死节点、关系、题目数量或布局图示例数据；完成后用真实接口和失败/空数据状态验收。
```

## 6. 阶段 3：节点学习工作台收敛

### 目标

把节点页面变成一个可完成任务的工作台，消除“关联实验/关联资源/学习资源”等重复入口。

### 修改范围

- `前端代码/osLab-frontend/src/views/learning/NodeLearningWorkspaceView.vue`
- `前端代码/osLab-frontend/src/components/learning/NodeWorkbenchDrawer.vue`（若存在并被使用）
- 对应 composable 或 `src/api/learning.ts` 类型

### 页面结构

顶部只保留：返回路径、节点名称、章节、掌握状态、一个收藏或记录动作。

主导航只保留三个标签：

1. `知识内容`：概念、核心原理、示例、常见误区和前置/后续关系。
2. `题目练习`：按知识点过滤的题目列表和连续答题入口。
3. `实践`：编程实验、交互模拟或其他真实实践入口，按数据是否存在显示。

右侧或下方的证据区展示掌握度、近期错误、相关节点和下一步建议。不要再并列展示 `关联题目`、`关联实验`、`关联资源` 三个同级卡片，也不要重复出现两个导师入口。

### 交互要求

1. 从图谱进入时保留 `nodeName` 或节点 ID，返回图谱后保留章节和选中节点。
2. “题目练习”跳转到题目页时携带真实过滤参数，不在前端复制一份题目数据。
3. “实践”根据 `experiments` 和 `simulationEntry` 显示编程实验或交互模拟；两者都不存在时显示空态和前置知识链接。
4. tutor 入口必须说明上下文来源，链接回本节点和相关证据；不要把普通文本聊天伪装成已有 GraphRAG 能力。
5. 切换节点时取消或忽略旧请求，避免上一个节点的内容留在当前详情中。
6. 需要保留已有本地缓存时，缓存键必须包含用户、节点和数据版本。

### 验收

- 页面没有重复的“关联实验/关联资源”标签和重复的资源入口。
- 节点内容、题目练习、实践三块均能到达真实目标页面。
- 无题目、无实验、无内容和接口失败时都有明确空态。
- 切换节点、刷新页面、返回图谱和换用户后数据不串页。
- 右侧推荐只显示真实存在的行动，不显示无法点击的推荐文案。

### 反模式

- 不为每个节点复制一份独立静态页面。
- 不保留一排视觉上同等重要的蓝色按钮。
- 不把“相关”关系描述成“必须先学”，只有 `dependent` 才是学习前置关系。

### 交给 agent 的提示词

```text
请按阶段 3 收敛 NodeLearningWorkspaceView。将页面重组为“知识内容 / 题目练习 / 实践”三个主标签，清理重复的关联题目、关联实验、关联资源和多个导师入口；复用现有 questions、experiments、simulationEntry、prerequisites、successors、mastery 数据。跳转必须带真实 nodeName/节点 ID，切换节点要处理旧请求和空态，不新增静态讲义页面。完成后逐个点击三个真实入口并记录接口与截图结果。
```

## 7. 阶段 4：题目练习改为章节和知识点学习流

### 目标

删除题目练习左侧课程侧栏，让用户先选章节，再选知识点，再进入连续答题。题目练习要像学习流程，不像后台题目表。

### 修改范围

- `前端代码/osLab-frontend/src/views/learning/LearningQuestionsView.vue`
- `前端代码/osLab-frontend/src/views/learning/AssessmentRunView.vue`
- `前端代码/osLab-frontend/src/components/learning/QuestionAnswerCard.vue`
- `前端代码/osLab-frontend/src/components/learning/AssessmentNavigator.vue`
- `LearningLayout.vue`/`CourseSidebar.vue` 的显式隐藏配置
- `前端代码/osLab-frontend/src/api/learning.ts`
- 后端题目聚合接口，仅在现有列表接口无法提供章节/知识点目录时新增

### 目录区

1. 页面顶部显示面包屑、当前章节和整体学习进度。
2. 使用横向章节选择条或紧凑章节菜单，显示章节名称和真实题目进度。
3. 当前章节下按知识点分组；每个知识点显示题目数、完成数、待复习数和掌握状态。
4. 知识点分组展开后显示题目列表，列表项显示题型、难度、状态和最近一次作答。
5. 多个节点关联同一道题时按 `questionId` 去重；不要直接使用 `personalGraph.chapters[].count`，它是图谱节点数。
6. 如果现有接口不能提供准确的章节 -> 知识点题目聚合，新增明确的后端 DTO/API，并在 `learning.ts` 添加对应类型；不要用前端猜测或图谱节点数代替。

### 答题区

1. 选中题目后使用全宽答题卡，显示题干、题型、选项/输入、提交、清空和查看反馈。
2. 支持现有答案格式：
   - `JUDGE`: `"true"` 或 `"false"`
   - `SINGLE`: `"A"` 等单个选项值
   - `MULTIPLE`: `['A', 'C']` 等数组
   - `FILL_BLANK`: 字符串
3. 提交后显示对错、解析、关联知识点和下一步建议；未提交前不能泄露答案。
4. 保留上一题、下一题、题目列表和退出练习；离开时提示未完成状态。
5. 单题练习可以调用现有 `answerLearningQuestion`，不强行创建测评 run。
6. 连续测评使用现有 `startAssessment`、`getAssessmentRun`、`finishAssessment`。当前 start 接口只支持 `chapter/nodeName/type/difficulty/studyState/count`，不得传入不存在的 `questionIds` 或 `startQuestionId`。
7. 如果产品确实需要“指定题目队列”，必须由后端增加经过校验的 `questionIds` 模式，服务端重新检查题目归属、权限和重复项；没有后端实现前不做客户端假队列。
8. 所有 run、question 和 submission 标识按字符串传输，答案提交包含真实 `assessmentRunId`/`submissionKey`（若接口返回）。

### 验收

- 题目练习页面没有左侧课程侧栏，主内容不会因隐藏侧栏留下空白。
- 能完成章节选择、知识点展开、题目选择、单题提交和连续测评。
- 四种答案格式都能提交并收到正确反馈。
- 刷新或返回后未完成测评不会悄悄变成已完成；完成后调用 finish 并更新进度。
- 多节点题目不重复计数；空章节、无题目、接口失败都有明确提示。
- 不出现不存在的筛选项、未知请求参数或只在前端存在的题目。

### 反模式

- 不恢复左侧课程导航。
- 不把所有题目继续塞进一张后台表格作为唯一入口。
- 不用布局图里的固定百分比或题目数量。
- 不把题型名称、题目内容或答案写死在组件中。

### 交给 agent 的提示词

```text
请按阶段 4 重做题目练习流：关闭 LearningQuestionsView 的左侧课程侧栏，改成“章节 -> 知识点 -> 题目 -> 全宽答题卡”的结构。复用 LearningQuestionQueryRequest、listLearningQuestions、answerLearningQuestion 和现有 assessment API；严格使用 JUDGE/SINGLE/MULTIPLE/FILL_BLANK 的真实答案格式，不传未知 start 参数，不把图谱节点数当题目数。若需要精确目录统计，先实现真实后端 DTO/API 再接前端。完成后覆盖单题、连续测评、未完成退出、四种题型和空态验收。
```

## 8. 阶段 5：实验中心和实验导师

### 目标

让实验中心只承担“编程实验”和“交互模拟”，并恢复编程实验页的实验导师。实验导师是针对当前实验和提交记录的辅助入口，不是重复的节点知识入口。

### 5.1 实验中心目录

修改：`前端代码/osLab-frontend/src/views/question/QuestionsView.vue`。

1. 删除首个 `.resource-section` 的“学习资料”卡片及其关联 import、状态、计算属性和 CSS。
2. 保留章节导航、编程实验列表和交互模拟入口。
3. 如果导航文字仍然重复，统一使用“编程实验”和“交互模拟”，不要同时出现“关联实验”和“编程实验”。
4. 所有实验卡片必须有真实路由和加载/空态；没有数据时不要渲染不可点击的卡片。

### 5.2 编程实验页

修改：`前端代码/osLab-frontend/src/views/question/ViewQuestionView.vue` 和必要的 `ChatWindow.vue`。

1. 移除“关联学习”区域中的 `节点导师`、`学习资源`，保留题目练习或真实相关入口。
2. 将失败提交后的“咨询节点导师”替换为带实验上下文的“实验导师”入口；不能只改按钮文字而继续调用节点导师逻辑。
3. 实验导师上下文至少包含：题目标题/ID、当前语言、代码、最近一次提交状态和编译/运行错误文本。
4. 当前 `/api/chat/ask` 是接收单个字符串并返回字符串的旧接口。最小实现可以由前端把上下文组装成一条清晰请求，再显示消息历史、等待态、错误态和重试；不得宣称这是结构化 GraphRAG。
5. 若要实现结构化导师，必须同时定义前后端请求 DTO、响应 DTO、权限检查和上下文截断规则，不能只在前端追加字段。
6. 发送前校验代码和题目上下文，避免路由切换后仍显示旧题目的回复。

### 5.3 交互模拟

修改：`前端代码/osLab-frontend/src/views/learning/SimulationView.vue`。

1. 页面按参考布局分成配置区、步骤矩阵、结果摘要、对比区和微练习区。
2. 页面支持页面置换 `FIFO/LRU/OPT` 和 CPU 调度 `FCFS/SJF/RR` 的现有接口，不复制布局图示例数字。
3. 点击运行时保存不可变的 `runConfig`，结果、动画、预测和对比均绑定这份配置；输入框修改后必须标记为“配置已修改，需重新运行”，不能继续把新输入发给旧结果。
4. 页面置换返回的 `step.frames` 是 FIFO/LRU 队列顺序，不是固定物理帧槽位。若要画物理帧表，要先在前端重建槽位，或由后端明确提供 `frameSlots`；不得把队列数组直接当固定行。
5. 只有返回的 `prediction.eventId` 才能写入学习证据；没有 eventId 时只显示演示结果，不更新掌握度。
6. 动画暂停、继续、逐步、重置和对比按钮必须真实改变状态；运行错误和输入非法要显示在配置区附近。

### 验收

- 实验中心不再有“学习资料”卡片。
- 编程实验失败后可以打开实验导师，消息包含当前题目和提交上下文，网络失败可重试。
- 交互模拟四种算法/三种 CPU 算法都使用真实接口，配置和结果不会串。
- 页面置换步骤、缺页数、命中率、淘汰页与接口返回一致。
- 无 eventId 时不会伪造学习证据。

### 反模式

- 不把实验导师重新命名为节点导师。
- 不在前端假造结构化 GraphRAG 证据。
- 不用示例图中的固定 LRU 数字覆盖后端结果。
- 不把动画状态和输入框当前值混用。

### 交给 agent 的提示词

```text
请按阶段 5 清理实验中心：删除 QuestionsView 的学习资料区，保留编程实验和交互模拟；在 ViewQuestionView 恢复实验导师，替换节点导师/学习资源入口，并把题目、语言、代码、最近一次提交结果传入现有聊天接口。同步重构 SimulationView 的配置区、步骤矩阵和结果区，运行时冻结 runConfig，按真实接口解释 frames 和 prediction.eventId。不要伪造 GraphRAG 或复制参考图数字；覆盖实验失败、聊天失败重试、FIFO/LRU/OPT、FCFS/SJF/RR 和重新运行验收。
```

## 12. OpenDesign 质量闸门

最终合并前按 OpenDesign 参考协议检查：

1. **参考一致性**：能看出 Notion 的工作区层级、Readwise 的阅读反馈和 Expo 的开发工具密度，但没有照搬品牌页面。
2. **信息层级**：每个页面只有一个主要动作；标题、状态、正文和辅助信息顺序稳定。
3. **视觉工艺**：使用一个网格体系、最多三到四个功能色、统一边框/圆角/间距，不靠阴影和渐变制造层次。
4. **功能完成度**：所有可见按钮都有真实动作、加载态、失败态和结果反馈。
5. **原创性**：视觉语言服务操作系统课程的图谱、实验和学习证据，不是通用 SaaS 仪表盘换标题。

如果任一页面无法通过以上五项，优先回到阶段 1 的 token 和布局层修正，不在局部追加装饰。
