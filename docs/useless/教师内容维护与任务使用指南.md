# 教师内容维护与任务使用指南

更新：2026-10-21

本指南对应本轮实现的教师端内容管理与“学习任务”闭环。教师端继续使用管理员账号；学生使用已有学生账号。

## 1. 入口

- 学生顶栏“学习任务” → `/tasks`
- 管理员顶栏“学习任务” → `/teaching/tasks`
- 教学管理侧栏：课程内容管理、学习任务、班级分析、知识维护、测评管理、实验管理、用户管理
- 原有独立入口保留：题目练习 `/assessments`、实验中心 `/experiments`、算法模拟 `/experiments/simulation`

学生首页显示待接收、进行中、待批阅、已批阅数量，均来自 `/learning/tasks/summary`。

## 2. 教师维护内容

### 2.1 题目

入口：教学管理 → 测评管理。

- 新建/编辑支持：标题、题型（判断/单选/多选/填空）、题干、选项、答案、解析、常见误区、章节、所属小节代码、难度、知识节点。
- 保存只产生草稿；提交审核 → 审核通过 → 发布后学生可见。已发布题目的编辑走修订流程，不会直接覆盖已发布版本。
- 知识节点可选；不选不产生掌握证据。题目练习与任务副本的去重身份由题干/选项/答案/节点内容指纹生成。

### 2.2 编程实验

入口：教学管理 → 实验管理 → 新建实验/修改。

- 新建：填写标题、实验说明、初始代码、参考解、标签、知识节点、判题限制、测试用例；点击“创建草稿”。
- 草稿状态：可继续“保存草稿”；确认无误后“发布实验”。发布前不会出现在学生实验列表。
- 已发布实验编辑：
  - “保存改稿”只生成待应用修订，学生继续看到当前发布版本；
  - “保存并应用”立即把修订写回原实验；
  - 若有待应用修订，页面顶部提供“应用修订”按钮。
- 始终保留原 `questionId`、历史提交与映射；不会因改稿创建新的实验 ID。
- 自动判题实验必须至少一条测试用例；没有测试用例时请改用人工评阅，系统不会伪造“通过”。

### 2.3 知识节点与关系

入口：教学管理 → 课程内容管理 → “知识节点与关系”标签。

- 选择节点后读取基础信息、出向关系与入向关系。
- 出向关系可新增/删除/修改：目标节点、关系类型、理由。
- 保存只替换本节点出向关系，不删除其他节点指向本节点的入向关系。
- `REQUIRES` 前置关系会检查环；其他关系不做全图无环限制。
- 保存后 MySQL 立即生效，图谱同步状态显示为 `PENDING`；可在“资源审核”或图谱同步区块查看/重试。同步未完成时不宣称 Neo4j 已展示。

### 2.4 学习单元

入口：教学管理 → 课程内容管理 → “目录与单元编排”标签。

- “读取草稿”或“新建单元”后，使用表单编辑：单元代码、标题、课程、小节、排序、预计分钟、学习目标、教学节点映射、活动列表与完成规则。
- 活动可配置引用类型（教学块/题目/资源）、稳定代码、必做与完成规则。
- “保存单元草稿”不改变已发布版本；“提交审核 → 审核通过 → 发布单元”后学生才使用新版本。
- 高级 JSON 折叠区保留完整定义，便于精确维护未暴露字段。

## 3. 教师布置学习任务

入口：教学管理 → 学习任务 → 新建任务。

### 3.1 基本信息

- 标题、说明、截止时间、是否允许逾期、可选关联课程/单元。
- 关联单元只用于筛选和返回上下文，不自动改写单元活动或登记完成。

### 3.2 内容块

点击“添加文字/资料/题目/实验”，可排序、设为必做、设置分值。

- 文字：Markdown 正文；可选要求文字答复、上传文件、阅读确认。没有答复要求时，正式提交即视为完成。
- 资料：先保存草稿，再上传教师资料文件；可要求阅读确认或提交作业文件。
- 题目：可“自行编写”或“从资源库选择”共享已发布题目；选择后可继续修改，只影响任务草稿，不改资源库原件。
- 实验：可自行编写或复用共享实验。自动判题需用例、限制与语言；人工评阅需填写报告要求。

分值与计分：只有开启“计分”并填写分值的块计入总分；未开启只计完成进度，不显示 0 分。

### 3.3 发布对象

- 按班级多选、按具体学生多选；两者可组合。
- “预览接收人数”显示去重后的有效人数与排除原因（未绑定账号、账号删除/封禁、不在名册）。
- 有效人数为 0 时不能发布。
- 发布后新入班学生不会自动接收；使用“追加接收学生”显式加入。

### 3.4 预览与发布

- “学生视角预览”只显示真实题干、资料、分值和提交要求；不显示标准答案、解析与隐藏用例。
- 点击“发布任务”后生成：
  - 每个自动题目/代码实验的私有执行副本；
  - 完整发布快照（含答案/用例，仅服务端与教师可见）；
  - 去重后的接收人名单。
- 重复点击发布不会产生第二份任务或副本。

### 3.5 发布后

- “设置”：延长截止时间、调整逾期开关、追加说明；题干/分值/必做规则不可改。
- “追加接收学生”：只新增，不重复；已提交记录不受影响。
- “关闭”：停止新接收与提交，保留查看、下载、批阅。
- “复制”：从当前定义/发布快照生成新草稿，不复制学生答案。
- “归档”：从任务列表移入归档视图。
- 只有草稿可以删除。

## 4. 教师批阅

入口：任务列表 → 批阅，或任务编辑页“查看批阅”。

- 接收人列表显示状态、轮次、提交时间、逾期、自动得分、总分。
- “查看提交”展示学生文字、文件、题目作答与代码判题结果。
- 每个需要人工评阅的块输入 0..maxScore 分数与评语；全部人工项填写后“提交批阅”，服务端重算总分。
- 纯自动任务提交后自动进入“已批阅”；含人工项时为“待批阅”。
- “退回修改”必须填写原因；若任务已超期且禁止逾期，必须同时提供新的截止时间。退回后学生进入下一轮，历史提交保留。
- 其他管理员不能查看或批改非本人创建的任务。

## 5. 学生学习流程

1. 学习任务列表按待接收/进行中/待批阅/已批阅查看；逾期显示标记。
2. 打开任务详情，阅读说明与资料；点击“接收任务”后才可保存与提交。阅读详情不等于接收。
3. 内容按教师顺序展示：
   - 文字与资料直接阅读；需要确认时勾选。
   - 客观题选择/填写答案，点击“检查答案”获取本次正误与解析；只保存草稿不进入正式提交。
   - 自动实验选择语言、编辑代码、提交判题；页面轮询到终态后显示结果。
   - 人工实验填写说明/上传报告。
4. “保存进度”可随时保存草稿；刷新后恢复。
5. “提交任务”前服务端检查必做项、文件归属与判题终态；未完成项会明确列出。
6. 提交后查看历史提交、自动得分、教师评语与退回原因。被退回后可修改并重新提交，新一轮不覆盖旧答案/文件。

## 6. 文件规则

- 单文件 ≤ 10 MiB；支持 doc/docx/pdf/txt/md/png/jpg/jpeg/webp；每块最多 5 个。
- 教师资料上传仅限任务草稿；任务发布后内容冻结。
- 学生文件仅本人与任务创建者可见；正式提交引用后不可删除。
- 下载保留原文件名并设置 `nosniff`；文件保存在服务器私有目录，不通过静态 URL 公开。

## 7. 配置与部署

```yaml
spring.servlet.multipart.max-file-size: 10MB
spring.servlet.multipart.max-request-size: 12MB
oslab.tasks.storage-dir: ${OSLAB_TASK_STORAGE_DIR:./data/task-files}
```

- 容器部署需将附件目录挂载持久卷。
- 新库初始化顺序包含 `oslab_upgrade_v8_teaching_tasks.sql`；存量库请单独应用 v8 迁移。
- 自动代码判题依赖 `codesandbox.remote.url` 可用；沙箱未配置时提交返回系统错误，任务不会被标记通过（可改用人工评阅实验）。

## 8. 验证与清理

验证使用独立班级与账号，未向真实班级发布测试任务。验证完成后已删除测试账号、任务、执行副本、附件、测试实验与测试单元草稿；如需复现，请使用任一 ADMIN 账号与独立测试班级重新创建。
