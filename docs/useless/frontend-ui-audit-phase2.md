# OSLab 第二阶段前端 UI 审计与更新分组

> 审计日期：2026-09-30。本文是只读审计，不修改代码。它服务于“知识图谱智能学习闭环方案”的第二阶段执行计划，重点把已经存在的功能统一到最终教学产品 UI，并明确管理员与学生两种视角。

## 1. 先纠正截图语境

用户提供的截图来自 `localhost:8081`，右上角显示“张小明 / 管理员·操作系统”，因此它是管理员视角，不是学生新账号视角。

截图中“暂无学习证据”以及左栏“已掌握 0、待巩固 0、薄弱 0、未学习 127”只能说明当前管理员账号没有可展示的个人学习事件，不能据此判断页面登录角色、后端掌握度逻辑或学生体验。管理员页面必须同时做到：

- 保留管理员的图谱编辑能力，但不把删除节点、新建节点、添加关系、执行 Cypher 混在普通学生学习 CTA 中；
- 明确管理员当前查看的是“课程结构/演示数据”还是“管理员个人学习状态”；
- 允许管理员切换到“课程全图、节点资源、班级热力/教师看板”等管理入口；
- 学生视角再显示个人掌握、证据、推荐、错题和学习路径，不把管理员个人的空掌握状态当成系统缺陷。

## 2. 方案要求与已存在能力

方案 `知识图谱智能学习闭环方案.md` 的关键 UI 需求：

- 核心闭环：普通题或实验提交 → 判题 → 知识点归因 → 个人图谱更新 → 薄弱路径高亮 → 推荐解释/练习/模拟器 → 再次验证（方案第 13-36 行）。
- 通用节点工作台，不为每个节点制作静态讲义；页面应动态组织概念卡、前后置关系、掌握度与可信度、错误、普通题、实验、路径、导师、模拟器入口（第 101-119 行）。
- 普通题支持判断、单选、多选、填空，从知识点或章节进入同一套练习，服务端判分并记录首次作答/解析/纠错证据（第 121-138 行）。
- GraphRAG 导师应引用当前节点、关系、题目、实验、历史提交和审核素材，并展示来源（第 140-157 行）。
- 模拟器首批为 FIFO/LRU 页面置换，并支持 CPU 调度扩展和预测题（第 159-178 行）。
- 动态学习路径和成长时间轴是 P1；教师班级薄弱点图谱是 P1（第 180-221 行）。
- P0/P1 完整清单在第 223-251 行。

目前前端已经有下列底座，但主要是“功能原型 + 页面拼接”，尚未完成统一产品化 UI：

- 普通题练习：`src/views/learning/LearningQuestionsView.vue`，筛选、分页、四题型答题卡、服务端作答。
- 节点工作台：`src/components/learning/NodeWorkbenchDrawer.vue`，掌握度、前置节点、推荐、普通题、事件时间线、导师问答。
- 模拟器：`src/views/learning/SimulationView.vue`，CPU FCFS/SJF/RR、页面 FIFO/LRU、结果表格、预测练习。
- 管理题库：`src/views/learning/ManageLearningQuestionsView.vue`，我的题目/审核队列、草稿到发布、题目编辑与详情。
- 教师看板：`src/views/learning/TeacherDashboardView.vue`，班级概览、薄弱 Top、节点热力、普通题正确率、成长时间轴、事件表。
- API 合约：`src/api/learning.ts:48-111,245-258,280-402`。

## 3. 管理员截图对应的真实问题

### 3.1 图谱节点数量与布局

证据：`src/views/knowledgeGraph/KnowledgeGraphView.vue:450-474,489-530,806-844`。

- `viewMode` 默认是 `mine`，管理员打开首页也会直接看到个人掌握的 curated 子图，不是课程全图。
- `canvasNodes` 在 mine 模式直接使用 `curated.value.nodes`，所以截图显示 6 个左右节点是前端主动裁剪，不一定是 Neo4j 只有 6 个节点。
- `CHAPTER_HUBS = ["内存管理","进程","文件系统"]` 是前端硬编码；章节成员通过关系深度推导，不是后端真实章节字段。
- `chapterFilter` 的选项来自 `categories`，但过滤条件使用 `n.category === chapterFilter`；这把“章节筛选”和“节点类别筛选”混在一起，页面选项文案与实际语义不一致。
- curated 位置在同文件约 `655-803` 以固定像素坐标绘制，当前结构容易导致节点集中在左下、中央留白很大；这与截图一致。

更新方向：管理员默认进入 `课程全图` 或管理员专用“课程结构”模式；学生默认进入 `我的掌握`。全图和个人图谱必须共用同一节点快照，只改变状态叠加、筛选和布局，不依赖前端硬编码章节成员。

### 3.2 管理员能力与学生 CTA 混排

证据：`KnowledgeGraphView.vue:196-332`、`KnowledgeGraphView.vue:1221-1235`。

- 右侧卡片同时承载知识详情、学生学习按钮和管理员的“删除此节点/新建节点/添加关系/执行 Cypher”。虽然这些按钮有 `isAdmin` 条件，但信息层级仍混在一个学习面板里。
- 管理员菜单来自 `courseNav`，加入题目管理和教师看板；当前没有独立的“图谱管理”工作台，也没有课程全图/个人掌握/班级热力入口的上下文切换。
- 前端 `isAdmin` 基于 `store.state.user.loginUser.userRole === ACCESS_ENUM.ADMIN`（约 460-462）；这是当前 role 分支证据，下一阶段必须保留并在布局级复用，不要把截图里的管理员当作学生。

更新方向：

1. 详情卡只保留节点资料、课程关系、资源统计、学习状态与 CTA。
2. 管理操作迁移到“管理员工具条/管理抽屉”，按权限显示。
3. 管理员默认看到课程结构统计（节点数、关系数、待配置题目数、待审核题目数），学生默认看到个人掌握统计。

### 3.3 “学习证据”文案语义错误

证据：`KnowledgeGraphView.vue:472-474` 将非灰色节点数量命名为 `evidenceCount`，模板 `141-144` 展示“最近更新 · X 条学习证据”。这不是事件条数，而是有非灰状态的节点数。

更新方向：后端/前端分开表达：`evidenceNodeCount`（有证据的节点数）、`eventCount`（事件条数）、`masteredCount`（状态统计）。管理员无个人事件时显示“当前账号暂无个人学习证据；请切换课程全图或教师看板”，不要显示含义不明的“0 条”。

### Group B：知识图谱产品化（管理员与学生双视角）

涉及文件：

- `src/views/knowledgeGraph/KnowledgeGraphView.vue`
- `src/components/KnowledgeGraph.vue`
- `src/api/learning.ts`
- 后端对应 `PersonalGraphVO`/知识图谱 VO 由后端 agent 共同确认

学生 UI：

- 默认“我的掌握”，显示个人状态热力、掌握度/可信度、最近事件和推荐路径。
- “课程全图”显示完整课程结构，不因个人没有事件而缩小节点集合。
- 节点详情直接展示关联普通题数、实验数、前置/后继节点、最近错误和下一动作；工作台不应必须打开抽屉才能看到核心信息。
- 节点单击选中并更新详情；双击不再跳到少量静态 HTML 文件，改为打开通用 `/knowledge/node/:nodeName` 或节点工作台。

管理员 UI：

- 默认课程全图，不把管理员个人掌握状态当作课程状态。
- 顶部显示课程结构指标：总节点、总关系、已配置普通题节点、已配置实验节点、待维护节点。
- 右栏显示节点结构和教学资源配置状态；个人掌握区明确标注“管理员个人学习状态（可选）”。
- 管理按钮进入独立管理抽屉或管理模式，必须确认删除；Cypher 仅管理员显示。

数据/交互修复：

- 取消前端 `CHAPTER_HUBS` 作为正式章节来源；后端返回真实 `chapter`/`chapterName`，或在 Neo4j 关系/节点属性中提供明确映射。没有真实章节字段时，UI 文案使用“类别/关系邻域”，不要伪装成章节。
- 修复 chapterFilter 实际按 category 过滤的问题。
- 图谱快照必须包含孤立节点；节点和 link 去重，布局由可视区域尺寸计算，不能使用 `startX=70` 等固定左下坐标导致大片空白。
- `KnowledgeGraph.vue` 的 `height:620px`（约 290-293）改成可响应式高度，并提供 fit/zoom/reset 控件。

验收：管理员截图账号打开首页显示课程全图且节点分布覆盖画布；学生账号打开显示我的掌握；两者同一节点详情不越权；过滤器的“章节/类别/掌握状态”语义准确；点击节点和 CTA 均可工作。

### Group C：动态知识节点学习工作台

现状证据：`src/components/learning/NodeWorkbenchDrawer.vue:1-196` 已有抽屉、概念卡、掌握度、可信度、前置节点、推荐、普通题、事件、导师问答；`199-295` 使用 `nodeWorkbench`/`tutorAsk`。

改造目标：抽屉升级为 `/knowledge/node/:nodeName` 的完整工作台页面，抽屉作为快速预览保留。

页面模块顺序：

1. 顶部节点标题、类别、章节/邻域、状态、掌握度、可信度、最近变化。
2. 一分钟概念卡：节点描述、核心关键词、常见误区。
3. 前置/后继/相关节点图谱小视图。
4. 证据面板：概念理解、实践应用、事件数量、最近错题/判题结果、变化原因。
5. 资源面板：普通题、编程实验、交互模拟器，并显示数量和完成状态。
6. 动态学习路径：为什么推荐、下一步按钮、路径节点状态。
7. GraphRAG 导师：回答、来源、检索轨迹、AI/规则降级标识。

不要为每个节点新增静态 `.html`。继续复用 `nodeWorkbench`、`tutorAsk`，并按需补充 node detail API 字段。

验收：任意真实节点均能打开同一套工作台；无关联资源时显示可理解的空状态；题目答题后工作台刷新掌握度和事件；导师来源可追溯。

现状问题：页面是连续卡片列表，筛选固定章节数组（约 97 行），缺少题目总览/掌握概览/错题状态/完成进度，视觉上与知识图谱工作台割裂。

### Group E：算法实验室 / 交互模拟器

涉及文件：`src/views/learning/SimulationView.vue:1-321,323-543`。

现状：CPU 与页面置换已有输入、服务端计算、结果表格和预测练习，但仍是普通表单堆叠；缺少逐步播放、当前步骤、高亮命中/缺页、算法对照和学习路径上下文。

要做：

- 页面顶部显示关联节点和目标；从节点工作台进入时自动带 nodeName。
- 页面置换首屏重点化：访问序列、物理块、算法切换、逐步帧表；提供播放/暂停/单步/重置、当前步骤高亮、命中/缺页/淘汰解释。
- 增加 FIFO/LRU 对比结果卡：缺页次数、命中率、关键差异。
- 预测练习保留服务端判分，将预测结果、学习事件和关联节点明确展示。
- CPU 调度保留 FCFS/SJF/RR，但重排为输入—运行—甘特图—预测四段；SJF/RR 后端已有接口类型，UI 不要另造接口。

验收：每步状态与服务端返回一致；预测成功/失败都产生清晰反馈；从节点页面进入后能返回节点并看到 SIMULATION 事件。

## 5. 角色验收矩阵

| 场景 | 管理员 | 学生 |
|---|---|---|
| 知识图谱默认模式 | 课程全图/课程结构 | 我的掌握 |

## 7. 已知反模式

- 不要把管理员截图解释成学生账号。
- 不要用前端 `CHAPTER_HUBS` 或关系深度冒充真实章节数据。
- 不要默认 `mine` 模式代表课程全图。
- 不要用“有颜色节点数量”冒充“学习事件数量”。
- 不要继续给每个知识点制作静态 HTML 讲义。
- 不要把管理员图谱 CRUD 按钮放进学生学习 CTA 区。
- 不要在学生端显示 `correctAnswer`；当前 `src/api/learning.ts:48-69` 的共享类型应拆成 Student/Admin 类型。
- 不要为了视觉效果伪造掌握度、事件、班级数据。
- 不要以增加页面数量代替完成闭环；每个页面都必须能回到知识节点和真实学习证据。

## 8. 验收证据要求

每个 UI group 的 agent 完成后报告：

- 修改文件与准确行范围；
- 使用的真实 API 和请求参数；
- 管理员账号和学生账号分别验证的截图/录屏路径；
- `npm run build`、必要的 lint/test 输出；
- 未完成项和数据缺口。

最终主线验收：

1. 管理员登录看到课程全图、节点结构统计和独立管理入口；
2. 学生登录看到个人图谱，进入任一节点通用工作台；
3. 从节点进入普通题，答错后看到解析、误区、掌握度变化和相关节点；
4. 进入页面置换模拟器完成逐步练习/预测，产生 SIMULATION 证据；
5. 回到节点工作台看到事件、推荐和 GraphRAG 来源；
6. 学生再次答题或提交实验后状态更新；
7. 管理员/教师看板能看到聚合后的班级薄弱点，且不泄露学生答案；
8. 所有导航按钮和 CTA 都有真实动作或明确禁用态。

## 9. 信心与缺口

- 高信心：以上路径、组件、API 和角色分支均来自当前工作区源码及方案文档。
- 中信心：截图中的完整 Neo4j 节点数量无法仅凭前端确认；当前少量节点可以由 `mine` curated 视图解释，也可能叠加后端全图丢失孤立节点问题，需要后端 agent 用真实接口响应确认。
- 需协同后端确认：节点是否已有章节字段、课程结构统计字段、全图快照是否包含孤立节点、教师看板的下钻数据是否已有 API。
