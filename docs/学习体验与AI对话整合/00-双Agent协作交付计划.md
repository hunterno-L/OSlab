# ZhiCore 学习体验与 AI 对话整合：双 Agent 协作交付计划

版本：2026-11-11。状态：待执行。建议工期：7 个工作日，两个开发 Agent 协作；本轮仅交付计划，没有实现代码或原型。

## 1. 范围与最终结果

本计划以用户认可的前端交互方案为准，纳入最新修订：**删除新增图谱状态说明区的设计，把 AI 对话体验作为本轮重点。**

完成后，学生应能从现有首页、课程单元、知识点、题目和实验进入同一个学习导师，在当前课程中连续提问；按自己的节奏完成逐题练习或整组自测；完成后继续执行已有的学习与复习建议。AI 面板应具备适合长文本阅读的布局、固定输入区、自然的追问和可靠的会话恢复。

### 必做交付

1. 统一全局、节点、实验、单元、题目中的导师入口、上下文与消息来源。
2. 重做 AI 对话面板：侧边辅导、展开阅读、窄屏适配、输入与消息交互、真实消息历史恢复。
3. 让同一会话的后续问题真正使用受限的最近对话上下文，而不只是把多次问答画在一起。
4. 整理现有首页、单元页、学习记录与下一步行动的衔接。
5. 逐题练习给简短即时反馈，整组自测提交后统一反馈；草稿、判分、帮助记录与重复提交正确。
6. 保留自主配置模型，统一模型选择入口及测试后启用流程。
7. 在现有操作系统课程和已发布的第二课程上验证核心路径，并交付可现场操作的演示脚本与检查记录。

### 本轮边界

- 图谱沿用现有状态显示和布局，不新增状态分类面板、掌握度说明区、概率仪表或新图例；仅允许必要的导师入口和上下文接线。
- 不更换 BKT 参数、掌握度算法、复习调度算法或误区诊断规则。此前关于算法的讨论作为后续独立工作，不夹带到本次界面整合。
- 不做代码动画，不新增递归等当前不存在的题目，不改算法演示的内容与播放逻辑。
- 不新建平行的“学习系统”“复习系统”或另一个重复首页。学习与复习仍发生在现有页面中。
- 不做会话全文搜索、语音、图片理解、自动生成整门课程、通用代码执行或复杂多 Agent 后端。
- 本轮不要求流式输出。现有轮询可以保留；不得用假打字效果冒充真实生成流，也不得在后端不支持取消时展示“停止生成”。

## 3. AI 对话的交互与视觉规格

这里的“像 Codex”指宽松的对话阅读、固定输入区、简洁工具条和上下文连续性，是本项目的设计目标；不要求复制 Codex 品牌、专有素材或完整功能。

### 3.1 一个面板、两种桌面尺寸

- **侧边辅导**：桌面默认右侧停靠，建议宽 460px，可在 400–560px 内调整。只有页面主体仍有至少 720px 可用宽度时才挤压布局，否则覆盖显示并允许关闭；不能把代码编辑器或题卡压到不可用。
- **展开阅读**：从同一面板展开为宽阅读空间，最大约 1100px、视口四周留白，正文列约 720–800px。必须复用同一会话、输入草稿、滚动位置与进行中的请求。
- **窄屏**：使用全屏面板，返回入口明确；输入区适应软键盘和安全区。长代码、表格在自己的容器内横向滚动。
- 保留现有全局头像入口及用户的拖动偏好；打开后避免头像继续遮挡发送按钮。不能同时渲染多个独立聊天实例。
- 关闭只收起界面，不清空消息，不取消已提交任务。重开显示当前任务的真实状态。

### 3.2 面板内容层级

```text
AI 导师                         最近对话  展开/收起  更多  关闭
数据库系统 / 当前单元            当前页面 ▾
──────────────────────────────────────────────────────────
学生问题：紧凑、靠右、浅底

导师回答：正文为主，少套卡片
段落 / 列表 / 公式 / 代码块清楚排版

[来源 2]  [复制]  [详情]          ← 使用时展开
[继续做一道练习 →]              ← 最多突出一个下一步

                          有新回复 · 回到底部
──────────────────────────────────────────────────────────
[本题/选段/运行结果 ×]            ← 看得见且可移除的附带上下文
输入问题；可以边等待边写下一条……
学习 / 复习     当前模型 ▾                          发送 ↑
```

- 使用现有浅绿工作区、白色或浅灰对话面、钴蓝主动作；面板内部以阅读为主，不铺满浅绿色或装饰图案。
- 界面和聊天正文使用现有无衬线字体。正文建议 15–16px、行高 1.65–1.75；代码建议 13–14px；不把整段 AI 回复做成细小提示字。
- 导师正文不再被一层层“消息卡—解析卡—诊断卡—来源卡”包裹。用户消息可用浅底气泡，导师回复作为连续正文。
- 来源默认显示数量与可读定位，展开后提供真实来源；不得用模型编造的书名补齐标题。
- 工具过程、模型耗时、token 和诊断证据收在“详情”，不在每条回答上占据主视觉。服务降级必须有一条简短可见提示，不能藏进详情。
- 已有下一步仍可执行；聊天中默认突出一个相关动作，其余收起。首页负责完整计划，聊天顶部不常驻大块重复计划。
- 首次进入只有简短说明和 2–3 个与当前课程/任务相关的建议。删除硬编码的 OS 示例跨课程出现的问题。
- 不把“持久会话、浏览器仅存指针、完整语义检索”等实现术语当成学生操作说明。

### 3.3 输入、阅读与等待

- 输入框自动增高，最多约 6 行，之后内部滚动；Enter 发送、Shift+Enter 换行，中文输入法组词期间 Enter 不得误发送。
- 发送后保持输入可编辑；同一会话有进行中请求时暂不重复发送，明确提示正在回复。首版不做隐式队列。
- 正在生成时可以写下一条草稿、复制上文和查看资料；错误后保留原问题与草稿。重试不能重复追加同一个用户消息或重复计费执行同一请求。
- 用户在底部才自动跟随新消息；正在阅读上文时保持位置，显示“有新回复”。展开来源、代码块或加载更早消息时也不得跳到底部。
- 复制提供轻量反馈；代码块支持复制；Markdown 继续使用既有净化链路，不能改为直接插入未经处理的 HTML。
- 等待提示只显示可证实状态。后端只有 RUNNING 时显示“正在回复”，不能伪造“正在读取第 3 份教材”或“思考过程”。
- “新话题”进入同一课程的新会话，旧会话可从“最近对话”读取；不删除学习记录。仍在回复或有未发送草稿时给出一次明确处理选项。
- 模型菜单只展示该用户可用且通过测试的配置；未配置时引导现有设置页。切换从下一轮生效，当前轮次使用的模型显示真实值，不默默回退到另一付费模型。

### 3.4 场景和会话的关系

学生仍然只面对“AI 导师”。场景决定辅导职责，不建立五套会话。

| 场景 | 主职责 | 页面入口 |
| --- | --- | --- |
| 全局 | 问答、解释当前学习建议、安排学习或复习 | 全局头像、首页计划 |
| 单元 | 围绕目标和选段讲解、衔接下一活动 | 单元标题和选段提问 |
| 节点 | 围绕当前概念回答、联系前置知识 | 现有节点求助入口 |
| 题目 | 分层提示、提交后解释错误和推荐练习 | 题卡“提示”“讲解这题” |
| 实验 | 根据学生明确附带的报错、片段和真实判题结果排查 | 实验页“帮我分析” |

- `学习/复习` 是会话目标；`单元/题目/实验` 是当前场景；`给提示/解释/排错` 是本轮意图，三者不能混成一个模式枚举。
- 同课程切换页面不自动清空对话，当前页面上下文随路由更新；已发送消息保留发送时的上下文快照。
- 可切换“当前页面 / 整门课程”。移除显示用的页面附件不解除服务端已经建立的答题/自测限制。
- 点击页面求助先填入草稿与附带内容，学生可编辑再发送；不因为打开面板就产生模型调用。明确标注“发送此问题”的快捷动作可以立即发送。
- 跨课程切换恢复对应课程会话、草稿和进行中状态，上一课程的迟到响应不能写入当前课程。

## 4. 现有学习页面的改造规格

### 4.1 首页与个人学习入口

- 沿用 `HomeView`，优先呈现“继续当前单元”，以及已有服务返回的到期复习/下一步行动。默认显示 1 个主要动作，最多补充 2 个候选。
- “复习 15 分钟”等操作修改现有会话目标并读取真实计划，不按前端时间预算临时拼造任务。
- 画像适当压缩，已有状态可继续使用；不新做一套图谱状态解释。没有记录时用“先完成一次学习或练习”及真实入口，不展示虚构统计。
- 头像菜单可将入口名称整理为“我的学习”，仍进入现有学习记录/复习位置；保留时间线与历史明细。
- 学生登录后的默认路由沿用当前约定；本轮不顺手把 `/graph` 改成 `/home`。

### 4.2 单元工作区与资源

- 保留目录、目标、当前活动和内容，减少目标、进度、推荐在多个区域重复出现。当前活动有一个清楚的主动作。
- 问题来自当前选段时，将选段摘要和来源定位带入导师，默认可编辑；点击引用能回到相应资料位置。
- 阅读/活动完成只更新真实进度，不将“阅读完成”宣称为“知识已掌握”。
- 完成题目或实验后，返回正确课程、单元、活动位置；保留必要筛选和滚动锚点，并刷新现有下一步建议。
- 学生顶栏的独立“学习资源”入口可收进课程内“资料”入口；必须先保证资料搜索和旧链接仍能到达。资料存储、访问控制和教师管理不删。

### 4.3 逐题练习

- 当前题目主操作为“提交答案”；提交后变为“下一题”或现有列表中的“继续练习”。不要每答一题强制打开 AI。
- 即时反馈只展开“对/错或待评阅 + 简短依据 + 详细解析入口”，完整误区、掌握度变化和 AI 分析按需展开。
- 错题提供一个就地补学动作；不自动跳走，不自动扣新题或开启新会话。
- “给我提示”通过统一导师和服务端帮助记录执行。帮助写入失败时，不先显示提示再补记录。
- 题目答案、综合题自评和人工核验的现有判分语义保留。模型不得替代正式判分。

### 4.4 整组自测

- 在现有练习入口选择“逐题练习 / 整组自测”；自测选择真实可用范围和数量，沿用当前 1–20 题上限，默认可选 5 或 10 题。
- 自测前说明“交卷后统一看解析”；没有真实计时规则就不添加倒计时。
- 答题时可上/下一题、标记不确定、查看答题卡、修改答案、暂存退出。草稿变化后显示保存状态，刷新可恢复。
- 自测进行中不返回本轮对错、正确答案、解析、诊断、推荐或本轮掌握度变化；仅隐藏 DOM 不合格。
- 自测期间不对本组题提供提示/答案。学生要求帮助时说明可以先交卷，再进入辅导；这是一项学习模式约束，不宣称具备监考或阻止外部 AI 的能力。
- 交卷前列出未答题和标记题。允许学生明确交卷；未答题不生成“知识薄弱”的失败观测。
- 交卷由服务端最终确认草稿版本、判分并产生证据。双击、网络重试和刷新结果不得重复记录。
- 综合题等不能自动判分的题目展示“待自评/参考解析”，不计入客观正确率；下线/版本失效题单独说明和排除。
- 结果页优先展示本组结果、错题/不确定题入口和一个下一步；可返回原单元或开启现有复习计划。

## 5. 两个 Agent 的职责与文件所有权

文件路径以下端根目录 `后端代码/osLab-backend`、前端根目录 `前端代码/osLab-frontend` 为准。一个文件只能有一个写入者；只读审查不受此限制。

| 责任域 | Agent A：AI 体验与集成 | Agent B：学习流程与测评 |
| --- | --- | --- |
| 前端独占 | `src/components/assistant/**`；`src/composables/useAiConversation.ts`、`useAiPageContext.ts`、`useAiLauncher.ts`；新增 `useTutor*` / `types/tutor*`；`src/api/ai.ts`；`src/utils/aiSources.ts` | `src/views/HomeView.vue`；`src/components/home/**`；`CourseUnitView.vue`、`LearningQuestionsView.vue`、`AssessmentRunView.vue`、`LearningRecordsView.vue`、`ResourcesView.vue`；题卡/答题卡/返回条及新增测评组件；`src/api/learning.ts`、新增 `api/assessment*.ts` 与测评 composable |
| 现有 AI 页接线 | `NodeLearningWorkspaceView.vue`、`ViewQuestionView.vue`：只改导师、上下文和相关布局，不改节点状态/判题/编辑器逻辑 | `KnowledgeGraphView.vue`：只改求助调用与上下文；单元、题卡、首页、记录页的入口由 B 接入 A 的公共契约 |
| 公共 AI 组件 | `AiSourceCard`、`AiToolTrace`、`AiDiagnosisPanel`、`AiModeBadge`、`AiMaterial*`、`ModelSettingsView.vue` | `AiNextActionCard`、`AiNextActions`、`AiHelpBadge`、`src/utils/aiActions.ts`；保持原组件 props/事件兼容 |
| 公共壳与导航 | `App.vue`、`LearningLayout.vue`、`src/styles/learning-theme.css`；仅新增导师布局所需机制，不改公共品牌系统 | `GlobalHeader.vue`、`navigation/appNavigation.ts`、`router/routes.ts`；只做约定入口/返回信息调整，不更换默认首页 |
| 后端独占 | `LearningAiController.java`；`ai/session/**`、`ai/tutor/**`；AI 会话/轮次 DTO、VO、Mapper；历史读取与场景策略；模型网关只在确有兼容需要时小改 | `LearningAssessmentRunController.java`、`LearningQuestionController.java`；测评 DTO、VO、实体、Mapper；`LearningQuestionService*`；`ai/evidence/**`；新增普通尝试接口、`TutorAssessmentGuard`；`LearningEventService*` 仅限证据接线修复 |
| 禁止自行修改 | B 所有权文件、判分器、BKT/ReviewPlanner/NextActionPlanner、课程内容 | A 所有权文件、模型调用、会话生命周期、BKT/ReviewPlanner/NextActionPlanner、课程内容 |
| 测试与说明 | AI 会话/面板/来源/上下文相关测试，A 的执行记录；最终集成报告与 README 由 A 负责 | 练习/自测/学习页面相关测试，B 的执行记录；内容与返回路径检查由 B 负责 |

补充规则：

1. A 是两个 Agent 中的集成人，不额外假设第三位协调者。A 负责公共前端 AI 契约，B 负责测评/帮助契约；两者的接口定义见 [01-共享契约与验收.md](01-共享契约与验收.md)。
2. `LearningAiController` 归 A；B 新增普通尝试 Controller，不能为帮助记录同时修改 A 的 Controller。
3. 若题卡反馈需要修改 A 的共享组件，由 B 写需求，A 实现并交付；反向同理。不能复制出另一份“临时组件”。
4. 未列出的既有文件默认只读，新增文件按所属责任域登记。需要跨域改动时由文件负责人接手，通常不需要再次询问用户。
5. 新迁移编号 D1 由 A 盘点分配：B 的自测迁移预计接在 v12 后，实际执行前核实；A 如需历史索引迁移另占编号。不得编辑已发布 v11/v12。
6. 教师端、已发布课程包、算法内容不纳入重构。资料入口移动不得破坏教师功能。
7. 容易冲突的现有前端测试明确归属：A 写 `ai-conversation-contracts.js`、`ai-source-actions.js`、`model-settings-contracts.js`、`ui-guideline-contracts.js`、`design-system-contracts.js`、`workbench-layout-contracts.js`、`node-workbench-cache.js`；B 写 `ai-help-flow.js`、`question-answer-context.js`、`home-contracts.js`、`learning-integration-contracts.js`、`knowledge-graph-render.js`、`course-catalog-multi-course.js`、`course-semantics.js`。需要调整另一方测试时由其负责人接手。

两个 Agent 可以并行读代码和修改各自文件；Node 构建、Maven 测试、浏览器完整回归等重任务串行，避免本机内存竞争。工作日是执行顺序，不是对实际工时的承诺。

| 工作日 | A 的产物 | B 的产物 | 汇合门槛 |
| --- | --- | --- | --- |

## 7. 开发与资源硬约束

### 7.1 范围和工作区

- 本计划交付后，只有收到执行指令才开始实现；本轮不启动两个开发 Agent。
- 执行时恰好两个开发 Agent，沿用各自默认模型；不因历史计划指定过模型而重选，不继续派生子代理。
- 开工保存 `git status`、已有差异的校验信息和文件所有权记录。当前浮动助手改动及 `public/ai-assistant*` 资源必须保留，任何替换应与本次必要功能明确相关。
- 默认在当前工作基线按文件所有权协作，不擅自把用户未提交文件搬到另一个 checkout。若使用工作树，由 A 负责准确迁移本次需要的基线与差异，不能误带或清理其他工作。
- 禁止 `git reset --hard`、`git clean`、批量删除未跟踪文件、覆盖用户修改、广泛格式化或大范围依赖升级。
- 本轮及后续执行默认不 commit、不 push、不合并、不部署、不修改 Git 配置；用户另行明确授权时才执行。不得 `git add .`。

### 7.2 技术与数据

- 继续 Vue 3 + TypeScript + Vuex + Arco 与现有 Spring Boot/MySQL。不得改成 React/Next，不新加状态库或整个聊天 UI 框架。
- 沿用 2 核 2GB、小规模演示、远程模型 API 的部署目标，无 Docker、无 Elasticsearch；不新增向量数据库、消息队列、本地模型推理或常驻重服务。保留现有可配置小堆启动方式，交付记录实际进程内存和队列上限；不能仅凭功能列表宣称该配置承载任意并发。
- 保持已有模型调用/工具预算：每轮最多 2 次模型调用、3 次工具执行；消息历史从 MySQL 受限读取，不能为每轮总结历史再增加一次模型请求。
- 新历史接口分页；上下文、草稿、报错摘要和代码片段有限长；进入页面不预取全用户/全课程消息。
- 所有 ID 作为字符串传输和保存。后端检验用户、课程、题目、会话、资料归属；前端显示的场景/帮助标记不是权限依据。
- API Key 保持后端加密/脱敏；不放入 localStorage、前端环境变量、URL、截图或日志。模型必须通过既有连接测试再激活。
- 不更改生成模型就重建 embedding，不为界面改造重写 RAG/诊断/调度服务。
- 资料默认只传定位 ID、选段及明确附带片段，不自动抓整个 DOM 或上传实验全部源码。
- `FALLBACK` 必须真实可见；不以静态回答、截图或 Mock 数据冒充模型效果。

### 7.3 UI 与状态

- 沿用项目字体、色彩、间距和语义令牌；导师组件可以新增局部布局令牌，不顺手修改全站品牌。
- 不能用“新增状态说明”变相恢复用户否决的图谱设计；教学透明度通过已有记录和必要反馈保留。
- 点击目标至少 44px（触屏）；正文可读；焦点清楚。侧栏非模态不锁住页面焦点，展开模态才管理焦点陷阱、Esc 和关闭后焦点返回。
- 320/390px 窄屏、1024px、1440px 和 200% 缩放必须可操作，内容不被 composer 遮挡。尊重 reduced-motion。
- AI 进行中、失败、模型未配置、来源失效、历史加载失败、无课程内容均有可恢复状态；不能整页白屏。
- 消息历史服务端持久化；浏览器不存完整对话。未发送草稿如需刷新恢复，仅用按用户/课程/会话隔离的 sessionStorage，有限长、有过期与退出清理，不包含密钥。
- 取消等待、关闭面板、切换模型不是后端取消生成；不能显示与实际不符的按钮或成功提示。

### 7.4 检查与记录

- 一次只允许一个重任务。A/B 在共享执行记录中登记重任务开始/结束；不并行跑前端 build、Maven 套件和多组浏览器。
- 前端构建沿用 `NODE_OPTIONS=--max-old-space-size=2048`，用完恢复原值；实际部署资源上限不等于开发编译内存。
- 只为状态、契约、隐私/隔离、草稿/判分/幂等等实质行为加测试；不为按钮颜色或组件名称堆源代码字符串断言。
- 原测试若绑定旧布局，应保留原业务保证并调整断言，不能直接删除失败测试来变绿。
- 区分已通过、既有失败、新增失败、未运行。新失败必须处理；基线失败只有能证明与本次无关且不影响交付路径时才列为已知限制。
- 可先用夹具测试失效分支，但最终成功链路必须连接真实后端与可用模型。没有真实模型验证时不得标记 AI 完成。
