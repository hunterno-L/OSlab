# 共享契约、状态边界与验收

版本：2026-11-11。配套 [00-双Agent协作交付计划.md](00-双Agent协作交付计划.md)。本文包含**拟新增契约**，不能当成已上线接口。D1 核对实际 DTO 后冻结；字段变更由各责任人同步更新本文和消费方，不做静默改名。

## 1. 公共规则与所有权

- 继续使用 `BaseResponse { code, data, message }`、现有 Cookie 鉴权与权限校验。以下 URL 省略 `/api` 前缀。
- 用户、课程、资源、会话、轮次、评估运行 ID 一律为字符串；前端不得通过 `Number` 做排序或比较。
- A 写前端导师公共类型、AI API 和后端 AI DTO；B 写评估 API、尝试/帮助服务与 `TutorAssessmentGuard`。两人可审查对方文件，修改仍交负责人。
- 请求允许携带定位和学习意图，不能接受客户端传来的掌握分、正确性、独立观测资格或工具执行结果。
- 接口只做本轮必要扩展；所有旧入口保持兼容，不整体重新生成 OpenAPI SDK。

## 2. 前端统一导师入口（A 定义，B 消费）

建议在现有 `useAiLauncher.ts` 上增加以下概念，具体导出名 D1 固定：

```ts
type TutorScene = 'GLOBAL' | 'UNIT' | 'NODE' | 'QUESTION' | 'EXPERIMENT';
type TutorIntent = 'ASK' | 'EXPLAIN' | 'HINT' | 'DEBUG' | 'PLAN';
type TutorContextScope = 'PAGE' | 'COURSE';

interface TutorLaunchRequest {
  scene: TutorScene;
  intent: TutorIntent;
  courseCode: string;
  scope?: TutorContextScope;
  unitCode?: string;
  nodeCodes?: string[];
  resourceRef?: string;
  selectedSourceIds?: string[];
  eventIds?: string[];
  attemptContextId?: string;    // 服务端建立的答题证据上下文
  assessmentRunId?: string;
  draft?: string;
  attachments?: TutorAttachment[];
  delivery?: 'DRAFT' | 'SEND'; // 默认 DRAFT，不因打开面板而调用模型
}

interface TutorAttachment {
  kind: 'SELECTION' | 'CODE' | 'ERROR';
  label: string;
  text: string;
  sourceId?: string;
}

openTutor(request: TutorLaunchRequest): void;
```

约束：

1. `scene/intent/scope` 与既有 `focus: LEARN|REVIEW` 分开。选择“当前页面”也不创建独立导师实例。
2. 页面元信息由当前页面注册；题卡等嵌套组件用显式 launch 参数覆盖当前题目，而不是抢占全局 provider。卸载旧 provider 不得清掉新页面的 provider。
3. 点击“提示”必须关联有效 `attemptContextId` 或 `assessmentRunId`；后端校验绑定题目。没有这些信息时先由 B 的流程建立上下文。
4. `attachments` 只含用户明确选取的内容。建议单选段 ≤2000 字、单代码/报错片段 ≤8000 字、合计 ≤12000 字；D1 对齐实际模型和请求上限。超限时明确提示选择更小范围，不静默上传全文。
5. 同课程弹入新草稿时，不能覆盖用户未发送内容；提供“替换 / 保留原草稿”或可插入的建议。只有明确 `SEND` 动作立即发起请求。
6. 旧 `openAiAssistant()` / `askAiAssistant(text)` 保留薄适配，已迁移入口改用新契约；不允许兼容层重新维护会话。
7. 请求发送前冻结用户、课程、sessionId、上下文及 requestId。后续路由变化只影响下一条消息。

## 3. AI 会话历史、追问与请求生命周期（A）

### 3.1 拟新增接口

| 接口 | 最小内容 | 规则 |
| --- | --- | --- |
| `GET /learning/ai/sessions?courseCode=&cursor=&limit=20` | `items: [{sessionId, courseCode, title, status, updatedAt}], nextCursor` | 当前用户、指定课程；limit 上限 50；标题取既有目标或首条用户问题的截断，不额外调用模型 |
| `GET /learning/ai/sessions/{id}/turns?before=&limit=20` | `items: [{turnId, clientRequestId, userMessage, createdAt, contextSummary, turn: AiTurnVO}], nextCursor` | 真实持久轮次；已关闭会话也可由所属用户只读查看；不返回密钥、原始系统提示或非公开工具载荷 |
| 现有 `POST /learning/ai/sessions/{id}/turns` | 兼容原字段，扩展场景、意图、附件和评估上下文 | 后端重新校验；不会因前端切换到 GLOBAL 就解除已识别的自测限制 |

最近对话在简洁菜单/抽屉中呈现，不强行常驻一个大型会话侧栏。已关闭会话仅浏览；继续新问题用当前活动会话或明确创建新话题，不隐式重开已关闭状态。

请求字段放置统一如下，旧客户端省略新增字段时继续按旧行为工作：

```ts
interface ExtendedAiTurnRequest {
  clientRequestId: string;
  message: string;
  context?: AiCourseContext & {
    attemptContextId?: string;
    assessmentRunId?: string;
  };
  tutor?: {
    scene: TutorScene;
    intent: TutorIntent;
    scope: TutorContextScope;
    attachments?: TutorAttachment[];
  };
}
```

A 维护该公共 DTO；B 的 Guard 读取已经校验的服务端 DTO，不另建同名字段。前后端要对齐 message 与附件上限，超限必须明确拒绝或由用户编辑；不能沿用静默截断逻辑，导致用户看见完整问题而服务端只记下前半段。

### 3.2 多轮上下文

- 后端只读取同一用户、同一课程、同一会话中、本轮之前的成功轮次。默认最多最近 6 轮，并限制总历史字符/模型上下文预算；上限配置化。
- 不能直接信任客户端上送的“历史消息数组”。历史消息属于对话数据，不升级为系统指令；当前题目安全限制和来源核验始终有效。
- 历史中的“来源 [1]”不能直接被当成当前来源编号；当前来源仍须重新检索/定位。无法确定“那一步”指代时应澄清，不能编造历史。
- 不额外调用模型生成历史摘要，保持现有每轮模型/工具预算。
- 同会话同一时刻只执行一个新轮次；跨标签页并发也由后端约束。冲突返回可恢复的忙碌状态，不进入无限排队。

### 3.3 状态与去重

```text
草稿 → 提交中 → RUNNING → SUCCEEDED / FAILED_RETRYABLE / FAILED
                 ↑           ↓
          网络重发用同一 clientRequestId 查询/恢复
```

- 网络超时、双击和对未定状态的重发复用原 `clientRequestId`；已知 turnId 优先读取该轮次，不重新调用模型。
- 明确终态失败后的“重新尝试”可创建新请求，标识这是新尝试，不重复展示同一用户消息。不得把一个进行中请求当成失败自动重复付费执行。
- 消息身份至少由 `sessionId + turnId + role` 确定；历史分页、乐观消息和轮询终态按身份合并。
- 前端状态以 `userId + courseCode + sessionId` 隔离，异步更新还校验账户 epoch/会话 generation。旧课程回复可保存于自己的状态，不能追加到当前面板。
- 切换课程恢复历史、草稿与真实 RUNNING 状态；退出登录清掉内存和临时草稿，迟到响应丢弃。
- 面板关闭不丢任务；浏览器刷新从历史接口恢复进行中轮次。消息恢复失败有重试，不显示“已恢复”假成功。

## 4. 尝试与帮助契约（B 定义，A 调用）

### 4.1 普通练习尝试

拟新增 `POST /learning/practice/attempts`：输入 `{questionId, courseCode, sourceUnitCode?, sourceActivityCode?, clientAttemptKey}`；返回 `{attemptContextId, questionId, questionRevision, submissionKey, helpLevel, status}`。

- 服务端验证已发布题目、课程归属和单位/活动归属，生成或复用稳定尝试上下文。
- 现有 `/learning/questions/answer` 增加可选 `attemptContextId`；有上下文时在答题事务前核对帮助资格。客户端不能自行传 `eligibleForObservation`。
- 一次新尝试仍受已有首次观测去重限制，不因刷新、换模型、换 AI 会话或换 attempt key 重新获得独立观测。
- 对旧无上下文调用保留兼容语义，但本轮迁移的学生题卡必须接上新链路。

### 4.2 导师服务端守卫

B 提供 `TutorAssessmentGuard`，A 在调度题目辅导之前调用。D1 冻结参数类型；职责如下：

```text
输入：登录用户 + 经校验的课程/资源/尝试/自测上下文 + 本轮意图
输出：允许与否 + 可公开的原因 + 已核验题目定位 + 已记录的帮助级别
副作用：需要提示时，先将帮助写入所属尝试，再允许生成/返回辅导
```

- 对自测中的本组题，禁止调用辅导或取出答案。守卫使用服务端 ACTIVE 自测和题目关联，不能只依赖可被前端删掉的 runId。
- 对普通未提交题，提示只获得必要的题面和允许的材料；不能把标准答案/完整解析作为客户端附件或直接展示内容。
- 生成提示失败不回滚已经持久化的帮助记录，避免并发提交造成资格穿透；界面区分“请求未完成”和“已得到回答”，不谎称用户看过成功提示。
- 看过答案或得到提示不得被新话题/切换模型恢复为 NONE；保持现有帮助等级单向升级。
- 清除页面上下文、切换到全局问答，不绕过系统已识别的本题限制；不宣称能够识别所有任意文本中的题目或阻止外部工具。
- 系统错误和编译错误不作为知识薄弱的失败观测。评分与掌握度始终走现有确定性服务。

## 5. 整组自测契约（B）

### 5.1 新增/扩展数据

```ts
type AssessmentMode = 'PRACTICE' | 'SELF_TEST';
type RunStatus = 'ACTIVE' | 'FINISHED';

interface SelfTestDraft {
  questionId: string;
  answer: string | string[] | null;
  markedUnsure: boolean;
  questionRevision: number;
}
```

已存在的 run 未带模式时按 PRACTICE 处理。模式由服务端保存，开始后不允许客户端随意切换。自测固定队列及题目版本；具体迁移字段、草稿与结果表结构由 B 在 D1 确认。

### 5.2 拟扩展接口

| 接口 | 行为 |
| --- | --- |
| 现有 `POST /learning/assessment/start` | 增加 `mode`；返回 runId、真实队列、rowVersion；保持旧 PRACTICE 默认行为 |
| 现有 `GET /learning/assessment/run?runId=` | ACTIVE 自测只返回题面、用户草稿、标记和保存状态；不含答案、解析、误区、正确性、当前或历史正确率提示 |
| 新增 `PUT /learning/assessment/runs/{id}/drafts` | `{clientSaveId, rowVersion, drafts[]}`；返回 `{rowVersion,savedAt}`；不判分、不发事件、不更新掌握度 |
| 现有 `POST /learning/assessment/finish` | SELF_TEST 增加 `{submissionKey,rowVersion}`；服务端核实草稿已保存，再原子判分并保存最终结果 |
| 新增 `GET /learning/assessment/runs/{id}/result` | 仅所属用户且 FINISHED 可读；返回逐题结果、待自评项、失效项、有效统计和后续动作定位 |

### 5.3 必须解决的行为

- 自动保存可以防抖，但切题/退出/交卷前要完成最后一次保存；保存失败保留本地当前输入并显示重试。不能只展示成功图标。
- 版本冲突不覆盖另一标签页更新，提供重新加载或确认恢复当前草稿的路径。
- 交卷先等待草稿保存成功；服务端比较 rowVersion，不拿旧草稿悄悄判分。
- 相同交卷键重发返回同一结果；并发交卷通过数据库状态/锁/唯一约束阻止重复事件。同一键不同载荷必须报冲突。
- 不接受客户端 `firstCorrect/answeredCount` 作为成绩；服务端从有效结果重算。
- 自测中的题目不能借普通 `/questions/answer` 或本项目另一已知页面的解析接口提前获得本轮结果。需要服务端校验，CSS 折叠、前端禁用按钮均不能替代。
- 交卷前禁止在统计、学习记录和下一步建议侧信道生成本轮的判分变化；草稿不写学习事件。
- 未答题不产生错误观测；综合题不由 LLM 自动计对错；版本失效/下线题不静默换题且不参与有效分母。
- 自测完成后原题解析可读，后续辅导使用新的普通练习尝试；不能把交卷后的学习标成该轮独立自测。

## 6. 完成动作后的页面刷新（B 发出，A/B 消费）

新增统一通知或等价 store action，建议：

```ts
type LearningUpdated = {
  courseCode: string;
  unitCode?: string;
  activityCode?: string;
  eventIds?: string[];
  runId?: string;
  reason: 'ANSWERED' | 'ASSESSMENT_FINISHED' | 'ACTIVITY_DONE' | 'JUDGED';
};
```

- 只在后端写入成功后触发，按课程使缓存失效；当前可见页再读取进度、画像和下一步。
- 服务端状态是来源，不能为了动画即时在前端修改掌握度或增加独立证据条数。
- 返回路径优先使用既有 `returnRef`、`returnTo`、单元/活动 query；仅允许站内白名单路由，避免任意外部重定向。
- 事件不重复触发判分、任务 start 或模型请求。同一结果的重复读取不会产生新的学习行为。

## 9. 演示脚本（5–8 分钟）

1. 使用测试学生账号，在首页继续真实已发布单元，选段向导师提问，展示当前课程与附带资料。
2. 连续追问，再展开面板阅读代码/公式或长回答；点真实来源返回资料位置。

## 10. D1 冻结补充（2026-11-11，A 盘点；不改变上文语义）

1. **前端落点**：类型文件固定为 `前端代码/osLab-frontend/src/types/tutor.ts`；`openTutor` 固定从 `src/composables/useAiLauncher.ts` 导出。旧 `openAiAssistant` / `askAiAssistant` 保留为薄适配。
2. **历史接口最终形状**：
   - `GET /learning/ai/sessions?courseCode=&cursor=&limit=20`：`items` 至少含 `sessionId, courseCode, title, status, updatedAt, focus`；`limit` 上限 50；cursor 不透明。
   - `GET /learning/ai/sessions/{id}/turns?before=&limit=20`：`items: [{turnId, clientRequestId, userMessage, createdAt, contextSummary, turn: AiTurnVO}]`；按时间正序返回，`nextCursor` 指向更早一页。
   - 两者都只允许会话所属用户；`GET` 不产生新轮次、不调用模型。
3. **多轮上下文**：默认最近 6 个成功轮次，单轮问答截断 1200 字，总预算 6000 字；配置键 `ai.turn.history-max-turns`、`ai.turn.history-max-chars`。历史只注入回答提示；工具计划提示最多带 2 条、各 300 字。
4. **帮助守卫**：A 定义 `com.yupi.springbootinit.ai.tutor.TutorAssessmentGuardPort`，B 的 `TutorAssessmentGuard` 实现该接口；A 在 `intent=HINT` 且带 `attemptContextId`/`assessmentRunId` 时于模型调用前执行守卫。无上下文的 HINT 由 A 直接拒绝（PARAMS_ERROR）。
5. **轮次请求扩展**：`context` 增加 `attemptContextId`、`assessmentRunId`（字符串，服务端会校验归属）；`tutor` 增加 `attachments`（A 校验上限：选段 ≤2000 字、单代码/报错 ≤8000 字、合计 ≤12000 字，超限拒绝并提示，不静默截断）。
6. **会话列表标题**：`goal` 非空用 goal，否则取首条用户消息前 60 字；不额外调用模型。
7. **迁移编号**：v13 预留给 B 的自测迁移；A 当前无需新迁移（沿用既有索引）。若后续需要，A 占 v14。不得编辑 v11/v12。
