## 工作台、记录与 API 的具体改动

- `NodeLearningWorkspaceView.vue`：首屏立即呈现节点标题与导师，数据区局部加载；发布正文与节点描述使用已有内容；每次只打开一道题的答题抽屉。导师对话按用户与节点隔离，刷新掌握度不清空消息，异步返回有节点/用户守卫与明确结束状态。
- `LearningRecordsView.vue`：连接式日期时间线与掌握度比较；节点/事件过滤响应路由更新；回放、提交详情切换及关闭后不接收旧请求结果，模态框适配窄屏。生成客户端按 `res.code` 读取，学习客户端按 `res.data.code` 读取；事件 ID 保留字符串精度。
- `NodeWorkbenchDrawer.vue`：共用用户与节点缓存，补充可见性及异步守卫、窄屏宽度；保留明确的进入学习命令，移除功能介绍文案。
- `useNodeWorkbench.ts`：缓存最多 24 个键，30 秒有效期；同用户同节点请求合并；变更事件清缓存，失效期间的旧请求不能重新写入缓存；业务失败不缓存。
- `learning.ts`：实际返回类型统一为 `AxiosResponse<BaseResponse<T>>`，不改变 HTTP 运行时或拦截器；新增请求类型 `studyState: ALL | UNANSWERED | NEEDS_REVIEW | CORRECT`；`assessmentRunId` 与回放事件 ID 接受 `number | string`；判断题仍发送 `"true"`/`"false"` 字符串；导师请求设 45 秒超时。答题及模拟成功后发出 `oslab:learning-changed` 使缓存失效。
- 服务端工作台 JSON 契约与 controller 路由不变。新增内部服务方法 `LearningQuestionService.getQuestionVOs(List<Long> questionIds, User user)`，批量读取已发布题目、映射及本人尝试，未答题不泄露解析或答案。测评会话校验由对应模块独立维护。
- `LearningMasteryServiceImpl`：工作台只使用一次图谱快照与一次掌握度读取；一次节点事件读取同时生成最新活动、最近 50 条及纠正状态；实验提交仅取当前用户、关联实验的最新提交字段，SQL 保留删除过滤及同时间 ID 顺序，不读取代码。推荐在图谱不可用时保留原有降级路径。
