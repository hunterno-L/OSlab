# OSLab 第三阶段后续：修正与收尾执行计划

**版本**：v1.0  
**编制日期**：2026-10-04  
**执行方式**：由 agent 按阶段实施，主 agent 逐阶段审核  
**目标**：完成 `log3.txt` 指出的界面修正，补齐知识图谱智能学习闭环的硬缺口，并以可复现的证据完成收尾。

## 0. 结论先行

当前不能直接宣布方案全部完成。截图和代码审计表明，第三阶段已经具备较多后端能力，但仍有以下未闭合事项：

1. 知识图谱默认进入了 ECharts 的模糊状态，节点文字和关系几乎不可读；页面两侧留白过大，图谱和实验中心被压缩在中间。
2. 知识点详情同时出现多个学习/实践入口，和学习工作台重复；工作台缺少“知识详解”入口。
3. 实验页面的“实验导师”位置和命名不符合新的学习流程；页面仍保留重复的“关联学习 / 题目练习”入口。
4. 全局 AI 助手尚未形成可拖动、可跨页面使用、按用户隔离的稳定组件。
5. 时间线接口已经存在，但前端还没有“图谱快照 + 时间轴 + 播放”的可视化回放。
6. 章节筛选中的“未归类”、测评候选题只取前 50 条、编译错误影响掌握度、Tutor 证据被截断等契约问题仍会造成错误学习结果。
7. 教师端目前是节点热度列表，不是可称为“班级薄弱点图谱”的拓扑视图；若继续保留原方案中的该功能名称，需要补上只读图谱视图。

因此本计划不是重新设计产品，而是“**OpenDesign 视觉修正 + 功能契约补齐 + 可验证收尾**”。只有第 1 至第 8 阶段的硬门槛全部通过，才可以把项目标记为“本地可交付”；Docker 判题、线上部署和真实数据验证仍需单独标记，不得用 stub 结果代替。

## 1. 执行约束

### 1.1 工作边界

- 当前工作区已有第三阶段未提交修改，直接在当前工作区继续修改；禁止 `reset --hard`、`checkout --`、覆盖用户改动或清理无关文件。
- 本轮只按计划修改源代码、测试和文档，不提交 Git、不推送、不部署生产环境。
- 不使用浏览器自动化。前端验收使用本地服务、手动操作和截图；API、构建、测试使用命令行。
- 不新增 AI 服务商、前端 API key、第二套聊天后端或第二套图谱存储。继续使用已有 `/api/chat/ask` 和学习 Tutor API。
- 页面文案统一使用“知识点练习”“题目练习”“判断题”“单选题”“多选题”“填空题”等已有产品语言。
- 管理员、教师、学生分开验收。截图中的张小明是管理员账号，不能据此推断学生的掌握度、推荐内容或学习记录。

### 1.2 收尾定义

一个阶段只有同时满足以下四项，才可在交付记录中写“完成”：

1. 源码已实现，且改动范围与本阶段目标一致。
2. 相关单元测试、接口测试或构建检查已通过。
3. 在指定角色和视口下完成手动验收截图。
4. 结果、未验证部分和已知限制写入交付记录。

“代码看起来已经有了”“接口返回 200”“stub 通过”都不能单独作为完成依据。

## 2. 设计基线：OpenDesign 落地规则

本阶段采用已有 OSLab 视觉方向，不再进行一次大规模换肤。OpenDesign 的作用是约束信息层级、间距、状态和交互，而不是增加装饰。

### 2.1 视觉令牌

以 Notion/Readwise/Expo 风格的克制白色工作台为基准，并保留 OSLab 的品牌蓝：

| 用途 | 令牌 |
| --- | --- |
| 页面背景 | `#FFFFFF` |
| 轻背景 | `#F9F9F8` |
| 更安静的分区背景 | `#F7F7F5` |
| 主文字 | `#1B1B1B` |
| 次级文字 | `#37352F` |
| 辅助文字 | `#A39E98` |
| OSLab 主蓝 | `#2059C9` |
| OpenDesign 交互蓝参考 | `#4B7BF5` |
| 分隔线 | `rgba(0,0,0,0.11)` |
| 状态：已掌握 | `#3B8F73` |
| 状态：待巩固 | `#B7791F` |
| 状态：薄弱 | `#B95C50` |
| 状态：未学习 | `#9AA39E` |

### 2.2 布局规则

- 采用 12 列网格，桌面端内容宽度随视口扩展；图谱和实验中心使用 `wide` 页面宽度，边缘保留 24–32px 内边距。
- 页面级宽度只在指定路由放宽，不能把所有旧页面的 `max-width` 全部改成满屏。
- 图谱主画布是页面的主要工作区，详情栏是固定的辅助栏；不再让多层 `max-width` 和重复侧栏挤压主画布。
- 卡片只用于详情、统计、弹层和重复条目；禁止在卡片中继续套装饰性卡片。
- 圆角使用 4/8/12px，按钮和输入框的高度、间距保持稳定；不使用大面积渐变、发光、毛玻璃和随机装饰。
- 交互反馈使用 200/400/800ms 的短过渡；状态颜色必须同时有文字或图标，不得只靠颜色。

### 2.3 信息层级规则

每个页面只保留一个主任务：

- 图谱页：浏览、选择和进入一个知识点的学习工作台。
- 知识工作台：学习内容、知识详解、题目练习、实践四种互补方式。
- 实验页：理解实验、查看关联图谱、向导师提问、编写和提交代码。
- 实验中心：按章节筛选并进入实验，不在此复制学习工作台的入口。
- 全局助手：解决当前页面上下文中的即时问题，不替代节点 Tutor。

## 5. 阶段 1：知识图谱布局与可读性修正

### 5.1 目标

让图谱在首次打开时清晰、稳定、可浏览；让页面宽度服务于图谱，而不是让图谱缩在中间的一小块区域。图谱详情只保留一个明确的学习入口。

### 5.2 实施文件与做法

#### A. 页面级宽度和列布局

涉及：

- `LearningLayout.vue`
- `KnowledgeGraphView.vue`
- 路由定义文件中的知识图谱路由 meta

实施要求：

1. 为知识图谱路由增加明确的 `contentWidth: "wide"`（名称可按现有路由 meta 约定调整）。
2. `LearningLayout` 只对 `wide` 路由放宽容器，建议桌面端最大宽度 1760px；小于该宽度时使用 24–32px 边距。
3. 保留现有课程侧栏、图谱画布、详情栏三块职责，但去掉重复的内层 `max-width` 约束；画布使用 `minmax(0, 1fr)`，详情栏保持约 340px。
4. 侧栏、画布和详情栏在 1024px 以下改为可折叠或纵向排列，不能出现横向溢出。
5. 不新增统计卡、推荐卡或装饰模块来“填空白”；空白要通过正确的宽度、间距和信息层级解决。

#### B. ECharts 图谱默认状态

涉及：

- `KnowledgeGraph.vue` 的 `buildNodeStyle`、`buildLabel`、`buildLink`、series option 和生命周期。
- `KnowledgeGraphView.vue` 的 `selectedNodeId`、默认选择和筛选逻辑。

实施要求：

1. 节点、文字、关系 ID 全部统一为字符串，比较前统一调用同一转换函数；不能让数字 ID 和字符串 ID 产生“找不到邻居”的假阴性。
2. 首次加载没有有效选中节点时，所有可见节点和标签保持可读：节点 opacity 为 1，文字使用主文字或次级文字颜色。
3. 默认选中节点只用于定位和详情，不得让 ECharts 自动把全图置于 blur 状态；优先将 `emphasis.focus` 改为 `none`，自行控制选中描边和相邻关系颜色。
4. 有效选中节点后，可以弱化非关联关系，但非关联节点文字不能降为不可读的浅灰；若确实需要弱化，节点和边的最低 opacity 分别不低于 0.72 和 0.45。
5. 只有 `selectedNodeId` 仍存在于当前可见节点集合时，才应用关联高亮；筛选后选中节点消失，应清理选中状态或自动选中第一个可见节点。
6. 选中节点使用 OSLab 主蓝描边，邻接边使用实线/虚线的既有语义；不要新增随机颜色。图例必须和节点、关系实际颜色一致。
7. 增加 `ResizeObserver` 或等价 resize 处理，在画布宽高变化后调用 `chart.resize()`；组件卸载时解除监听。resize 不应重新随机播种力导向布局。
8. 将当前只设置 center/zoom 的“适配/重置”按钮改成“重置视野”，或真正实现重新适配全部可见节点；按钮名称、提示和行为必须一致。
9. 图谱高度使用稳定的 `min-height`/`clamp`/布局约束，避免节点、标签和详情栏造成页面抖动。

#### C. 详情操作去重

涉及：

- `KnowledgeGraphView.vue` 详情模板、`PracticeEntry` 类型、`practiceEntries`、`hasQuestions`、`goPractice`、`goExperiment` 及只被它们使用的样式。

实施要求：

1. 删除详情中的“实践入口”区域。
2. 删除重复的“进入实验”“做题”按钮和相关的重复推荐项。
3. 详情区只保留一个主按钮“进入学习”，进入统一的节点学习工作台。
4. 继续保留掌握状态、最近证据、前置知识、后续知识、相关节点和学习建议；这些信息不能因删按钮而丢失。
5. 若实验或题目确实与节点相关，只在工作台的“题目练习”和“实践”页签中出现，不在图谱详情重复渲染。

### 5.3 验收清单

- [ ] 首次进入图谱，150 个节点（以当前数据为准）不再整体发白或模糊。
- [ ] 选中一个节点后，只有必要的关系弱化；节点文字仍可读。
- [ ] 搜索、章节筛选、状态筛选后，选中状态不残留到隐藏节点。
- [ ] 缩放窗口、折叠侧栏、切换详情时，图谱不裁切、不抖动、不出现空白画布。
- [ ] 详情只出现一个“进入学习”主入口。
- [ ] 1920×1080、1440×900、1024×768、390×844 手动截图通过。

### 5.4 反模式

- 不要把所有节点始终设置为低透明度来“突出重点”。
- 不要把 ECharts blur 的默认行为和业务高亮同时叠加。
- 不要通过新增右侧卡片、统计卡或大标题来填补外侧留白。
- 不要删除掌握度和学习证据，只因为删除了重复按钮。

## 6. 阶段 2：学习工作台增加“知识详解”

### 6.1 目标

在现有节点工作台中增加第四个页签“知识详解”，复用已经存在的静态 HTML 资源，不为每个节点重新制作讲义页面。

### 6.2 实施文件与做法

涉及：

- `NodeLearningWorkspaceView.vue`
- `learningResources.ts`
- `ResourcesView.vue`（只在需要抽取复用组件时修改）
- `learning.ts`（仅在现有接口无法表达状态时修改）

实施要求：

1. 将工作台页签扩展为“知识内容 / 知识详解 / 题目练习 / 实践”，页签顺序固定，URL 查询参数使用稳定的 `tab=resources`。
2. 取消把 `tab=resources` 静默改回 `learn` 的逻辑；未知 tab 才回退到默认页签。
3. 通过 `getResourcesForNode(nodeName)` 查询资源，不在组件中硬编码第二套资源表。
4. 现有两个资源直接复用：
   - `/resources/process-scheduling.html`
   - `/resources/syscall-concepts.html`
5. 资源页签首次打开时再加载 iframe；同一节点有多个资源时使用资源选择器或列表，不能把多个 iframe 同时堆在首屏。
6. 资源为空时显示明确的空状态和“查看学习资源”链接，不伪造内容、不显示空白 iframe。
7. 工作台正文中的“阅读材料”只保留摘要或跳转到“知识详解”；不能同一页面重复完整渲染相同 HTML。
8. 保持 `/resources` 学习资源总览页可用，两个入口必须指向同一份 HTML 内容。
9. 说明这类静态资料是学习内容，不自动伪造完成证据；掌握度仍由题目、实验和有效学习事件更新。

### 6.3 验收清单

- [ ] 四个页签可切换，刷新和复制 `?tab=resources` 链接后仍停留在“知识详解”。
- [ ] 进程调度节点能打开对应 HTML；系统调用节点能打开对应 HTML。
- [ ] 无资源节点显示空状态，不报错、不显示死 iframe。
- [ ] iframe 在资源页签首次打开时懒加载，切换页签不丢失工作台状态。
- [ ] 资源总览页与工作台的资源内容一致。
- [ ] 资源加载失败有可读错误提示和重试入口。

### 6.4 反模式

- 不要为 150 个节点新增 150 个静态页面。
- 不要将资源正文复制进组件字符串中，形成第三份内容。
- 不要把“知识详解”做成外链新窗口后就算完成；工作台内必须有稳定入口和加载状态。

## 15. 收尾判定

### 可以标记“本地可交付”的条件

- 阶段 1–7 的硬项全部完成。
- 前端构建无新增 error，后端目标测试通过。
- 图谱、工作台、实验页、全局助手、时间线和教师视图均有手动截图。
- 至少一条失败—补救—通过—掌握度变化链路可复现。
- 交付记录明确标注 Docker 和线上验证状态。

### 不能标记“方案全部完成”的条件

- 图谱仍处于默认不可读的模糊状态。
- 仍存在重复入口或“知识详解”无法通过工作台打开。
- 测评仍固定取前 50 条，或 Compile Error 会改变掌握度。
- Tutor 只返回泛化回答，没有当前用户证据和可执行下一步。
- 时间线只有表格/抽屉，没有图谱状态回放。
- 教师端仍只有列表，却继续对外宣称班级薄弱点图谱。
- 真实判题、外部依赖或线上部署尚未验证，却把 stub/本地构建当作生产完成。

最终交付必须回答三个问题：

1. 用户能否从图谱进入一个清晰、可解释、可操作的学习闭环？
2. 失败结果是否会以正确的证据、来源和下一步动作影响个人掌握度？
3. 这条链路是否有角色、接口、测试和截图证据，而不是只有演示数据？

只有三个问题都能用交付记录中的证据回答“是”，才结束本轮开发。
