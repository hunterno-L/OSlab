## 6. 协作原则

- 目录负责教学顺序，单元负责一次学习流程，知识节点负责概念与诊断；三者分别维护。
- 正文素材与题目都关联稳定 `nodeCode`；显示名称可以调整。
- 同一资源可以在多个单元中复用，单元编排不复制资源正文。
- 单元完成与节点掌握分别记录；观看演示不自动提高掌握度。
- 保留“数字孪生学习画像”：公共知识结构叠加个人概念／实践掌握、证据、变化历史和推荐；没有实践证据时显示未评估。
- 题目练习、算法模拟、编程实验保留三个可直接访问的独立入口，课程学习编排引用同一批资源。
- 优先做出一章可用样板，再逐章扩展；不设硬性开发日期。

## 7. 并行工作与文件交接

系统工程代码由 L 统一维护，包括前后端、数据库、导入工具、课程与图谱接口。J、A 负责教学内容和资源，不需要同时修改系统源码；A 维护的实验代码框架、参考实现与测试用例属于教学资源，仍由 A 整理并交付。

GitHub 不是三人协作的前提。L 独立管理系统版本；J、A 通过共享文件夹或压缩包交付 JSON、图片、代码／用例和说明。L 汇总到项目中并处理所有系统校验、导入、在线核对及发布。
