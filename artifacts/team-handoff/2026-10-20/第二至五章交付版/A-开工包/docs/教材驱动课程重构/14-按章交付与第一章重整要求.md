# 按章交付与第一章重整要求

> 历史阶段说明（2026-10-20）：本文件保留第一章重整要求；第一章现有成果不需重做。当前第二至五章任务、综合题及实验维护按 [19 文档](19-第二至五章交付任务.md) 执行。

更新：2026-10-17。适用于 J、A、L 及后续实施 agent。本文件取代此前“先交 1.1 小包，再逐节交接”的安排。

## 1. 当前决定

1. 正式资源交付、内容审核和学生验收均以一章为单位。当前范围为第一章“计算机系统概述”1.1—1.6，以及 1.7 本章疑难点／复习。
2. 不采用现有 1.1 成果。此前 `A-第一章-1.1与实验-001`、其退修版及相关 1.1 题目、解析和映射，不作为本章基础，不导入、不自动复用、不合并进新包。第一章中的 1.1 与其他内容一起重新依据教材整理。
3. 既有提交文件和审查记录仅是历史留档，不算有效交付。此次不删除原文件、不操作运行库；历史编程实验及学生提交继续保留，不能与作废的 1.1 内容包混为一谈。
4. 公共目录、预分配编号、JSON 协议、空白模板及系统工具继续使用。这些是协作基础，不是被放弃的 1.1 教学成果。

## 2. J：第一章知识包

从自己的《王道操作系统》教材重新整理完整第一章，提交：

```text
J-第一章-知识-001/
├─ knowledge.json
├─ assets/
└─ 交接说明.md
```

批次使用 `batch.j.overview.chapter.001`。一个知识包汇总本章节点、教学块和关系；正文仍按小节定位、按完整语义切块，不把整章塞进一个内容块。

交接说明按 1.1—1.7 列覆盖表，写明实际印刷页码、对应节点与教学块、图表、需要 L 确认的结构调整。没有独立正文或图表的部分据实说明，不为凑数量虚构材料。习题精选与答案解析不建成知识节点。

以共享词表为起点；节点定义、拆合和关系必须依据教材。编号变更及时告诉 L 和 A，不用为每次变更打包交付整份材料。正式交付时附本章最终节点代码清单和相对预分配表的变更说明。

## 3. A：第一章题目包

独立对照教材重新整理本章题目与解析，包括重新整理 1.1；不复制旧 1.1 JSON 后拼接剩余各节。提交：

```text
A-第一章-题目-001/
├─ questions.json
├─ assets/
└─ 交接说明.md
```

批次使用 `batch.a.overview.chapter.001`。原题号可以继续包含 `s1_1` 等节定位：实体编号表示题目来源，不表示按节交付，也不要求为本次重整而无意义改号。

以教材题为基础；自编题可以用于补足辨析与练习，但必须明确标记 `SELF_AUTHORED`，不得混作教材原题。不要沿用旧包的题目数量指标，也不要求每节凑齐四种题型。

交接说明按小节列教材题收录、改编、自编和未纳入题目数量，注明不支持的题型及处理建议；列出答案复核、节点覆盖和单元用途。仅有题面而没有可靠答案的题不能伪装成已完成题目。

J 尚未交付时，A 使用 L 预分配编号继续工作。缺节点、拆合或归属疑问集中列出，不等 J 完成才录题；正式导入前由 L 结合 J 的最终节点核对 A 的引用。

## 4. 历史编程实验单独交付

已有编程实验仍由 A 持续维护，但不与每章题目重复打包。按实际完成的维护范围另交：

```text
A-实验维护-001/
├─ experiment-maintenance.json
├─ experiment-files/
├─ assets/
└─ 交接说明.md
```

使用独立批次 `batch.a.experiments.001`，后续按维护批次递增。保留原 `questionId`、学生历史及独立实验入口。需要重新核实旧 1.1 混合包中的实验盘点或候选映射时，依据原实验快照与实际材料重审，不直接把旧结论视为已确认成果。

不要求每次重做全部 48 项盘点，不要求所有历史实验先修完才交付第一章。第一章没有合适编程实验时，可以使用阅读、例子和题目完成学习；需要纳入本章的实验单独验证后由 L 引用。

## 5. 并行与正式接收

| 成员 | 过程中的工作 | 正式交付 |
| --- | --- | --- |
| J | 按小节整理正文；发现编号变更就通知 L/A | 整章知识包 |
| A | 按小节录题与复核；整理候选映射；实验维护另行推进 | 整章题目包，另交实验维护包 |
| L | 维护公共编号与系统；回答材料和结构问题 | 核对整章覆盖、汇总映射、导入、编排与学生验收 |

J 与 A 可以独立交出各自的整章包，不必同一时刻完成；L 先审核已收到的整章包。零散问题、编号清单和格式示例可以在过程中沟通，但不作为正式交付或已完成章节统计。

L 接收顺序：整章覆盖与来源 → J 的节点及编号变更 → A 的题目映射 → 知识与题目草稿导入 → 十个候选单元的活动编排 → 发布所需内容 → 完整学生路径验收。接口上传大小或条数限制由 L 在导入环节分批处理，不反过来要求成员逐节交付。

内部可以分次导入或逐单元检查，但第一章只有在从 1.1 到章末的内容、练习、反馈、继续位置和本章复习连贯可用后才算正式交付。数字孪生画像、节点工作台及题目／算法模拟／编程实验三个独立入口继续保留。

## 6. 修订与下一章

每次正式交付或集中返修后，J 执行 [J 审查流程](15-J交付前审查流程.md)，A 执行 [A 审查流程](16-A交付前审查流程.md)。先检查并修改实际资源，再复查，随包提交简短真实的自审记录，可独立成文件或放在交接说明中。

第一章包有内容问题时，在原章包中修订并标明版本与改动；沿用稳定实体编号，不再拆成逐节退修包。接收通过后，再按相同规则交付第二章及后续章节。

正式交付目录只放本章实际资源。旧 1.1 包、协议样例、其他章样板、完整实验快照和未修订实验不混进本章完成统计。
