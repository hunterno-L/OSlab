# 综合应用题：A 的整理格式与自审要求

更新：2026-10-20。用于第二至五章完整题目交付。当前平台只自动判分 SINGLE／MULTIPLE／JUDGE／FILL_BLANK；本文规定新增的**资源整理协议**，不是现行导入接口。

## 1. 文件与题号

在同一章题目包中增加 `application-questions.json`，协议为 `oslab-application-authoring/1.0`，`packageType=APPLICATION_QUESTIONS`。批次用 `batch.a.process.chapter.001.application` 等；contributor=A，courseCode=course.operating-systems。

questions 数组中每项代表一道完整教材大题，type 固定 `COMPREHENSIVE`。简答、计算、证明、画图或伪代码等由各小问的 responseType 区分；只有一问也使用一个 parts 元素。不要人为把一道多问题分散成无共同条件的多道题。

原题号保留在 sourceQuestionNumber。代码示例 `q.wd25.s2_4.app.001`：app 区别于同节重新编号的选择题；不是另一道教材题。拆分题面或变更条件时按 ADAPTED，并写清变更。

## 2. 完整形状

可复制开工包 `reference/samples/application-questions.sample.json`；样例是自编格式演示，不计教材题收录。

| 层级／字段 | 要求 |
| --- | --- |
| questionCode、title | 稳定题号；标题不提前揭示答案 |
| contentMd | 公共题干、全部条件、符号和材料，支持 Markdown 表格与数学式 |
| type | COMPREHENSIVE |
| sectionCode、sourceRef | 题面出处，格式沿用协作规范 |
| answerSourceRef | 答案出处；自行推导时明确 SELF_AUTHORED 和实际依据，不能伪称教材答案 |
| difficulty | 1—5 |
| maxScore | 建议总分，大于 0；原书有分值则保留，原书没有则在交接说明标为建议 |
| nodeMappings | 整题考查节点，至少一个 PRIMARY；不是把全部背景名词都挂入 |
| usageSuggestions | `[{unitCode,usage:PRACTICE|ASSESSMENT|REVIEW}]`，可引用 J 的本章候选单元 |
| parts | 有序小问数组，至少一项 |
| assets | `[{path,caption,sourceRef}]`；题面和答案图分开引用，路径相对整包 |

每个小问：

| 字段 | 要求 |
| --- | --- |
| partCode | 稳定小问代码，如 q.wd25.s2_4.app.001.p1 |
| promptMd | 小问完整要求，不在这里写解答 |
| responseType | SHORT_ANSWER／CALCULATION／PROOF／DRAWING／PSEUDOCODE／MIXED |
| answerMd | 完整参考解，包含关键过程、结论和必要图表 |
| maxScore | 本小问建议分值；全部小问之和等于整题总分 |
| nodeMappings | 本小问真正能验证的节点，至少一个 PRIMARY |
| rubric | 分步评分点数组；每项 rubricCode、description、points、nodeCodes |
| commonErrors | 具体常见错误及原因的字符串数组，可为空 |
| acceptableAlternatives | 合理等价答案／其他方法及判定条件的字符串数组，可为空 |

每小问 rubric.points 相加等于该问 maxScore。评分点写可观察的成果，如“正确求出 Need 矩阵”“给出并验证一条安全序列”，不写“理解充分得满分”。nodeCodes 必须属于该问的考查映射。

评分点分值是**评分建议**；nodeMappings.weight 是画像影响建议，两者不互相替代。自评、参考答案阅读、教师评阅和可靠自动判分是不同证据；A 负责资料和建议，不宣称系统已实施主观自动判分。

## 3. 综合应用题怎么整理

以用户提供的死锁章节截图为例，只说明整理方法，不猜测截断的后续表格：

- 共用资源表、进程编号、资源总量、Max／Allocation／Request 全部抄准，跨页表格拼齐再解题。
- 按原题小问保留“是否安全／安全序列／请求能否满足／是否死锁”等不同任务；安全与死锁不能混为一个是非题。
- 银行家题保留 Available、Need、Work 的计算过程；多条安全序列时给出判定规则，不把参考解的一条序列当唯一字符串答案。
- 同步互斥题明确共享量、初值、P/V 操作、代码边界及设计理由；算法设计题保留伪代码和正确性说明。
- 作图题有清楚的参考图及文字解释；计算题标单位、舍入和边界；证明题列假设与论证链。

## 4. A 交付前的额外自审

1. 不看答案独立解完整道题，再按各小问与教材解析核对；对所有数值、表格、进程号和否定词回查原页。
2. 对每个评分点检查“学生怎样做才得分”；总分、分问分值与评分点精确相加一致。
3. 验证合理替代方法，确认没有把“一个答案”误当“唯一答案”。下游小问依赖前问时说明中间结果错误的评分建议。
4. 核对每问的考查节点，避免整题一错就把所有节点判薄弱。
5. 打开所有题面、答案图片并检查跨页连续性；答案图片不放进学生题干。
6. 在整章收录表分别统计选择题题号组与综合应用题题号组，不能用选择题数量代表整章题目齐全。

教材有明确答案且可自行核对的问题由 A 修好；只有确实无法定论的争议留给 L，并附原页、自己的推导和推荐处理。材料整理不以平台尚未实现评阅为由等待。
