# 成员 A：题目与编程实验资源包整理指南

更新：2026-10-17。参考《王道操作系统》。本指南可单独交给 A 执行，字段详解见 [协作数据规范](05-协作数据规范.md)，实验专项工作见 [编程实验维护与映射指南](07-成员A编程实验维护与映射指南.md)。

## 1. 你的职责

负责补充题目，准确整理题干、选项、答案、解析、常见误区、教材定位和考查节点，提交完整题目资源包给 L。

同时负责已有编程实验的内容、输入输出样例、参考解和用例维护，填写实验与新知识节点、学习单元的映射，作为实验维护包提交。保留原实验 ID；正式修改、导入、判题联调和发布由 L 执行。

数据库与题目判分结构由L设计。你可以提出缺少题型、节点或练习顺序的建议，不需要编写建表 SQL、手动生成数据库 ID，也不需要修改学生历史记录。

当前优先交付第一章“计算机系统概述”整章的配套题目，并盘点已有编程实验中与该章相关的任务。先从 1.1 对应题目和答案开始，后续按节交付。数量服从知识覆盖和题目质量，不要求给每个节点机械凑固定题数。

已有 [页面置换题目包](../../content/operating-systems/wangdao-2025/questions/a-memory-page-replacement-001.json)：8 道教材题改编（原题号 43—50）和 14 道自编巩固题，四种题型齐全，保留作后续内容与协议样板。41、42 题缺少对应答案，51 题缺少题面，继续保留在该批待补清单。

## 2. 开始前拿到什么

- 自己持有教材中的题目及对应解析，保留完整题号与条件。
- J 与L共同维护的节点词表。
- 当前课程目录、单元草案及题目包样例。
- A 开工包中的题目模板、实验维护模板、现有实验快照和编号清单。

无需平台账号、数据库或导入工具。你只整理文件并提交；L 校验、导入、在线作答与判题复核。现有实验快照已随开工包提供，先盘点资料和修订内容即可，不必等待系统改造。

直接使用 shared/overview-authoring.json 和共享词表中的编号，不需要等待节点入库。缺少的节点／单元写入建议清单，L 汇总确认；正式导入顺序由 L 处理。

## 3. 题目类型与实际判分

第一批使用现有四种客观题型，不需要同时开展主观题判分建设。

| 类型代码 | 含义 | 标准答案格式 | 判分方式 |
| --- | --- | --- | --- |
| `JUDGE` | 判断 | `"true"` 或 `"false"` | 正确／错误匹配 |
| `SINGLE` | 单选 | `"B"` | 选项代码精确匹配 |
| `MULTIPLE` | 多选 | `["A","C"]` | 集合完全相同，当前无部分得分 |
| `FILL_BLANK` | 单空填空 | `["LRU","最近最久未使用"]` | 一个输入命中任一可接受表述 |

填空答案数组表示同一个空的多个可接受写法，不表示多个空。多空原题可以拆成独立单空题，保留共同题组编号和各空序号；需要整体多空判分时交L设计，不把它塞入现有数组格式。

简答、证明、作图和复杂公式题可以另列候选材料，不能当作现有系统已经支持的自动判分题。

## 4. 每道题需要整理哪些内容

| 字段 | 说明 |
| --- | --- |
| `questionCode` | 稳定外部题号；修正后仍使用同一个代码 |
| `title` | 简短、具体，如“LRU 命中后的顺序更新” |
| `content` | 完整题干，支持 Markdown 与图片 |
| `type`、`options`、`answer` | 正确且一致的题型、选项、标准答案 |
| `analysis` | 说明原因，计算题保留关键推演；选择题解释易混选项 |
| `misconception` | 这道题对应的具体误区，避免只写“理解不牢” |
| `difficulty` | 1—5，依次为识记、基础理解、应用、综合、较难综合 |
| `sectionCode` | 教材目录定位，不是随意填写的章节字符串 |
| `sourceRef` | 资源号、版本、印刷页码、原题号与来源类型 |
| `nodeMappings` | 实际考查的知识节点、主次和模型影响权重 |
| `usageSuggestions` | 建议用于哪些单元，属于练习、测评还是复习 |

题目应有至少一个明确的主考查节点。某术语仅用于描述背景时，不把它标成考查节点；答错一道 LRU 题不能同时认定所有内存管理知识都薄弱。

## 5. 稳定题号与出处

推荐原题代码：`q.wd25.s3_2.017`，其中 `017` 是教材中确认的题号。原题拆分或改编时加明确后缀，如 `.b1`、`.adapt1`，并记录原题号。

自编题使用 `q.self.lru.001` 一类编号，不冒用教材原题号。编号一旦发布，不因排序、题干改写或显示标题改变。

同一道教材题在不同单元中使用，只创建一个题目，单元另行引用。如果教材不同版本题号相同但内容不同，需要按版本区分题目来源及代码。

来源类型：`TEXTBOOK`（原题）、`ADAPTED`（改编）、`SELF_AUTHORED`（自编）。本交接包的样例是 `SELF_AUTHORED_SAMPLE`，用于说明格式，不是已经整理的教材题目。

多空拆题保留共同 `sourceQuestionNumber`、`parentQuestionCode` 和 `partIndex`。L在导入时保留题组信息。

## 6. 答案与解析核对

### 判断题

使用含义明确的陈述句。避免把“是否需要更新？”这样的问句配上 true／false 后产生语义歧义。解析必须说明判断依据。

### 单选与多选

选项代码统一大写 A、B、C、D，可继续扩展。单选答案必须是字符串，不能写 `["B"]`。多选答案不能有重复项，解析检查每个正确项与关键错误项。

题干写明选择一个还是多个；题干、选项和答案的否定词要逐一对照原材料。

### 填空题

题干只留一个答案位置，可接受别名逐个列出。系统会处理大小写、首尾及连续空白，不自动理解同义词、全半角、标点或公式等价；需要接受的写法明确列入答案。

数值题应明确单位及精度，首批使用确定的标准字符串。需要误差范围时提出判分需求，不把任意近似值都视作系统会自动接受。

### 算法题

保留页框数、访问序列、初始状态，或进程到达时间、服务时间、时间片等条件。涉及 SCAN/C-SCAN 时保留初始方向、磁道范围及回程统计约定。

可以利用算法演示辅助核对，但演示源码本身也需要标准案例验证；出现教材与演示结果不一致时，记录完整条件交L复核。

## 7. 知识节点与单元用途

`nodeMappings` 回答“这道题能验证哪个知识”；`usageSuggestions` 回答“建议放到哪里练”。两者分别填写。

例：一道“命中后是否更新访问顺序”的题，主节点是 `os.memory.lru`，可建议放在 LRU 单元的随堂练习，以及页面置换比较单元的复习。

初始主节点权重 1.0；确实能观察到的次要节点可建议 0.3。权重是掌握度影响强度，不是得分比例。没有清楚次节点时只填写主节点，L审核后采用。

不把主节点自动扩展到它的所有祖先和前置节点。活动／单元的知识列表也不能直接复制成题目的考查映射。

推荐文件：


复制 [题目包样例](../../content/operating-systems/wangdao-2025/samples/questions.sample.json)，保留包结构，替换题目内容与真实来源。通常每批 20—50 道便于核对；现有旧导入单次上限为 100，新版首期也采用这一上限。

从 A 开工包复制 work/ 模板，填写 questions.json 和 experiment-maintenance.json，补齐 assets/、experiment-files/ 与交接说明。把整个 work/ 文件夹压缩提交给 L 即可。

修订沿用同一 questionCode，不新建另一份相同题目。L 负责校验、编号确认、导入及保存代码—系统 ID 对应，并把需要修正的具体条目反馈给你。

已经发布的题目再次修订时，新内容先进入修订草稿，经L审核发布后生效；没有变化的包不生成新版本。不要通过换题号重新创建同一道题来绕过修订。

现有审核流由 L 在系统中执行。contributor 记录 A 的材料整理身份，导入操作者按 L 的实际账号记录，不需要给 A 配置管理账号或代替 A 登录。

## 9. 当前旧导入格式：只供 L 对接参考

目前 `/teaching/assessments` 的导入框接受 JSON 数组，只有 `title/content/type/options/answer/analysis/misconception/chapter/difficulty/nodeNames`。

接口为 `POST /api/learning/questions/import/preview` 与 `/import/commit`，前端自动把数组文本包装到 `content` 字段。导入只创建草稿，节点名称必须已存在。

旧接口不保存稳定题号、教材出处、单元用途或权重，也不会去重。A 按新版模板交包即可，不需要适配或操作旧导入界面；L 负责对接和运行校验。

## 10. 编程实验维护与映射：由 A 负责

A 逐项盘点现有实验快照，检查题面、原始代码／代码框架、样例、参考实现、测试数据和知识标签。修正写入 contentChanges 和配套文件，不直接修改运行库。需要改变判题契约时记录原因交 L 确认；不要仅为改名或重挂节点分配新的实验 ID。

每个实验分别整理：① `questionId` 与稳定 `resourceCode`；② 真正考查的新 `nodeCode`、主次角色和权重；③ 适用 `unitCode`、必需／可选及完成条件；④ 维护及运行核对结果。节点与单元映射是两项交付，不用旧标签或同章归属代替。

已有节点直接复用代码；确实缺少节点时向 J 提交候选与依据。A 在资源包中填写节点／单元关联，L 保存正式映射并确认课程顺序和发布。详细字段与例子见 [实验专项指南](07-成员A编程实验维护与映射指南.md)。

实验与测评题分表，不把代码题当成填空题导入。语言运行环境、判题服务器、数据库及映射接口由 L 维护；A 负责实验内容、验证材料与映射文件。

## 11. 复核与交接

每批完成后检查：

- 题面、答案、解析和原题号一致，图片完整。
- 四类答案结构正确，填空别名与多空区别已核对。
- 主考查节点存在，背景知识没有被误标为考查对象。
- 原题／改编／自编标记清楚，没有重复题目代码。
- 题目资源包、图片与交接说明完整，待确认的编号或答案已列清楚。
- 解析与答案自行复核，提供需要 L 在线验证的具体案例。
- 已有编程实验完成盘点，已维护项与待处理项清楚，保留原 ID。
- 实验到新节点、实验到学习单元的映射分别齐全；无合适单元的实验标明后续归属。

交接说明列出题目与实验覆盖的节点、题型分布、实验修订、已有运行结果、单元映射及待补内容。未运行的如实记录。A 提交文件，L 负责系统校验、导入、在线验收与发布。
