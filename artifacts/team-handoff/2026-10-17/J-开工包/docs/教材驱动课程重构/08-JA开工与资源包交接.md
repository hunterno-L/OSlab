## 3. J 的第一批任务

1. 阅读包内 J 指南，使用 shared/overview-authoring.json 中的第一章编号。
2. 按 1.1.1—1.1.3 整理概念、特征、目标与功能。定义、完整解释、图表和情境例子按语义切割；不要固定字数截断。
3. 在 work/knowledge.json 填节点、教学块和候选关系；图片放 work/assets/，路径写成 assets/文件名。
4. 关系写明依据与出处；REQUIRES 保存“后学→前置”。不能仅因同页出现就建边。
5. 在交接说明中列新增编号、拆合建议、待确认原文，以及给 A 的可用节点代码。

已预分配的代码可直接用于整理，不需要等入库。新增确切知识不在清单中时可以提出新代码，在交接说明列出，由 L 汇总到正式词表。

## 4. A 的第一批任务

1. 阅读题目指南和实验专项指南，熟悉四类答案结构。
2. 有教材时整理 1.1 配套题及答案解析到 work/questions.json，逐项标注考查节点，填写建议单元。
3. 从 reference/experiments/实验清单.md 逐项盘点已有实验。当前仓库快照有 48 项，每项按 questionId 单独保存，含题面及原有代码／参考解／用例／配置；缺少字段已标记待补。
4. 把已核对或已修订实验写入 work/experiment-maintenance.json；代码和用例修订文件放 work/experiment-files/。
5. 分别填写实验—节点和实验—单元映射。没有适用第一章单元时保留后续教材归属建议，不把所有实验强挂到概述章。

实验包使用仓库 SQL 快照，并非当前运行库。A 依据该资料整理，L 在正式导入前与当前记录核对。快照中用例可能是占位数据，原始资料也未运行验证；把确定的错误、缺文件和环境依赖记录在交接说明。

有条件时 A 可以本地验证参考解和用例；没有运行环境时交文件和预期结果即可，由 L 完成在线验证。无需为完成资源包自行搭建沙箱。

## 5. 交回什么

J 的提交：

```text

├─ knowledge.json
├─ assets/
└─ 交接说明.md
```

A 的提交：

```text
A-第一章-1.1与实验-001/
├─ questions.json
├─ experiment-maintenance.json
├─ assets/
```

把 work/ 整个文件夹重命名或压缩后发给 L。某批只交题目或只交实验也可以，在交接说明注明；不需要每次把全部实验重新整理一遍。修订沿用原 nodeCode、chunkCode、questionCode 与 questionId。

assets/ 和 experiment-files/ 路径相对交回文件夹根目录。不要填写自己电脑的绝对路径。shared/、reference/ 和工程源代码无需重复交回。

## 7. L 的接包核对

接收时先打开交接说明，确认本批范围、文件和待确认项，再按正式词表检查引用。空模板不能当作完成包；每批只校验本批交付内容，避免未做的实验或样例混入统计。

开工包提供可选离线文件检查命令，仅依赖 Node.js；J、A 不必运行，L 可以代查：

```powershell
node tools/check-member-package.mjs .
```

在解压后的开工包根目录执行，work/ 放提交文件。它检查 JSON、节点／单元引用、答案形状和附件；未确认的候选编号先写入交接说明，由 L 更新 shared/ 后再校验。该命令不写数据库，也不代替教材和运行核对。

交接包通过后，L 将成员文件归档到 content 协作目录，再依次导入知识、题目、实验修订与映射，最后编排单元。不需要等 J 和 A 整章全部完成，1.1 的小批材料就能进入联调。
