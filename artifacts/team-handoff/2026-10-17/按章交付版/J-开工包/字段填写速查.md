# 第一章资源包字段填写速查

这是格式说明，示例内容为自编协议样例。正式工作请用自己教材整理的实际内容与出处，不能把示例直接算作教材收录成果。

正式交付以章为单位：J 的 work/ 是整章知识包，A 的 work/ 是整章题目包，A 的 experiment-work/ 是独立实验维护包。现有 1.1 成果不采用，第一章全部重新整理；公共预分配编号可继续使用。内部按小节制作不等于逐节交付。

## 1. J：一个节点与一个教学块

把以下形状分别放入 knowledge.json 的 nodes 和 chunks 数组，替换文字和来源。第一章可用代码见 shared/overview-authoring.json。

```json
{
  "nodeCode": "os.overview.concurrency",
  "name": "并发",
  "nodeType": "CONCEPT",
  "layer": "CORE",
  "description": "多个程序在同一时间间隔内交替推进。",
  "aliases": [],
  "homeSectionCode": "sec.overview.basic-concepts",
  "sourceRefs": [
    {"sourceCode":"sample.oslab","origin":"SELF_AUTHORED_SAMPLE","sectionCode":"sec.overview.basic-concepts","pageStart":null,"pageEnd":null,"locator":"自编字段示例，正式提交时替换为实际教材出处","sourceQuestionNumber":null}
  ]
}
```

```json
{
  "chunkCode": "chunk.wd25.overview.concurrency.001",
  "sectionCode": "sec.overview.basic-concepts",
  "title": "区分并发与并行",
  "chunkType": "EXPLANATION",
  "contentMd": "并发强调同一时间间隔内多个任务都在推进；并行强调同一时刻多个任务同时执行。\n\n这里是自编格式示例，实际讲解与情境应按教材整理。",
  "nodeCodes": ["os.overview.concurrency", "os.overview.parallelism"],
  "sourceRef": {"sourceCode":"sample.oslab","origin":"SELF_AUTHORED_SAMPLE","sectionCode":"sec.overview.basic-concepts","pageStart":null,"pageEnd":null,"locator":"自编字段示例","sourceQuestionNumber":null},
  "assets": []
}
```

第一章常用 chunkType：DEFINITION 定义、EXPLANATION 解释、WORKED_EXAMPLE 完整例子、FIGURE 图表、SUMMARY 小结。概念单元不必使用 ALGORITHM。

关系例子：CONTRASTS_WITH 保存两端代码字典序排列的一条关系；REQUIRES 保存“后学→前置”。每条关系都要写 reason 和 sourceRef。

## 2. A：四种答案结构

共同字段包含 questionCode、title、content、type、options、answer、analysis、misconception、difficulty、sectionCode、sourceRef、nodeMappings、usageSuggestions、parentQuestionCode、partIndex。完整可复制题形在 reference/samples/questions.sample.json。

| 题型 | options | answer |
| --- | --- | --- |
| JUDGE | `[]` | `"true"` 或 `"false"`，字符串 |
| SINGLE | `[{"key":"A","value":"选项内容"},{"key":"B","value":"选项内容"}]` | `"B"` |
| MULTIPLE | 同单选结构 | `["A","C"]`，完全正确的选项集合 |
| FILL_BLANK | `[]` | `["内核态","管态"]`，同一个空的可接受写法 |

填空数组不表示多空。parentQuestionCode／partIndex 未拆题时均为 null；确实拆题时保留共同来源题号并填写正整数 partIndex。

第一章教材题号应在对应节的范围内记录，如 `q.wd25.s1_1.001`。这里的001只是编号规则示范，实际按书上题号填写。自编题用 `q.self.overview.<语义编号>`，不要冒用教材题号。

节点考查例子：

```json
{
  "nodeMappings": [
    {"nodeCode":"os.overview.concurrency","role":"PRIMARY","weight":1.0},
    {"nodeCode":"os.overview.parallelism","role":"SECONDARY","weight":0.3}
  ],
  "usageSuggestions": [
    {"unitCode":"unit.overview.basic-concepts","usage":"PRACTICE"}
  ]
}
```

主节点表示真正考查的知识，不按题干提到的所有术语扩大映射。usage 使用 PRACTICE／ASSESSMENT／REVIEW，最后排序由 L 处理。

## 3. 实际教材出处

正式教材整理使用以下 sourceRef，替换为实际页码、标题与题号：

```json
{
  "sourceCode": "book.wangdao.os.2025",
  "origin": "ADAPTED",
  "sectionCode": "sec.overview.basic-concepts",
  "pageStart": 2,
  "pageEnd": 2,
  "pageStatus": "VISIBLE",
  "locator": "1.1.2 对应段落或实际题号，按自己教材填写",
  "sourceQuestionNumber": null
}
```

该页码仅演示字段，不能作为未核对材料的实际出处。原文／原题使用 TEXTBOOK，教学改写／改编使用 ADAPTED，自编内容使用 self.oslab／SELF_AUTHORED。整本教材不必重复扫描；出现图表或需要对照核实的段落时附必要图片，题号和页码保留即可。

图片路径如 `assets/wd25-p0002-fig01.png`，章节图片放在 work/assets/。块内 assets 对象有 path、caption 和 sourceRef；Markdown 可写 `![图说明](assets/wd25-p0002-fig01.png)`。自编题的 pageStatus 可以省略，不使用未定义的 NOT_APPLICABLE。

## 4. A：实验修订文件

在独立 experiment-work/experiment-maintenance.json 的 experiments 数组中，每个记录保留原 questionId（字符串）和资源代码。reference/experiments/inventory.json 已提供原 ID，不要自行编造。修订文件放 experiment-work/experiment-files/，交付时将 experiment-work/ 重命名为 `A-实验维护-001`，内部相对路径仍为 experiment-files/…。

contentChanges 每项用 field、file、reason：

```json
{
  "contentChanges": [
    {"field":"content","file":"experiment-files/原实验ID/题面.md","reason":"补充完整输入输出要求"},
    {"field":"originalCode","file":"experiment-files/原实验ID/starter.c","reason":"修正代码框架"},
    {"field":"answer","file":"experiment-files/原实验ID/reference.c","reason":"补充参考实现"},
    {"field":"judgeCase","file":"experiment-files/原实验ID/judge-cases.json","reason":"替换占位用例并覆盖边界"}
  ]
}
```

纯文字和代码文件按原格式保存。judgeCase 文件用 `[{"input":"...","output":"..."}]`；judgeConfig 文件保留原项目结构。原快照中的 referenceAnswer 对应修订字段 answer。每项只填写确实修改的字段，未修改字段不必重抄。

实验节点映射和单元映射分别填写。暂时没有合适单元时，unitMappings 可以为空，并在 unitProposals 或交接说明中写后续教材位置；实验本身仍保留独立入口。

## 5. 交包前

打开图片和修订代码，核对题号与答案；确认 JSON 引号、逗号与数组结构正确。整章包按 1.1—1.7 填写覆盖表，教材题／改编／自编数量分别统计；不复制或合并旧 1.1 成果。不要在 JSON 中插入注释。缺少的节点、单元或不确定原文写进交接说明即可，L 负责最终机器校验及导入。
