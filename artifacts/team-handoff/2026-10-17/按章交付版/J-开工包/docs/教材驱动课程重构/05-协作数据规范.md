# 教材内容、节点、题目与学习单元协作数据规范

协议版本：`oslab-authoring/1.0`，更新：2026-10-17。面向 J、A、L及导入工具实施 agent。样例位于 [内容协作目录](../../content/operating-systems/wangdao-2025/README.md)。实验维护文件使用第 11 节的单独协议，避免与测评题导入格式混用。

这是新版文件契约，不是当前旧接口的请求格式。文件采用 UTF-8 JSON，正文使用 Markdown。数据库 ID、Neo4j 内部 ID、审核人、实际发布状态由系统生成，成员不手填。

## 1. 统一编号

| 对象 | 示例 | 规则 |
| --- | --- | --- |
| 课程 | `course.operating-systems` | 不随教材年份或课程标题改变 |
| 教材来源 | `book.wangdao.os.2025` | 实际使用版本确认后固定；不同版本分别登记 |
| 目录 | `sec.memory.page-replacement` | 语义编号；展示节号另存 textbookNumber |
| 知识节点 | `os.memory.lru` | 不随改名、目录移动改变 |
| 教学块 | `chunk.wd25.memory.lru.rule.001` | 同一块修订沿用代码；协议自编示例用 chunk.sample 前缀 |
| 题目 | `q.wd25.s3_2.017` | 实际题号确认后分配；拆题加 b1 等后缀 |
| 单元 | `unit.memory.lru` | 单元编排编号，由L维护 |
| 活动 | `act.memory.lru.read` | L维护；移序沿用代码，替换教学任务才换代码 |
| 演示资源 | `demo.page.lru` | 区分 CPU、磁盘、内存算法 |
| 编程实验资源 | `exp.legacy.<questionId>` | 对应现有实验，保留原 questionId；已分配语义代码的沿用 |
| 批次 | `batch.j.overview.chapter.001` | 一次整章交付编号；实验维护独立编号，不能用于实体去重 |

代码仅用小写英文字母、数字、点、连字符、下划线，首字符为字母。不含空格、中文或斜杠。节点名称可使用中文，别名可包含英文缩写。现有代码目录里的文件名不需要按此改名。

正式交付按章汇总，第一章使用 `batch.j.overview.chapter.001`、`batch.a.overview.chapter.001`；历史实验维护单独使用 `batch.a.experiments.001`。题目代码中的 `s1_1` 仍表示教材来源位置，不是小节交付批次。现有 1.1 成果不采用，完整接收规则见 [按章交付与第一章重整要求](14-按章交付与第一章重整要求.md)。

共享目录和词表位于 `catalog/sections.json`、`catalog/nodes.json`。新增代码交L确认后登记。`nodes.json` 当前是设计词表草案，不代表全部节点已在数据库存在。

目录 `sectionType` 使用 CHAPTER / CONTENT：CHAPTER 为顶层章，CONTENT 为正文目录项，CONTENT 仍可拥有子项。目录可继续细分，不用类别字段表示树深度。

## 2. 包级字段

知识包、题目包、单元包均使用对象包装：

```json
{
  "schemaVersion": "oslab-authoring/1.0",
  "packageType": "KNOWLEDGE",
  "batchCode": "batch.j.memory.001",
  "contributor": "J",
  "courseCode": "course.operating-systems",
  "nodes": [],
  "chunks": [],
  "relations": []
}
```

`packageType` 为 KNOWLEDGE / QUESTIONS / UNITS。知识包包含 nodes、chunks、relations；题目包包含 questions；单元包包含 units。`contributor` 是材料整理成员，不替代平台登录用户或作者权限。

## 3. 出处 sourceRef

```json
{
  "sourceCode": "book.wangdao.os.2025",
  "origin": "TEXTBOOK",
  "sectionCode": "sec.memory.page-replacement",
  "pageStart": 217,
  "pageEnd": 219,
  "locator": "示意定位；正式材料替换为准确标题、图号或段落",
  "sourceQuestionNumber": null
}
```

此片段仅说明字段，页码范围参考目录，不是对某个实际正文块的引用。正式材料以印刷页码、实际标题边界和原题号填写。

| 字段 | 内容 |
| --- | --- |
| sourceCode | 在 sources.json 中登记的教材、演示项目或自编素材来源 |
| origin | TEXTBOOK 原文／原题、ADAPTED 改写／改编、SELF_AUTHORED 自编、SELF_AUTHORED_SAMPLE 协议示例、EXTERNAL_DEMO 授权演示、TOC 目录截图 |
| sectionCode | 教材中的目录定位；不要求出处所属章节等同所有考查节点主章节 |
| pageStart / pageEnd | 教材印刷页码，正整数且结束不早于开始；没有页码的自编或软件资源填 null |
| pageStatus | VISIBLE：图中可见；INFERRED：按目录和连续正文推定；NOT_VISIBLE：截图未含页码；自编材料可省略 |
| sourceAsset / answerAsset | 可选，指向收到的原始截图；答案另页时记录 answerAsset |
| locator | 定位说明，如图号、例题标题、原目录路径、源代码文件 |
| sourceQuestionNumber | 原题题号；正文和自编内容填 null，不能编造教材题号 |

TEXTBOOK 和 ADAPTED 材料优先记录准确页码及 locator。若题目截图没有页码，可以明确填写 pageStart/pageEnd=null、pageStatus=NOT_VISIBLE，同时提供 sourceAsset、原题号和 locator；不为了满足格式编造页码。已知范围但页码由连续正文推定时标为 INFERRED。节点可以通过 sourceRefs 数组保存多个出处。没有收到对应正文时，节点草案可以使用 TOC 表示目录依据，但不能宣称已有正文支撑。

教材版本登记在 sources.json。此次收到的印刷页 220 页眉已确认正文为 2025 年版；具体印次未核对。其他年份正文使用不同来源编号，不能只改显示名称而把不同版本正文混为一份。

## 4. 知识节点

| 字段 | 必填与含义 |
| --- | --- |
| nodeCode | 必填，稳定身份 |
| name | 必填，学生看到的名称 |
| nodeType | 必填，CONCEPT / ALGORITHM / MECHANISM / IMPLEMENTATION |
| description | 必填，简短概念说明，不代替教材正文 |
| aliases | 数组，可以为空；同义名称和缩写 |
| homeSectionCode | 必填，主要教材位置；其他单元通过关联引用 |
| sourceRefs | 数组，保留一个或多个出处 |
| layer | CORE / IMPLEMENTATION；初学图谱默认 CORE |

`layer` 控制图谱展开范围，`nodeType` 控制语义类别。实现节点不能因为与基础知识同章就自动出现在初学主线。

词表中的 legacyNameHints 仅辅助旧名称人工对照，不是已确认的旧数据映射。尤其两个 FCFS 不按缩写合并。

## 5. 教学块

| 字段 | 含义 |
| --- | --- |
| chunkCode | 稳定块代码 |
| sectionCode | 所属目录 |
| title | 具体内容标题 |
| chunkType | DEFINITION / EXPLANATION / ALGORITHM / WORKED_EXAMPLE / FIGURE / SUMMARY |
| contentMd | 完整 Markdown 内容；公式、条件和表格保留 |
| nodeCodes | 实际解释的知识代码，至少一项 |
| sourceRef | 完整出处 |
| assets | 图片等附件对象数组；无附件用 [] |

附件对象字段：path、caption、sourceRef。`path` 从内容协作根目录计算，例如 `assets/page-replacement/p0218-lru-table-01.png`。正文中使用同一路径，导入服务统一解析为可访问资源。J 不需要自己构造服务器 URL。

完整例题必须保留条件和结论。AI 检索片段由系统生成，不另要求 J 填 token 数、向量或检索 chunk。

## 6. 关系

关系对象字段：fromNodeCode、toNodeCode、relationType、reason、sourceRef。

| 代码 | 存储方向 | 路径用途 |
| --- | --- | --- |
| REQUIRES | 后学 A → 前置 B | 单独用于前置排序 |
| CONTAINS | 父类 A → 子项 B | 分类展开 |
| CONTRASTS_WITH | 无方向，两端代码字典序保存 | 对比学习 |
| BASED_ON | 算法／机制 A → 原理 B | 原理解释 |
| IMPLEMENTS | 实现 A → 概念／算法 B | 实验展开 |
| RELATED_TO | 无方向，两端代码字典序保存 | 辅助关联 |

所有关系有明确 reason。REQUIRES 不自指、不形成前置环；其他关系的环不视作前置错误。对比关系不同时写正反两条。

例：LRU 依赖页面置换基础，存 `os.memory.lru → os.memory.page_replacement`。学习展示先基础后 LRU，与文件方向不同，后端只在展示层做一次转换。

## 7. 题目

| 字段 | 约定 |
| --- | --- |
| questionCode / title / content | 稳定题号、短标题、完整 Markdown 题面 |
| type | JUDGE / SINGLE / MULTIPLE / FILL_BLANK |
| options | 选项对象数组，key 为大写字母，value 为文字；判断／填空填 [] |
| answer | 按下表填写，不使用统一字符串化数组 |
| analysis | 必填，给出原因或关键推演 |
| misconception | 建议填写具体误区；没有明显误区可用空字符串 |
| difficulty | 1—5 的整数 |
| sectionCode / sourceRef | 题目在教材中的位置及出处 |
| nodeMappings | 至少一个 PRIMARY 考查节点；各项 nodeCode、role、weight |
| usageSuggestions | 建议用途数组；各项 unitCode、usage（PRACTICE / ASSESSMENT / REVIEW） |
| parentQuestionCode / partIndex | 未拆题均为 null；拆题记录共同原题代码及从 1 开始的序号 |

| type | answer | 限定 |
| --- | --- | --- |
| JUDGE | `"true"` / `"false"` | 字符串，不是 JSON 布尔值 |
| SINGLE | `"B"` | 一个真实选项代码 |
| MULTIPLE | `["A","C"]` | 非空、无重复，集合完全匹配；不支持部分得分 |
| FILL_BLANK | `["LRU","最近最久未使用"]` | 一个空的可接受写法；非空字符串数组 |

填空只归一化大小写及首尾／连续空白，不自动处理数学等价或未声明的同义词。`nodeMappings.weight` 使用 (0,1]，PRIMARY 默认 1，SECONDARY 默认 0.3，不要求总和为 1。首期复用现有模型：该权重调节综合 pKnown 的更新幅度，分项模型维持现行规则。

拆题的 parentQuestionCode 可以是仅用于分组的来源编号，不强制创建不可作答的父题；每个子题仍有独立 questionCode。usageSuggestions 是给L的建议，不自动改写已发布单元。

## 8. 学习单元

L维护 unitCode、sectionCode、title、objectives（可验证目标数组）、sortOrder、estimatedMinutes、status、nodeMappings、activities。

unit.nodeMappings 使用 nodeCode 与 role，role 为 TEACHES / PREREQUISITE / EXTENSION，不使用题目的考查权重。

活动字段：activityCode、title、activityType、sortOrder、required、reference、config、completionRule。reference 使用 `{ "kind": "CHUNK", "code": "chunk.sample.memory.lru.rule" }`。

| 活动类型 | 引用 kind | completionRule |
| --- | --- | --- |
| READING / WORKED_EXAMPLE / SUMMARY | CHUNK | CONFIRM：学生明确确认，仅更新进度 |
| DEMO | RESOURCE | RUN_TO_END：指定运行到终步，仅更新进度 |
| PRACTICE / ASSESSMENT | QUESTION | SUBMIT：完成真实提交；PASS：后端判定通过 |
| EXPERIMENT | RESOURCE | SUBMIT 或 PASS，以判题服务返回为依据 |

config 保存实际活动参数，如页框数、页号序列、算法和任务说明，引用资源本身不复制。跨题目引用案例时条件一致，不能把不同序列的题目和演示当成一个预测任务。

默认检查点 SUBMIT 允许继续，但显示真实达标情况；需要强制通过的活动才用 PASS。提交接口不能允许前端上传 arbitrary correct=true 来产生节点证据。

## 9. 发布、修订与样例状态

L 从成员资源包导入的内容先进入 DRAFT，再由 L 使用系统审核流管理 SUBMITTED / APPROVED / PUBLISHED / REJECTED。J、A 只提交文件，不执行导入和在线审核；单元样例中的 status=DRAFT 表达设计状态。

同一稳定代码再次导入更新原实体，保留内部 ID。显示名和题面可以修订，已发表版本与历史判分保留。已发布题目的变更先形成修订草稿，审核发布后切换有效版本；无变化则不生成修订。批次不同并不表示内容身份不同。

samples 中的 sourceRef 指向 sample.oslab，origin 为 SELF_AUTHORED_SAMPLE，仅用于开发和试导。旧的五单元样例包含空活动，保留用作协议说明；当前实际教材批次使用 [七单元包](../../content/operating-systems/wangdao-2025/units/owner-memory-page-replacement-001.json)，正式教材和自编题分别记录真实来源。以批次清单选择文件，不同时导入同代码的样例与真实单元。

## 10. 内容检查命令

在仓库根目录运行：

```powershell
node scripts/validate-course-content.mjs
node scripts/validate-course-content.mjs --batch batches/memory-page-replacement-001.json
```

脚本只检查文件，不写数据库。检查 JSON、编号唯一性、目录及节点引用、关系方向约束、四种答案形状、素材路径和单元引用。它不能代替对照教材核实原文、正确答案和算法；目前也不验证线上导入接口。

成员正式材料分别放 knowledge/、questions/、units/ 后，使用通用命令检查。指定 `--batch` 时只检查该清单中的三个实际包，避免样例影响统计。正式包引用 shared catalog 中已登记的代码；L批准新增词表后再运行。

## 11. 编程实验维护与映射

A 维护已有编程实验，并完成两种独立关联：实验—知识节点和实验—学习单元。详细流程见 [实验专项指南](07-成员A编程实验维护与映射指南.md)。

实验维护文件协议为 `oslab-experiment-maintenance/1.0`，包包含 batchCode、contributor、experiments；每个实验保留原 questionId（JSON 字符串）、resourceCode、内容修订、nodeMappings、unitMappings 和 verification。它是待实现的管理工具交接格式，不属于现有 `oslab-authoring/1.0` 的三种包，也不受当前内容校验脚本覆盖。

实验 `nodeMappings` 使用 nodeCode、PRIMARY／SECONDARY、weight 与 reason，实际落在 `experiment_node`。`unitMappings` 使用 unitCode、required、completionRule 与 reason。A 只提交这些字段及实验修订资源，L 校验并用管理工具生成或更新对应 EXPERIMENT 活动草稿，再确认排序与发布。无变化的重导沿用原映射与 activityCode。

J、A 的交包模板使用通用文件名 knowledge.json／questions.json／experiment-maintenance.json，字段协议不变。L 归档到协作目录后可改成带批次的文件名，稳定代码不随文件名改变。成员附件路径相对提交根目录，L 导入时保留批次资产前缀；成员不需手填最终服务器 URL。

编程实验与知识测评分别保留原 question／learning_question 数据，不重新建题获得新身份。资源节点展示、判题事件、导师和教师统计共用正式实验映射，旧 tags 作为检索展示和迁移线索保留。不能同时把旧标签、新节点映射各记一轮学习证据。

课程内外使用相同资源与事件。独立入口产生的结果正常更新个人画像；明确携带 sourceUnitCode／sourceActivityCode 的结果才完成该活动。没有实践证据的概念节点显示“未评估”，不从阅读完成度推算实践掌握。
