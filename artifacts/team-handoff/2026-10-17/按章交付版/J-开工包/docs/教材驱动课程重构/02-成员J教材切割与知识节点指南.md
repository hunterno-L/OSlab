# 成员 J：教材切割与知识节点工作指南

更新：2026-10-17。参考《王道操作系统》。本指南可单独交给 J 执行，字段详解见 [协作数据规范](05-协作数据规范.md)。

## 1. 你的任务与L任务

你的主要任务是把教材整理成可复用的教学内容块、知识节点与有依据的关系，提交完整资源包给 L。系统校验、导入、在线预览与发布由 L 执行。

你不需要设计数据库、不需要给每个节点单独制作网页、不需要自行编排所有学习单元。L设计目录、单元及图谱总体结构；你可以根据正文指出需要调整的层级、粒度和关系。

## 2. 开始前拿到什么

- 自己持有的教材、L 给定的章节范围及编号清单。
- 当前目录骨架、节点词表和已存在节点导出清单。
- 本指南、开工包中的空白知识模板和 shared/overview-authoring.json 预分配编号。

你已持有教材，可以直接开始第一章。无需平台账号、数据库、Neo4j 或导入工具；解压 J 开工包，编辑 work/ 模板即可，不用等待 L 提供截图。

当前优先范围为 **第一章“计算机系统概述”整章**。按 1.1—1.6 整理正文，再整理 1.7 的疑难点／复习材料，完成后一次提交整章知识包。现有 1.1 成果不采用，1.1 也需重新依据教材整理。目录覆盖与单元草案见 [第一章交付方案](06-第一章交付方案与资料清单.md)，最新规则见 [按章交付与第一章重整要求](14-按章交付与第一章重整要求.md)。

已有的 [页面置换知识包](../../content/operating-systems/wangdao-2025/knowledge/j-memory-page-replacement-001.json) 含 15 个节点、15 个教学块、19 条候选关系，保留为格式与后续章节样板，不必重新录入。对应 [交接说明](../../content/operating-systems/wangdao-2025/handoffs/memory-page-replacement-001.md) 继续有效，但不占用第一章的交付顺序。

## 3. 文件组织

第一章使用开工包 `work/knowledge.json` 的空白结构，批次为 `batch.j.overview.chapter.001`。本章节点、教学块与关系汇总在同一知识包中，提交目录如下；L 接收后归档为 `knowledge/j-overview-chapter-001.json`：

```text
J-第一章-知识-001/
├─ knowledge.json
├─ assets/
│  └─ wd25-p实际页码-图号.png
└─ 交接说明.md
```

正式交付单位是一章。内部可以按小节整理，教学块数量由完整语义决定，不设每批 10—30 块之类的交付指标。交接说明按小节列全章覆盖情况，避免只完成部分正文却作为整章提交。

## 4. 第一步：定位与识别

保留教材标题路径和印刷页码。例如：

```text
第3章 内存管理 → 3.2 虚拟内存管理 → 3.2.4 页面置换算法
```

记录准确标题、正文开始结束位置、图表／例题编号。PDF 页序与教材印刷页码可能不同，统一采用印刷页码；截图有裁切或页码不明时，在 `locator` 标注并交L确认。

OCR 可用于初稿，但需要对照截图复核公式、上下标、页号序列、表格、否定词和关键术语。看不清的部分保留为待确认条目，不自行补出原文。

## 5. 第二步：按完整意义切割教学块

每个块只承担一个清楚的说明任务。可使用以下类型：

| `chunkType` | 内容 | 切割方式 |
| --- | --- | --- |
| `DEFINITION` | 概念与术语解释 | 定义与必要条件一起保留 |
| `EXPLANATION` | 机制、过程或理由 | 按完整论述划分 |
| `ALGORITHM` | 算法步骤 | 步骤、条件和变量含义一起保留 |
| `WORKED_EXAMPLE` | 完整例题推演 | 保留输入、假设、过程、结果 |
| `FIGURE` | 图表与文字说明 | 图片与解读关联保存 |
| `SUMMARY` | 小结 | 关联总结所涉及的节点 |

可以以几百字为常见规模，但不按固定字数截断。完整算法、例题或图表可以更长；同一块过长且包含多个独立主题时，再按语义拆开。

教材“习题精选”和“答案解析”主要交给 A 整理。正文中用于解释机制的完整例题仍可作为你的 `WORKED_EXAMPLE`，A 可以引用或另行改编成独立题目。

### 5.1 需要保留的条件

页面置换例题必须写明页框数、访问序列、初始内存是否为空、是否只统计缺页、使用何种算法。调度例题应保留到达时间、服务时间、抢占规则、时间片及同优先级规则。

不要把例题结论单独切出来，以免离开原条件后无法理解。

### 5.2 图片与公式

图片保存到批次的 `assets/` 子目录，记录相对路径、图号、说明和出处；内容块正文中通过相对链接引用。表格能准确转为 Markdown 时直接转换，复杂图保留原图。

公式可以使用 Markdown 数学表达，但需保留变量解释。多页例题可以由一个块引用多张图片；截图命名包含印刷页码，方便 A 和L复核。

## 6. 第三步：识别、复用与建立知识节点

知识节点表示可复用的概念、算法、机制或实现。可以定义、解释、关联练习，通常能够判断学生对它的理解。

| 适合建立节点 | 应作为内容或目录 |
| --- | --- |
| 缺页中断、LRU、局部性原理 | 第3章、3.2.4、某一教材段落 |
| 临界区、信号量、生产者消费者问题 | 本节小结、习题精选、答案与解析 |
| 页表、TLB、系统调用 | 某一页图片、阅读完成步骤 |

先搜索词表中的名称和别名，再决定是否新增。页面置换、页替换等同义表述可使用同一节点和别名；CPU 的 FCFS 与磁盘的 FCFS 属于不同对象，不合并。

节点字段至少有：`nodeCode`、`name`、`nodeType`、`description`、`aliases`、`homeSectionCode`、`sourceRefs`。简介采用便于学生理解的简短说明，正文由内容块提供，不把整节教材塞进简介。

### 6.1 代码规则

示例 `os.memory.lru` 是稳定标识，`LRU 页面置换算法` 是显示名称。改名保留代码；同一知识出现在不同章节时复用代码。

新增节点可先在本批中提出代码，交接说明列出新增原因。L确认后加入共享词表。需要拆分／合并已有节点时，列明旧代码、新代码与理由，历史数据迁移由L处理。

### 6.2 内容块如何关联节点

内容块使用 `nodeCodes` 数组：主要解释一个节点时只关联该节点；例题确实同时解释多个概念时可以关联多个。所有关联应能在正文中找到明确依据。

一个节点可以关联多块正文，例如 LRU 的规则、实现方式与例题；不需要合并成一个超长块。

## 7. 第四步：补充有依据的关系

关系使用总体设计中的六类词表。重点注意：

- `REQUIRES`：A → B 表示 A 需要 B，先 B 后 A。
- `CONTAINS`：A → B 表示 A 包含 B。
- `BASED_ON`：A → B 表示算法或机制以 B 为设计依据。
- 对比和一般关联不用于强制学习排序。

每条关系填写 `reason` 和 `sourceRef`。例如：“LRU 依据局部性原理利用历史访问情况进行置换”，可作为 `BASED_ON` 候选；是否还需要前置关系由L结合教学安排决定。

同页出现两个术语不是自动连边的理由。对比关系不重复保存正反两条。不要把教材页码、章节或题目伪装成知识关系。

## 8. 第五步：填写知识包

知识包包括三部分：

```text
nodes       知识节点
chunks      语义完整的教学块
relations   有依据的候选关系
```

每块记录来源类型、教材资源号、章节定位、印刷页码和简要定位信息。团队已确认授权，工作重点是让来源可复核、内容可复用。

详细 JSON 字段见 [协作数据规范](05-协作数据规范.md)，可复制 [知识包样例](../../content/operating-systems/wangdao-2025/samples/knowledge.sample.json)。样例中的内容是自编说明，正式整理时替换为实际内容与出处。

## 9. 第六步：文件自查与提交资源包

提交前完整执行 [J 交付前审查流程](15-J交付前审查流程.md)，按流程实际核对教材、正文、关系和图片，修改资源后复查；随包附 `自审记录.md`，或将真实记录放入交接说明的自审一节。

整章完成后提交 work/ 中的 knowledge.json、assets/ 和交接说明，打包为 `J-第一章-知识-001` 即可。无需运行系统或导入命令。自查整章覆盖、正文完整性、出处、图片和关系方向；不确定的结构写入交接说明。旧 1.1 文件不放入新包，也不作为已完成素材合并。

L 接收后运行文件校验，确认编号并导入，再核对节点词表、正文、图片、所在目录和发布状态。L 反馈需要修订的条目，你在原包中修正并重新交付。

修正沿用原 `nodeCode`、`chunkCode`；`batchCode` 记录交接批次，不用换实体编号来表示内容修订。

## 10. 与 A 的交接

过程中有新增、拆分或合并节点时，把编号清单和依据告诉 L/A 即可，无需逐节提交完整包。A 先使用预分配编号并行录题；整章交付时提供本章最终节点代码、名称与易混点清单，由 L 对照 A 的题目映射核定，不必等所有章节整理完。

如果 A 发现题目考查的概念尚未在词表中出现，他提出节点建议，由你结合正文补充；不要为了挂一道题随意创建近义重复节点。

A 也负责已有编程实验的新节点和学习单元映射材料。你协助核对候选定义与别名，尤其教材概念与具体函数、结构体之间的区别；A 整理维护和映射文件，L 执行正式保存与导入。

## 11. 每章完成检查

- 教材范围和版本明确，1.1—1.7 覆盖表完整，印刷页码可定位。
- 内容块语义完整，算法条件、例题过程与结果保留。
- 同义节点已复用，名称、分类和稳定代码一致。
- 图表可打开，公式和 OCR 关键内容已对照原文。
- 关系方向和依据清楚。
- 已列出需要L确认的结构建议。
- 旧 1.1 成果未混入；新包包含重新依据教材整理的本章内容。
- 已把 knowledge.json、图片及交接说明放在同一资源包，交给 L 进行系统核对。

交接说明使用样例中的格式，写清数量和待确认条目即可，不需要长篇开发报告。
