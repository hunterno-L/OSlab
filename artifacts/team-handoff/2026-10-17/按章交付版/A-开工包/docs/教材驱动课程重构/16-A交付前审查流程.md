# A：整章题目与独立实验包交付前审查流程

更新：2026-10-17。给 A 或负责复核 A 资源的 agent 使用。每次正式交付、集中返修后执行。题目和实验走各自流程，不要求交一章题目时重审全部历史实验。

输出是修订后的实际资源包和简短 `自审记录.md`。答案、映射、修订文件中的明确错误由 A 修好再交 L，不以“问题已写进说明”代替修改。系统导入、单元发布和沙箱适配仍由 L 负责。

先阅读 [题目指南](03-成员A题目整理与导入指南.md)、[实验指南](07-成员A编程实验维护与映射指南.md)、[协作数据规范](05-协作数据规范.md) 和 [按章交付要求](14-按章交付与第一章重整要求.md)。

## 1. 确定本次审查对象

| 本次交付 | 实际检查范围 |
| --- | --- |
| 整章题目包 | questions.json 中的全部题目、题目图片、交接说明和教材对应习题／答案；第一章覆盖 1.1—1.7 的适用资源 |
| 独立实验维护包 | 本次 experiment-maintenance.json 列出的实验、实际修订文件、原实验快照及验证材料 |

记录包名、版本、batchCode、实际路径和上一轮退修意见。不要审查完某个工作副本，却把另一个旧目录打包。

第一章题目包含重新依据教材整理的 1.1，不从旧 1.1 提交及退修版复制合并；题号仍可含 s1_1 等来源位置。公共代码继续使用，不靠机械换号表示重整。题目包用 `batch.a.overview.chapter.001`，实验用独立的 `batch.a.experiments.001` 等维护批次。

本步结果：实际题目数量／本批实验 ID 范围、版本及待回查意见，后续按下面相应路径继续。

## 2. 题目流程：文件检查与整章覆盖

在开工包根目录、确认本次题目位于 work/ 后运行：

```powershell
node tools/check-member-package.mjs .
```

独立交付目录先在开工包副本中放到 work/ 再检查。正式自审不使用 `--allow-empty`。没有运行条件就记录未运行及原因，不能把准备好的命令写成已通过。

从 questions.json 重新统计：总题数、四类题型分布、教材／改编／自编来源分布、逐节覆盖、重复代码。数字与交接说明逐项对上。

逐节对照教材题号，建立下面的收录表：

| 教材位置／题号范围 | 已收录代码及数量 | 未纳入题号及原因 | 对应节点／单元用途 |
| --- | --- | --- | --- |
| 实际范围 | 实际代码／数量 | 无答案、不支持题型等实际原因 | 实际关联 |

没有配套题的小节可以注明，以适当练习或其他单元复用补足学习需要，不为了填表虚构教材题。自编题用于补足覆盖和辨析，不用数量代替质量。题目只录一次，多个单元通过用途建议复用。

本步结果：文件检查记录、实际数量及覆盖表。未知节点先查词表或列候选，不能改挂到宽泛节点来消除报错。

## 3. 逐题先作答，再核对教材答案

每道题执行一次独立核对，不仅检查 answer 是否落在 A／B／C／D 中。

1. 先读题干、选项和条件，独立得出答案，再与教材答案和当前 JSON 比较。
2. 对照原书核对题号、选项顺序、否定词、数值、单位、图表及跨页内容。选项重排后答案字母也必须一致。
3. 读完整解析，确认能解释正确项和关键错误项；解析不能与题干、标准答案、同章概念冲突。
4. 计算或算法题实际重算，保留关键步骤、状态表或中间结果。采用演示器辅助时仍需用完整条件核对，不以演示输出代替独立推演。
5. 标题、提示和解析的展示位置不能提前泄露作答所需答案。题目页面上会先看到的文字一并审查。

教材题干与选项保持原样时用 TEXTBOOK；改了决定答案的条件、选项或拆分任务时，按 ADAPTED 记录原题与变更。自编题使用 SELF_AUTHORED 和自编编号，不能把取材于教材的自编判断句当成教材原题。

发现答案或教材解析有疑问，回查原页和完整上下文，提出自己的推导与建议；已能确定的整理错误直接修改。真正无法确定的题不计为可交付的正确题目，只列具体待核事项。

本步结果：逐题核对完成；有问题的 questionCode、依据和修订进入自审记录。正确题不需要重复抄写一篇审查说明。

## 4. 按题型复查判分与题目设计

| 类型 | 字段与判分核查 | 内容核查 |
| --- | --- | --- |
| JUDGE | options=[]；answer 为字符串 "true" 或 "false" | 陈述句含义明确，不把问句与布尔答案硬配 |
| SINGLE | 选项 key 唯一且 value 非空，answer 为某个真实选项的字符串代码 | 在题目条件下只有一个最佳答案，解析说明易混项 |
| MULTIPLE | answer 为非空、无重复的选项代码数组；当前按集合完全一致判分 | 逐项核实，不漏正确项；没有干扰项的识记题可保留为复习，但不冒充强诊断题 |
| FILL_BLANK | options=[]；只有一个答案位置；answer 数组为同一空的等价写法 | 每个别名代入题干后仍准确，不能收进相邻但不同的概念 |

对每种本批实际使用的题型，选一题演练“正确提交、典型错误提交、边界输入”的预期判分。例如填空要明确接受的空白／大小写变化，不能默认系统理解未声明的同义词、标点或公式等价。

重点检查：

- 填空题干已有“复用技术”时，不把会造成重复语义的整句随意收入标准答案；可改题干让需要填写的术语范围更自然。
- “临界区”与“临界资源”等不是可随意互换的别名。
- 多空原题按协议拆成独立单空时，保留共同来源、parentQuestionCode 和正整数 partIndex；不要用答案数组假装系统支持多空。
- 数值题写清单位、精度及边界；选择题排除因条件缺失而产生多个合理答案的情况。
- 同一考点多题重复时，区分练习价值和测评价值，必要时精简或调整用途；不为达到预设题数保留低质量重复题。

本步结果：题型字段与预期判分一致。只演算了预期结果时写“规则核对”，不能写“平台判分已验证”。

## 5. 审查节点映射和单元用途

逐题问两个问题：答错它究竟能说明哪个知识有问题？学生学到哪里适合做这道题？

1. 核对 nodeCode 的定义，而不是只看名称或旧标签。至少一个主考查节点；背景术语不扩展成被考查对象。
2. PRIMARY 默认权重 1.0，确实被观察到的 SECONDARY 可用 0.3；权重在 (0,1]，不是得分比例，不要求总和为 1。
3. 综合多选漏一项，不能据整题错误断言所有关联概念薄弱。先考虑改成更聚焦的题；保留综合复习题时，给 L 写明归因建议。
4. 把 usage 改为 REVIEW 不会自动证明系统停止产生掌握证据。不能凭空增加 JSON 中不存在的“关闭证据”字段；需要系统处理时给 L 明确列出题号和建议。
5. usageSuggestions 使用真实 unitCode 和 PRACTICE／ASSESSMENT／REVIEW；这是用途建议，不是课程已经发布。
6. J 的词表有新变化时，用旧代码 → 新代码／定义变化清单逐题核对。公共预分配编号可用于并行整理，J 新候选与 L 已确认编号分开记录。

第一章常见误标反例：“分配一个物理页”不等于教材“连续分配管理”；“裸机”术语题不必附带资源管理考查；题干提到系统调用不一定是在考查整个内核切换过程。

本步结果：题目映射及用途与实际能力一致，缺号和结构问题有明确对象与建议。不要为“全部通过”把真正的映射缺口掩盖掉。

## 6. 检查来源、图片及轻量检查器的遗漏项

完整回查教材来源、实际印刷页、原题号和 locator；PDF 页序单独定位。自编题使用 self.oslab／SELF_AUTHORED，空页码可为 null，pageStatus 可省略，不使用 NOT_APPLICABLE。

所有图片实际打开，核对公式、标签、选项对应、裁切和清晰度。题面图与解析图分清用途，路径相对本包根目录，不能依赖自己电脑上的绝对路径。

轻量检查通过后还要查：difficulty 是 1—5 整数、选项 value 非空、usage 枚举正确、parentQuestionCode／partIndex 形状合理、pageStatus 合法，以及题干答案的科学正确性。当前轻量脚本不会完整覆盖这些内容。

完成第 2—6 步后，题目进入第 9 步做修改后复查；本次未提交实验包时跳过第 7—8 步。

## 7. 独立实验流程：先核对任务和实际修订

本步只查本批维护包列出的实验，不因交一章题目而重复所有历史盘点。

1. 用字符串 questionId 对照原快照，确认标题、题面及待补函数属于同一实验；resourceCode 保持稳定，不重建同名实验以代替维护。
2. 明确学生需要补什么、提交什么、怎样运行、期望什么行为。题面、代码框架、参考实现、样例和用例必须围绕同一任务。
3. 逐个打开 contentChanges 引用的实际文件，核对 field、file、reason。记录写了“已修订”就应有实际变化，空数组只能说明尚未交付修订。
4. 检查学生起始代码是否已包含待完成答案，参考实现是否真完成题意。教师侧参考解包含答案是正常的，问题在起始代码泄露待实现部分。
5. 检查空输入／空输出、123→123、仅写“答案”等占位内容，不能当真实验证材料。
6. 核对判题配置与现有协议。timeLimit／memoryLimit／stackLimit 是现有 JudgeConfig 字段，不能因没有语言／编译命令字段就自动判定文件缺陷；完整内核项目缺工具链或构建入口时另列工程依赖，由 L 处理适配。

在开工包根目录检查 experiment-work/：

```powershell
node tools/check-member-package.mjs . --work-dir experiment-work
```

本步结果：逐实验区分“仅盘点”“已有文件修订”“有运行记录”。盘点有价值，但不将其计成已修复或可判题实验。

## 8. 独立实验流程：核对映射和验证证据

节点映射依据任务真正验证的行为，单元映射依据先修知识、学习目标和教学安排；两者不能互相替代。

逐项检查 nodeMappings 与 unitMappings，给实际主次节点、权重、required、completionRule 和理由。SUBMIT 是真实提交后完成活动，PASS 是判题通过后完成，不将二者与“必做／选做”混淆。

没有正式单元时，提案具体说明教材位置、先修内容、任务目标、实践类型与候选安排，不只写“以后再补”。缺运行环境不妨碍给出准确教学建议，但活动发布与可运行状态仍待 L 确认。第一章没有适用实验，不强行挂入概述学习单元。

有相应运行环境时，实际验证：

- 参考实现通过预期用例；
- 一个与考查点有关的典型错误实现被用例识别；
- 至少一个边界用例得到可解释的结果。

记录真实命令、输入、预期／实际结果和必要环境信息。完整教学内核须在对应工程与运行条件下验证，不把独立终端小程序通过当成原内核实验通过。

没有环境就记录尚未运行、已完成哪些文件核查、还缺哪份源码／工具链／执行约定，以及交给 L 的预期案例。只缺运行适配不妨碍交付已完成的文件修订；不能据此声称实验已可判分。

本步结果：验证事实与 verification 字段一致；无法确定的测试残留记录为“无有效任务／执行条件待判断”，不凭空推断其技术依赖。

## 9. 修改后复查，并生成真实自审记录

先改实际资源，再执行：

1. 修改题干、选项、答案或解析后，重新独立作答并检查出处、题型、图片和节点映射。
2. 修改实验后，回查相关文件、参考实现、用例及两类映射；有环境时重跑受影响验证。
3. 重跑对应文件检查，重新从 JSON 统计数量、来源与本批修订项，再更新交接说明。
4. 将上一轮退修意见逐条对应到实际修改及复查结果；没有修改的解释实际原因。

题目包与实验包分别保存下面的 `自审记录.md`，也可各放入对应交接说明的自审一节。报告汇总即可，不需要复制整个题库或全部运行日志。

```markdown
# A 资源包自审记录

日期、包名、版本、batchCode：
审查者、实际教材／原快照与词表依据：
本次范围：整章题目／独立实验维护。

## 题目结果（仅题目包填写）

- 总题数__；实际独立核对__；尚未核对__。
- 教材题__、改编__、自编__；题型和逐节覆盖见__。
- 文件检查：实际命令及结果，或未运行原因。
- 答案、解析、来源、图片、题型规则核对结果。
- 节点映射和单元用途核对结果；综合题归因的具体建议。

## 实验结果（仅实验包填写）

- 本批 questionId 清单__；实际修订__项；仅盘点__项。
- 文件检查：实际命令及结果，或未运行原因。
- 参考解／错误解／边界用例的真实运行记录，或未运行及缺失条件。
- 节点与单元映射、候选安排核对结果。

## 实际修订

| 对象代码／questionId／文件 | 问题 | 修改 | 复查依据／结果 |
| --- | --- | --- | --- |

## 需要 L 决定

只列答案争议、正式编号／单元和工程运行契约等具体问题，给出建议；没有写无。

结论：内容自审通过／内容自审通过且有具体待确认项／尚未通过。
实验另外写明运行已验证的范围或尚未验证，不由内容自审结论推断可判题。
```

## 10. 打包后再核对一次

打开最终压缩包，核对最新 JSON、图片、修订代码／用例及自审记录均已包含。第一章题目包与历史实验维护包分开，旧 1.1 包、空模板、教材整本副本和未修改的全量快照不混入交付。

题目正式交付为整章，返修在同一章包中完成，不恢复逐节交付。已知内容错误仍未解决时标明尚未通过；仅待正式编号或实际运行适配的事项单独说明，避免让 L 再重复查一遍哪些工作真的做过。

## 可直接交给审查 agent 的任务

> 请完整读取本流程、最新协作规范、本次实际资源包及退修意见。整章题目按第 1—6、9—10 步逐题独立作答并对照教材；本次另有实验维护包时，再对该包全部条目执行第 7—8 步。明确错误直接修改 JSON、题面、解析、代码或附件，修改后复核，不停留在撰写建议或润色说明。题目与实验分包，保留稳定代码和原实验 ID，不合并旧 1.1 成果。最终交修订包、基于真实检查的自审记录及确需 L 决定的少量问题；未执行的命令、书页核对和运行验证如实记录。
