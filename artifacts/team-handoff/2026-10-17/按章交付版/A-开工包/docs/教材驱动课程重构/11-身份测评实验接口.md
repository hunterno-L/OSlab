# 身份、测评与实验接口

以下接口统一管理员 `/api/teaching`，标准 BaseResponse 包装。ID 字符串。

- POST `/assessments/import/preview`、`/assessments/import/commit`：`{package: QUESTIONS协作包}` 或 `{content:JSON文本}`；返回 `{valid,items:[{type,code,action:CREATE|UPDATE|UNCHANGED}],errors:[{path,message}],created,updated,unchanged}`。
  支持附带 `assets:[{path,contentBase64,contentType}]` 的 PNG/JPEG/WebP/GIF 图片，导入时归档，并将题干、选项和解析内相对地址改写为内容哈希地址。相同文件重导保持相同地址；漏传被引用图片会报错。来源截图不因随包上传而直接向学生公开。
- GET `/assessments/{questionCode}`：`{questionId,questionCode,publishedRevision,activeStatus,revision,status,draft}`。draft 含管理答案；学生继续 `/learning/questions/get?questionId`，永不含答案。
- POST `/assessments/{questionCode}/review`：`{action:SUBMIT|APPROVE|REJECT|PUBLISH,reason?}`。旧题目 review 接口也接入修订状态机。
- POST `/experiments/import/preview`、`/experiments/import/commit`：`{package:oslab-experiment-maintenance/1.0包,files:[{path,contentBase64}]}`，也可用 `content` JSON文本、`assets` 作为 files。附件路径严格 `experiment-files/...`，读取UTF-8；contentChanges 使用 `{field,file,reason}`，不接收任意数据库字段。
- GET `/experiments/{questionId}/mappings` 返回 `{questionId,resourceCode,title,nodeMappings,unitMappings,revision,status,before,after}`；PUT 提交两类映射并创建修订草稿，不立即覆盖现行实验。
- POST `/experiments/{questionId}/review`：`{action:SUBMIT|APPROVE|REJECT|APPLY,reason?,confirmed?}`。流程为 DRAFT → SUBMITTED → APPROVED → APPLIED；APPLY 必须 `confirmed:true`，才更新原实验和正式节点映射，并保存单元活动草稿。应用前核对原题面等字段是否已变化；before/after 保留版本快照。新实验资源先为 DRAFT，运行核验后由 L 启用，不自动发布课程单元。
- PUT `/nodes/{nodeCode}/legacy-identity`：`{legacyNodeName}`，管理员显式确认旧身份；一经绑定不能重绑定，节点改名不影响历史。名称不唯一时不自动猜测。绑定会加入图谱同步队列；若此前已生成课程投影，将关系转移到原节点，保留原图谱 ID。应在该新代码开始积累学习证据之前完成历史身份绑定。

题目显式携带 revision 时，修改内容必须匹配当前草稿版本，否则预览和提交都返回版本冲突；完全相同的内容可幂等重导。旧题保持 ID 和历史作答，新修订发布前不切换学生当前答案。

学生作答 `/learning/questions/answer` 及代码提交 `/question_submit/add` 的请求增加可选 `sourceUnitCode/sourceActivityCode`，二者必须一起填写且指向已发布、资源相符的活动。省略表示独立入口，只更新画像。作答后已有 `attemptId`，实验有 `submissionId`，使用课程 complete 接口服务端校验结果。

节点工作台支持 `GET /learning/mastery/node?nodeCode=...`（兼容旧 nodeName）。时间线支持 nodeCode。正式映射唯一来源 experiment_node；旧标签只展示，不重复计分。

图谱 NodeDTO、MasteryNodeVO 增加 nodeCode 与 displayName；name 仍为历史存储名／未绑定节点的稳定代码，displayName 才是 registry 当前显示名。这样旧页面的 name 路由、统计与历史快照仍有效，显示名变化不会另建掌握状态。新页面优先展示 displayName，路由优先用 nodeCode。

迁移顺序 v6 → v7。旧题目保留原ID并分配 `q.legacy.ID`；导入同 questionCode 更新原题，已发布题只创建修订草稿，审核发布才切换答案及节点映射。每次作答保存服务端完整题目快照，重发反馈使用原快照。新增事件记录 nodeCode、单元／活动上下文及观测权重、模型版本；历史事件账本不改写。

验证记录：本地 MySQL 8.4 已执行 v6、v7 并重复执行 v7 验证幂等（mysql 客户端需 `--default-character-set=utf8mb4`，在 SQL 所在目录使用 `source 文件名` 避免 Windows 中文路径编码差异）。真实SQL集成测试验证题目重导ID、无变化不增修订、发布前答案保持、发布后切换、作答快照反馈；实验重导保持原 questionId/activityCode；测试事务回滚后无测试实体残留。未运行参考解／沙箱，实际实验可判题性仍待A真实材料和环境核验。

事务：`LearningTransactionConfig` 显式提供主 SQL 事务管理器。该项目同时接入 Neo4j，原自动配置会令无限定 `@Transactional` 使用 Neo4j 事务，不能回滚 MySQL；本次已用真实失败事务与库外查询验证SQL回滚。图谱同步仍由课程同步队列及 Neo4j Driver独立提交。
