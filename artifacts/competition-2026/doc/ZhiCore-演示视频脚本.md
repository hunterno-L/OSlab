# ZhiCore 作品介绍视频脚本

> 对应作品介绍文档第 7 节「演示视频地址」。
> 版本：v1.0 ｜ 成片时长：4 分 35 秒 ｜ 画幅：16:9 ｜ 分辨率：1920×1080
> 形式：真实系统录屏 + 旁白 + 中文字幕，不制作假 UI。
> 本稿按 2026-10-30 本地实际页面核对，页面名称、按钮与数据均可在系统中找到。

---

## 一、视频定位

这不是功能罗列，而是跟随一个学生走完一次真实学习闭环：

**课程主线 → 图谱定位 → 单元学习 → AI 导师 → 练习/实验 → 学习记录 → 教师端 → AI 测试可信边界**

三个表达重点：

1. **主线清楚**：五章、104 个学习单元，先读、再练、再做实验，不是把内容、题库和 AI 拆成三个入口。
2. **AI 有依据**：图谱导师和实验导师都读真实证据、真实代码、真实判题结果；回答带来源，AI 不写掌握度。
3. **过程可验证**：活动进度与掌握证据分开记录；教师端看同一套数据；AI 的检索、引用与回退有确定性测试守住。

目标观众是评审，所以每 30 秒至少出现一个可核验的细节：来源、证据、判题结果、发布快照或测试输出。

## 二、成片规格

| 项目 | 要求 |
| --- | --- |
| 时长 | 4:35（正片）；另附 60 秒短版 |
| 画幅 | 1920×1080，16:9 |
| 帧率 | 录屏 60fps，成片 30fps 或 60fps |
| 编码 | H.264，10–16 Mbps；音频 AAC 192 kbps |
| 字幕 | 简体中文，底部安全区；术语首次出现加英文小注 |
| 配乐 | 无配乐或极轻氛围垫；不得盖住旁白 |
| 音效 | 少量点击音、切换音；不要连续轰炸 |
| 片头/片尾 | 品牌标记 + 一句话，不制作假界面 |
| 画面 | 浏览器全屏，隐藏书签栏、扩展、通知；鼠标移动要慢 |
| 重点强调 | 关键点击加 1.2 秒放大或点击环；静态页可做 1.02 倍缓慢推近 |
| 转场 | 硬切为主；章节之间可用 6 帧淡入淡出，不用花哨转场 |

### 口径要求

- **判题只出现 C 语言**。不要出现 Java / C++ / Go 的判题选项或口播。
- **AI 模型按最终部署口径**：屏幕角标写「DeepSeek 官方 API 平台 · deepseek v4.1」；不要拍配置文件、环境变量或密钥。
- **不口播题库总量**。页面与文档的题目统计口径可能不同，视频里只说「按知识点筛选」，避免数字冲突。
- **不展示班级人数等容易显得样本不足的数字**。教师端构图从「薄弱知识点 Top 5」「班级节点掌握热力」开始。
- **所有画面必须来自真实系统**。AI 未返回、判题失败、数据为空时，修环境或重录，不用假数据补。

## 三、录制前准备

### 3.1 环境

- 启动完整环境：前端 8081、后端 8121，MySQL / Redis / Neo4j 正常。
- 判题使用**真实代码沙箱**（Docker，C 编译可用），不要用 echo stub 录「提交评测」。
- 浏览器使用干净配置：1920×1080、100% 缩放、全屏、隐藏书签栏和扩展、关闭通知。
- 学生段和教师段分开录；切换账号的过程不入镜。

### 3.2 数据

- 学生账号：`student_demo1`（已有 371 条学习活动、9 条有效证据、薄弱节点「进程状态」）。
- 教师账号：`teacher_demo`（班级 `os2026`，已有 521 条班级事件、薄弱知识点数据）。学生教师密码都是：123456。
- 当前单元「操作系统是什么，有哪些基本特征」提前完成 **6/10** 个活动：阅读与演示完成，练习和测评保留未完成。这样首页和单元页能看到真实进度，又能讲清「进度 ≠ 掌握」。
- 节点导师提前问一次「下一步该学什么」，确认：
  - 回答带 `GraphRAG` 标签，不是「规则回答」；
  - 来源不少于 3 条，点击来源能打开；
  - 回答延迟在 5 秒内。
- 实验页提前准备一份**会失败的 C 语言草稿**，并确认「提交评测」能返回真实判题结果；再确认点击「向导师提问」会预填「我的提交没有通过，请帮我定位问题并给出修改建议。」
- 教师端提前创建一条已发布的学习任务（按班级 `os2026` 下发），任务内容包含一道题目和一个实验；学生端能看到 1 条「待接收」。
- 昵称、头像使用中性演示资料，不出现真实姓名、学号、手机号。

### 3.3 录屏

- OBS 录屏 60fps，画面和旁白分开录，片头拍手同步。
- 每个镜头至少录 3 条；鼠标移动放慢，点击前停 0.3 秒。
- 滚动不要快；AI 检索等待可以保留 1–2 秒真实 loading，过长则 2 倍速并在画面保留「正在检索」。
- 录屏时关闭 DevTools；终端不出现密钥、数据库口令、内网地址。

### 镜头 02 · 00:10–00:25 · 开场定位

**画面**

- 全局 AI 助手画面只拍面板标题「AI 助手」和输入框，不拍具体回答。

**旁白**
> 内容在教材里，练习在题库里，AI 在另一个窗口里——这是很多学习平台的日常。ZhiCore 想做的，是把它们放回同一条路径：先读，再练，再做实验，每一步都留下可回看的证据。

**屏幕文字**
- 三连切时分别打：`教材`、`题库`、`AI 窗口`

**剪辑**
- 这一段的节奏可以比其余部分快 10%，但不能快到看不清字。

- 镜头给到提示语特写：`阅读与演示记录学习进度；作答与判题结果形成个人掌握证据。`
- 右侧「本单元地图」：`1 阅读与演示 0/7`、`2 练习与测评 0/3`，以及提示「先完成阅读，再作答。答错时回到对应阅读段，不直接跳到下一题。」

**操作**
- 在阅读正文处停留 2 秒，让观众看清「出处 / 版本 / 内容版本 1」。

**旁白**

**屏幕文字**
- 左侧：`进度 ≠ 掌握`
- 右侧：`活动进度 / 掌握证据`
- 底部：`BKT · 概念证据 + 实践证据`

**剪辑**
- 这一段是全片的教学理念核心，语速放慢一点。
- 「阅读与演示记录学习进度；作答与判题结果形成个人掌握证据。」这句话必须完整入镜。

### 镜头 06 · 01:45–02:15 · 图谱导师

**画面**
- 从首页点击「下一步：进程状态」，进入节点工作台 `/knowledge/node/进程状态`。
- 页面标题「进程状态」，右上角状态「薄弱 / 掌握度 11%」（以真实数据为准）。
- 右侧「图谱导师」面板：
  - `当前学习焦点`
  - 证据卡：`掌握状态`、`学习证据`、`最近失败`
  - 欢迎语与两个建议按钮：「解释核心概念」「下一步该学什么」
- 点击「下一步该学什么」，输入框自动带入问题并发送。
- 等待时保留 1–2 秒：`正在检索本节点证据`。
- 回答出现后，先拍标签 `GraphRAG`，再拍回答正文和下方来源列表；鼠标依次划过 2–3 条来源。
- 展开底部「检索轨迹」，让 3–4 条检索步骤入镜（种子节点、一跳关系、个人事件、教材段落）。
- 点击第一条来源，展示它跳回教材或节点内容；不需要停留太久，证明「可点回」即可。

**操作**
- 提问前确认证据卡里有真实的「最近失败」，这是导师有依据的关键。
- 不要手动修改回答；不要切换到「规则回答」模式录这一段。
- 如果回答超过 6 秒，剪辑时 2 倍速，保留「正在检索」画面，不要剪成瞬间出现。

**旁白**
> 遇到问题，右侧的图谱导师不会凭空回答。它会带着当前节点、一跳关系、我自己的学习事件、已发布教材段落和下一步路径一起检索。回答里的每条引用都能点回原文；AI 只读证据，不修改掌握度。

**屏幕文字**
- 导师面板：`NODE MENTOR`
- 回答上方：`GraphRAG`
- 右侧角标：`最多 8 条来源 · 引用校验`
- 底部：`DeepSeek 官方 API 平台 · deepseek v4.1`
- 最后 2 秒：`AI 只读 · 不写掌握度`

**剪辑**
- 这是 AI 技术展示的核心镜头，给足 30 秒。
- 来源列表和「检索轨迹」各给至少 2 秒特写，让评审看清不是一句空回答。
