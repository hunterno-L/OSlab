## 修复结果

- 正式学习目录默认只开放 `course.operating-systems`。数据库课程作为可选跨课程测试内容保留，历史数据没有删除。环境变量 `OSLAB_LEARNING_ENABLED_COURSES` 可显式启用多课程，Compose 已透传该配置。
- 首页优先操作系统，保留有效的当前课程；画像、推荐、图谱和路径传递课程范围。发布节点从发布快照与引用的已发布资源解析，包含显式历史节点身份。OS 范围实测 196 个节点，DB 范围为 3 个；原全局图谱为 349 个。
- 首页同组件的课程 query、历史导航与迟到响应正确同步；课程目录按当前课程先完成加载，其他课程的慢请求不阻塞当前内容。
- 节点推荐显示人类可读名称，链接保留稳定编码与课程上下文。没有有效课程时，前端不发起无范围个人图谱请求；旧无 `courseCode` 画像接口保留兼容行为。
- 实验 1.1 的真实 API 返回 C 初始代码和 `CONCEPT_HARNESS`。已有 C++ 草稿保留并解释语言不一致；恢复须确认且可找回替换前草稿，多次替换的备份会归档。概念测试通过不代表完成 Minix 构建；本地构建实验禁止在线自动评测。
- Monaco 的程序赋值不回写成学生编辑，移除重复语言监听；离页释放 editor 与 model，并避免重复释放。窄屏恢复操作至少 44px，语言提示使用浅色背景与正文颜色。
- 教师跟进、班级列表、课程进度、大纲节点名称、任务统计和提交记录改为请求内批量查询。任务发布时的评分快照、班级统计与权限不变。此前修复的草稿逻辑删除和任务上下文同步已回归。
- 独立审查发现导师工具仍可能以空列表读取本人全部课程事件。现按会话课程的发布节点限定；模型或页面指定的节点须与课程取交集，包含稳定编码和明确的历史存储键。空范围、缺上下文或范围读取失败不会回退全课程，亦清除本轮旧证据。
- Windows 启动脚本从运行副本启动后端，避免锁定 Maven JAR；启停检测识别该副本与 npm 前端。移除启动脚本强制回显沙箱与固定认证覆盖，采用项目配置和环境变量。

## 性能对照

前后使用同一隔离数据库、同一 OS+DB 启用配置和相同接口参数。每接口先预热 2 次，后连续发起 10 次真实 HTTP 请求。SQL 通过 MySQL `performance_schema.events_statements_summary_by_digest` 中该验证库的 `COUNT_STAR` 差值计数，排除计数器查询；没有重置全局计数。p95 在这 10 个样本中取最大值。
