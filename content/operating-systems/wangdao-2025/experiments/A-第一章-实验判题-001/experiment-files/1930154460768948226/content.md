# 实验 1.5 实现内核中的 printf 函数

## 实验背景

在本实验中，你将学习如何在内核中实现一个基本的 `printf` 函数。由于内核开发中不使用 C 语言标准库，你需要从底层开始，逐步实现字符输出功能。

## 知识要点

1. **C 语言标准库**：
   - 理解 `printf` 函数在 C 语言标准库中的作用和实现方式。
2. **内核编程基础**：
   - 了解内核编程的基本概念，包括内核空间和用户空间的区别。
   - 学习如何在内核中进行字符输出。
3. **格式字符串解析**：
   - 理解格式字符串的组成，包括格式标识符（specifier）和格式修饰符（flag、width、precision）。
4. **汇编语言基础**：
   - 学习基本的汇编指令，理解如何在汇编层面实现函数调用和返回。
5. **函数调用约定**：
   - 理解函数调用过程中的参数传递和返回值处理。

**扩写**：转换说明形如 `%[flags][width][.precision]conv`。`width` 是**最少**字段宽度，`precision` 对 `d/x` 是**最少数字位数**、对 `s` 是**最多字符数**。`0` 与 `-` 冲突时 `-` 优先；指定 precision 时 `0` 对整数失效。

**内容来源**：`lib/print.c`/`console.c` 的**原指导 Listing 未随工作区提供**（`originalCode`/`answer` 实测均 0 字节）。harness 用 `struct ArgList` 等价替代 `va_list`、有界 `print_char` 等价替代控制台 sink，是**按公开语义构造的等价环境**；参考解另与宿主 libc `snprintf` 交叉校验（7 MATCH / 1 SKIP）。

## 实验任务

**实验任务**

1. **阅读相关代码和文档**：
   - 阅读 `lib/print.c` 和 `drivers/gzconsole/console.c` 文件中的代码。
   - 理解这些代码如何实现字符输出。
2. **补全 `lib/print.c` 中的 `_Printf()` 函数**：
   - 根据函数规范，补全 `_Printf()` 函数中缺失的部分。
   - 实现格式字符串的解析和字符输出。
3. **实现字符输出**：
   - 编写代码，将解析后的字符输出到终端。
   - 确保输出格式正确，包括对齐、填充和精度控制。
4. **测试 `printf` 函数**：
   - 在内核中调用 `printf` 函数，测试其功能。
   - 验证输出结果是否符合预期。

**每步验证**：核对输出路径，补全 `_Printf()`，在内核中测试。

## 本平台判题说明

- 判题方式：**Tier A**：主机端等价 harness，判真实目标函数 `_Printf()`。
- 你需要填写：`static void _Printf(const char *fmt, struct ArgList *ap)`（`starter.c` 填写区）；用 `arg_int`/`arg_str` 取参、`print_char` 输出。
- 判题输入：三段：格式串（≤200 字符）、参数个数 n（0..8）、n 个参数——「i <int32>」为整数、「s <无空格字符串>」为字符串（≤63 字符）。其余约束见下方契约原文。
- 判题输出：`_Printf` 的字符流原样输出，驱动末尾补一个换行。conv 支持 `d`/`x`/`c`/`s`/`%`，语义与 C 标准 printf 在该子集内一致（见契约原文）。
- 宿主环境适配：`va_list`→`struct ArgList`；整数一律 `int32_t`；输出走有界 `out_buf[4096]` 而非串口；`%x` 按无符号 32 位解释，`-1` 打印 `ffffffff`。
- 与真实内核的关系：格式解析逻辑与真实内核一致，只有取参与字符 sink 是主机替身；本地仍应在 MIPS 环境用 `printf` 验证。
- 内容来源标注：`lib/print.c` 原文**未随工作区提供**，harness 为按公开语义构造的**等价**环境，非北航原文转录。

契约原文（逐字引自本目录 `cases.json` 的 `description`）：

```text
驱动 lib/print.c 的 _Printf()。stdin 第 1 行是格式串（原始文本，可含空格；\n \t \r \\ 由驱动解码为真实控制字符；长度 ≤200；转换说明内部的 width/precision 数字串最多 2 位即取值 0..99，格式串中的普通数字文本不受此限）；第 2 行是参数个数 n（0..8）；随后 n 行每行一个参数：「i <int32>」表示整数参数、「s <无空格字符串>」表示字符串参数（≤63 字符）。支持的转换说明符：%[flags][width][.precision]conv，flags 为 '-' 左对齐 / '0' 零填充 / '+' 强制正号 / ' ' 正数前空格（可组合可重复），conv 为 d（十进制有符号）、x（十六进制小写无符号）、c（单字符）、s（字符串）、%（字面百分号，不取参）。语义与 C 标准 printf 在该子集内一致：d/x 的 precision 是最少数字位数（不足补前导 0，值为 0 且 precision 为 0 时不输出数字），指定 precision 时 '0' flag 失效，零填充补在符号之后数字之前，'-' 与 '0' 同时出现时 '-' 优先；s 的 precision 是最多输出字符数，'0' flag 对 s/c 无效；c 的 precision 无效；未识别的 conv 字符原样输出 '%' 与该字符且不取参；格式串在 conv 前结束则输出一个 '%' 后停止。参数按出现顺序用 arg_int/arg_str 取（va_arg 的主机等价物），参数耗尽时整数取 0、字符串取空串。输出：_Printf 产生的字符流原样输出，末尾由驱动补一个换行。
```

## 本地完整验证

本地完整验证（选填）：`make` 后在 `init/init.c` 里加 `printf("[%08d][%-8s][%.3s][%x]\n", -42, "ab", "abcdef", -1);`，gxemul 串口应打出 `[-0000042][ab      ][abc][ffffffff]`。

## 常见错误

1. 解析出 width 却不用（`wrong.c`：`width = 0;`）：`%08d` 打成 `-42` 而非 `-0000042`。
2. 零填充补在符号之前：`-0000042` 才对；`%08.5d` 应得 `   00042`（precision 使 `0` 失效）。
3. 把普通数字文本当宽度：`100%% done %d` 里的 `100` 是字面文本，必须原样输出。
