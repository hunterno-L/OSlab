# 实验  3.2 管理进程控制块数组

## 实验背景

**题目原文**

### 任务描述

在操作系统实验中，需要初始化进程控制块（PCB）数组 `envs`，并将所有空闲的 PCB 连接成一个链表 `env_free_list`。所有初始的 PCB 都是空闲的，因此需要将它们全部添加到 `env_free_list` 中。

PCB 的空闲链表把可用槽位交给后续分配；链表的遍历次序会直接影响下一次取得的 PCB。

## 知识要点

### 知识要点

1. **进程控制块（PCB）**：
   - PCB 是操作系统用于管理进程的数据结构，记录进程的状态和相关信息。
   - PCB 包含进程的状态、优先级、程序计数器、寄存器集合、内存管理信息等。
2. **空闲进程链表（env_free_list）**：
   - 空闲进程链表用于管理所有当前未被使用的 PCB。
   - 初始时，所有 PCB 都是空闲的，需要将它们添加到 `env_free_list` 中。
3. **链表操作**：
   - 需要了解如何将 PCB 添加到链表中，包括链表的插入操作和顺序。

**理解与应用**：平台使用 64 个槽位：升序遍历并头插，得到 63 到 0 的链表；每个槽位同时置为 ENV_FREE。

## 实验任务

### 实验任务

1. **编写 `env_init` 函数**：
   - 在 `lib/env.c` 文件中实现 `env_init` 函数。
   - 该函数负责初始化 `envs` 数组，并将所有空闲的 PCB 添加到 `env_free_list` 中。
2. **链表插入顺序**：
   - 确保在 `env_init` 函数中正确地将 PCB 添加到 `env_free_list` 中，注意插入的顺序。
3. **参考代码**：
   - 可以参考 `lab2` 中的类似操作，特别是如何将空闲的 PCB 连接成链表。

**实施与验证**：先初始化链表，再逐项置状态并插入；用 I、L、A 对照长度、前几个下标和第一次分配结果。

- 判题方式：Tier A 单文件 C 主机端等价 harness，填写 `starter.c` 中成对标记包围的学生填写区：`static void env_init(void)`。

- 以下逐字引用 `cases.json.description`；stdin 按空白分词，输出的行内空格敏感。

> 驱动 lib/env.c 的 env_init()。stdin 首行 npage freemem（物理页数 1..256、启动期空闲内存起始字节 0..65536），次行操作数 n（0..48），随后 n 行每行一个操作码：I=调用一次 env_init()（重复 I 打印 I SKIP）；L k=打印空闲链表前 k 个 PCB 下标（0<=k<=64）；A=调用平台 env_alloc 取一个 PCB；F idx=把 envs[idx] 放回空闲链表；C=打印空闲链表长度。输出：I 行为「I 空闲链表长度」；L 行为「L 下标 下标 ...」（不足 k 个就打印实际个数，空链表时 L 后无内容）；A 行为「A 返回码 PCB下标」（失败时下标 -1，返回码 -5 表示无空闲 PCB）；F 行为「F idx 放回后的链表长度」；C 行为「C 长度」。所有整数为十进制。

**操作与参数 → 输出**：

- `I` → I 数量 / I SKIP
- `L` k → L 下标...
- `A` → A 返回码 下标
- `F` idx → F idx 长度
- `C` → C 长度

**契约片段**：「I 空闲链表长度」；「L 下标 下标 ...」；「A 返回码 PCB下标」；「F idx 放回后的链表长度」；「C 长度」。

## 常见错误

1. 降序遍历仍头插，会反转期望次序。
2. 忘记初始化链表或遗漏某个槽位，会使长度不足。
3. 只链接槽位却不设置 ENV_FREE，会留下错误状态。
