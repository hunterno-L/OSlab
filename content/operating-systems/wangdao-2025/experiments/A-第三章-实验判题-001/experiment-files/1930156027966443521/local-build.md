## 1. 时钟中断与时间片轮转的关系（知识要点 1）

时间片轮转（RR）需要一个**外部周期性事件**来剥夺当前进程的 CPU 使用权，否则一个死循环进程会永远占住 CPU。
这个事件就是时钟中断：定时器每隔固定时间拉一次中断线 → CPU 陷入内核 → 内核调用调度器换进程。
所以「时钟中断」是 RR 调度的**触发源**，`sched_yield` 是**执行体**，两者缺一不可。

## 2. 设置定时器并绑定 4 号中断（实验任务 1 / 实验步骤 1）

`kclock_init` 要做两件事：

**(a) 设置定时器频率。** gxemul 的 `oldtestmips` 机器模拟了 PC 风格的 8253/8254 可编程定时器：
向控制端口写方式字（选择计数器 0、先低后高字节、方波/速率发生器模式），
再向计数器 0 端口写 16 位分频值。输出频率 = 输入时钟 / 分频值。
分频值越小中断越频繁；太小会让内核几乎全部时间都在处理中断，太大会让调度迟钝。
**具体端口地址与分频常数以实验指导为准**，不要凭猜测填。

**(b) 把时钟中断绑定到 4 号中断线。** 定时器输出接到中断线 4，对应：
- `CP0 Cause.IP4` = bit 12（硬件置位，表示 4 号中断挂起）；
- `CP0 Status.IM4` = bit 12（软件置位，表示不屏蔽 4 号中断）；
- 同时 `Status.IE`（bit 0）= 1 开总中断，且 `Status.EXL`（bit 1）= 0（不在异常级）。

三者缺一，中断都不会被取走。绑定动作通常体现为：初始化定时器硬件 + 置 `Status.IM4`。

## 3. 配置中断入口地址（实验任务 2 / 实验步骤 2）

与实验 3.12 完全一致：在链接器脚本中把异常/中断分发代码定位到 `0x80000080`。
MIPS 不为每个中断号提供独立向量，**所有中断共用通用异常向量**，靠软件读 `Cause` 区分。

```ld
    . = 0x80000080;
    .exc.handler : { *(.exc.handler) }
```

## 4. 异常分发路由到 `timer_irq`（实验任务 3 / 实验步骤 3）

在 3.12 的分发代码里补上中断细分：

```asm
    /* ExcCode == 0 (Int) 时进入这里 */
do_irq:
    mfc0  k0, CP0_CAUSE
    mfc0  k1, CP0_STATUS
    and   k0, k0, k1          /* 只看「挂起且未屏蔽」的位 */
    andi  k0, k0, 0x1000      /* bit 12 = IP4 → 时钟中断 */
    bnez  k0, timer_irq
    nop
    /* ... 其他中断号 ... */
```

（**等价示例，非原文转录**。`Cause & Status` 是取「有效中断」的标准做法。）

## 5. 编写 `timer_irq` 并调用 `sched_yield`（实验任务 4 / 实验步骤 4）

`timer_irq` 的职责：
1. 保存现场（复用 3.10 的 Trapframe / TIMESTACK 机制，注意 `k0/k1` 已被分发代码占用）；
2. **清中断源 / 应答定时器**（若硬件需要，否则中断会立刻再次触发，形成中断风暴）；
3. 调用 `sched_yield()`：把当前进程挂回就绪链表尾，选下一个 `ENV_RUNNABLE` 进程，`env_run` 切过去；
4. 恢复现场并 `eret`。

约束：
- 中断上下文里**不能阻塞、不能睡眠、不能申请可能失败的锁**；
- `sched_yield` 必须能处理「就绪链表为空」（回到当前进程或 idle）与「只有一个进程」两种退化情形；
- 若 `timer_irq` 直接跳到调度器而不保存现场，被切换回来的进程寄存器会被破坏 —— 表现为随机崩溃。

## 6. 测试与验证（实验任务 5 / 实验步骤 4）

```bash
make
mips-linux-gnu-readelf -S gzemul/vmlinuz | grep -i exc    # 入口段地址必须是 0x80000080
gxemul -E oldtestmips -d gzemul/vmlinuz                   # 具体命令以实验指导为准
```

验证点：
1. 创建**两个以上**用户进程，每个都跑死循环并周期性打印自己的 envid；
   串口输出应交替出现不同 envid → 说明时钟中断确实触发了轮转；
2. 若输出停在某一个 envid 不再变化 → 中断没被取走，逐项查：
   定时器是否真的在计数、`Status.IM4` 是否置位、`Status.IE` 是否为 1、
   `0x80000080` 处是否是分发代码、分发是否识别了 IP4；
3. 若内核立刻复位或跑飞 → 现场保存/恢复或 `eret` 有问题；
4. 若中断频率异常高（输出被中断处理淹没）→ 分频值设错。
